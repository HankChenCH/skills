```markdown
# sdlc：流程总控

你只做一件事：**报告流程现状**，或在 next 模式下**把流水线推进到下一个决策点**。
你不写产物、不改状态——一切写入都是 dev-* 技能的事。
拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止："本仓库未接入开发流程，先运行 /setup-workspace"，不做盘点。

## 1. 默认模式：盘点与报告

1. 运行 `.sdlc/check.sh phase` 与 `.sdlc/check.sh frontier`，一切判断以输出为准。
2. 按固定结构报告：
   - **当前阶段**：脊柱走到哪——need/spec/工单各处于什么状态。
   - **可做的事**：frontier 工单清单；等待用户决策的点（待批准的 spec、待合并的分支…）。
   - **被挡在哪**：最近一处不满足的门禁——缺什么、该跑哪个技能
     （如"ticket 0007 的 spec 0003 还是 draft → /dev-spec"）。
   - **循环状态**：逐 need 报轮次进度——当前 round 是否已验收、验收报告里残余风险
     几条、是否建议开下一轮（读 docs/acceptance/ 的"残余风险/下一轮建议"节）。
3. 全程只读，报告完即停，等用户指令。

## 2. next 模式：自动推进

用户说"继续推进 / next / 自动推进"时进入。先 Read references/next-mode.md（路由表）
与 references/context-watermark.md（水位线），然后：

1. **水位评估**：按 references/context-watermark.md 测量当前会话上下文 token
   用量占窗口百分比并定档（绿 <30% / 黄 30%–50% / 红 ≥50%）。
   绿 → 正常推进；黄 → 只推进单阶段、出口不自动串联，并告知用户用量与本轮边界；
   红 → 不推进，建议新开会话重跑 /sdlc 从盘上续接。拿不准按更高档执行。
2. 按默认模式盘点，对照路由表确定下一个该动作的技能，说明路由依据
   （"3 张工单已实现且已有 approved 评审覆盖 → 进入 dev-ship"）。
3. 用 Skill 工具调用目标技能（黄档时向它声明：完成本阶段即在出口收口，不自动串联）。
   被调技能会在自己的门禁或决策点停下——决策问题原样转达（必须带默认建议），
   本轮到此为止。
4. 目标技能未安装 → 报告断链："流程走到 dev-ship，该技能未实现"，指路蓝图批次
   或按 docs/METHOD.md 手动推进，禁止越权代劳它的写入动作。
5. 一次 next 只推进到一个决策点；用户答复后再次 next 时重新评估水位再继续。

## 3. 中断与交接

总控无自有状态，任何时候中断都无损失：状态全在盘上，重进即按 §1 重新盘点。

## 禁止事项（任何时候）

- 创建、修改、移动任何文件——包括"顺手"帮用户改一个状态字段。状态变更只由对应 dev-* 技能执行。
- 跳过门禁代劳下一步（spec 未批准就拆工单、评审未过就催合并）。
- 红水位下以"就差一步"为由继续调用新技能。
- 不运行 check.sh 就凭记忆盘点，或报告盘上不存在的状态。
```

### 3. skills/sdlc/references/next-mode.md（约 50 行）
进入 next 模式才加载。核心是按优先级排列的路由表（盘上状态 → 下一动作 → 停在哪）：
1. 有 in-progress 工单 → dev-implement 重入续接；2. 有 implemented 工单未被 approved review 覆盖 → dev-review；3. implemented 且已有 approved review 覆盖 → dev-ship（合并确认单向门）；4. frontier 有 ready 工单 → dev-implement（多张时先问，默认最小编号——dev-implement 规定工单由用户点名）；5. spec approved 且无工单 → dev-plan（拆分粒度确认）；6. spec draft → dev-spec（批准+分轮决策点）；7. design draft → dev-design（批 2）；8. need draft 或空库 → dev-clarify（批 2）；9. spec 全部工单 done 无 acceptance → dev-accept；10. 验收 passed 有残余风险/need 未 fulfilled → 问是否开下一轮（循环回转点）；11. need fulfilled → 闭环报告即可。
表后附三条规则：推进=调 Skill 不代劳；断链处理与指路；匹配不到时如实报告请用户裁决。

### 4. skills/sdlc/references/context-watermark.md（约 45 行）
进入 next 模式才加载。内容：
- **定位**：next 模式是全链路里最容易连续吃上下文的环节（被调技能 + 它的 references + 产物全文 + 命令输出全部进窗口）；上下文越满模型表现越差。水位线收紧到 50% 即红，职责是在跌出聪明区之前早早收口，把续接交给盘上状态，而不是赌压缩后的记忆。
- **测量（先精确后估算，宁高勿低）**：
  1. 首选：读智能体环境的上下文指示（已用 token 数或剩余百分比）。有精确值 → 直接按档位表定档。
  2. 兜底估算：环境无指示时按字符折算——中文 ≈1.5 字/token、英文 ≈4 字符/token，估算对象为系统提示 + 全部对话消息 + 全部工具输入输出的累计值，除以窗口总量；只允许向上取整，算不准按更高档。
- **档位表（占窗口百分比；用户定档 2026-10-27）**：
  - 绿 <30%：正常推进——调用路由表目标技能，允许自动串联，直走到下一个决策点。
  - 黄 30%–50%：收窄推进——只调用目标技能完成单阶段，向它声明"出口收口、不自动串联"；决策点照常问人；推进前告知用户当前用量与本轮边界。
  - 红 ≥50%：停止推进——不调用任何技能；报告用量与档位，建议新开会话重跑 /sdlc（盘点）或 /sdlc next（从盘上续接）。
  - 50% 红线远在常见自动压缩阈值（80–90%）之前，为收口与决策对话留足余量；环境压缩阈值更低时以更低者为准。
- **话术规范**：黄/红档输出必须含当前用量（精确值或"估算 ≥N%"）、命中档位、本轮边界；默认建议放第一项；禁止"感觉还够"式表述。
- **禁止**：红档继续调新技能；无环境指示时跳过评估；因水位收窄跳过决策点（收窄的是推进距离，不是决策纪律）；估算向下取整。
