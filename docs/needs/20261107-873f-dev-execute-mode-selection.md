# dev-execute 运行形态选择：并行模式与值守模式

## 背景与业务目标

用户 2026-11-07 提出（原话）：

> 我想把 dev-execute 这个技能做升级：
> - 并行模式提供选择，默认推荐为异步多子智能体方式
> - 增加值守模式选择，分为有人值守和无人值守，无人值守时按大模型判断选最优解

已查证现状（2026-11-07）：

- 现行并行形态是**自动探测回退链**、用户不选择：dev-execute SKILL.md §3.3 开工确认前
  做能力探测，命中即声明——档 1 整图单运行（声明式工作流）> 档 2 后台子代理 >
  档 3 同步子代理 > 档 4 串行逐票（派发细则见
  `~/.zcode/skills/dev-execute/references/run-mechanics.md` §4）。该回退链来自
  need 0010 / spec 0012（FR-6 宿主自适应派发）；档 1 列最优先来自 need 0011 /
  spec 0013（整图单运行，done）。
- 值守模式无既有覆盖：现行所有决策点（开工确认、编排评审阻断、§8 五类异常流、
  合并确认单向门）一律停下问人，且明文"不自动重试、不自动解冲突、不自动改 spec"。

与既有产物的关系：

- "默认推荐异步多子智能体（档 2 后台子代理）"与 spec 0013 把档 1 设为回退链
  最优先的拍板**方向相反**——是策略调整，非重复立项。
- 值守模式触碰 §8 异常流与合并确认两条硬边界，是授权边界问题，非机制缺失。

业务目标（2026-11-07 拍板）：

- **并行模式默认推荐档 2**：动机为档 1 脚本生成成本高 + 编排重、逐票进度不透明
  （D1 多选拍板）；档 1 降为可点名选项，spec 0013 交付的机制保留（D2）。
- **无人值守挂机跑**：发起时一次点选（含开工确认）+ 合并到主分支一次人工确认，
  中间决策由大模型判断选最优解、零人工停机（D3）。
- **有人值守零回归**：默认值守档行为与现行完全一致，人工交互次数与现状持平
  （开工确认 + 合并确认两次）；变化的只是并行档默认建议文案（D4）。

## 干系人与用户

- 编排用户：在宿主智能体中发起 dev-execute 运行的人（本技能为个人技能，唯一用户）。
  并行模式与值守模式的选择者；无人值守时把决策权让渡给大模型，事后依留痕审计
  自主决策的人。
- 主会话 / 图内脚本：运行编排者，值守模式决定其决策点行为（停下问人 vs 自行选优
  并留痕）。
- 实现子代理：每票一个，行为不受本 need 影响（实现纪律不变）。

## 系统能力需求

- **FR-1 并行模式点选**：开工确认时能呈现能力探测后的全部可用并行档位（档 1/2/3/4，
  宿主缺能力的不出现）供用户点选，默认推荐档 2 后台子代理；用户可点名任意可用档
  （含档 1 整图单运行）。〔源：原话"并行模式提供选择"、D1、D2、D4、D8〕
- **FR-2 档 1 退出自动优先位**：能力探测不再把档 1 列为自动命中首选——档 1 仅经
  用户点名进入运行；档机制本身与 spec 0013 交付的整图单运行能力保留。〔源：D2〕
- **FR-3 值守模式点选**：开工确认时能一并点选值守模式——有人值守（默认，行为与
  现行一致）或无人值守。〔源：原话"增加值守模式选择"、D4〕
- **FR-4 无人值守自主处置**：无人值守运行中，除"合并到主分支"外全部决策点由
  大模型自行判断选最优解并继续运行——含评审设计级阻断自行定方案、合回冲突自行
  解冲突、spec 缺口自行修订并入图、预演失败自行开 fix 票入图重算、机械评审问题
  修后重审；运行不因决策停机。〔源：D3、D6、原话"按大模型判断选最优解"〕
- **FR-5 合并到主分支人工门保留**：无人值守运行全绿后停在合并确认，不自动合并、
  不自动清理；用户显式确认才执行合并。〔源：D3 用户原话"要不要合到主分支才要人
  决定"〕
- **FR-6 自主决策留痕**：无人值守每次自主决策逐条留痕——决策点、候选与所选、
  一句理由，进该票 Progress 与出口报告；事后审计可依留痕推翻任一决策并重跑。
  〔源：D7〕

## 场景

主流程：

- **场景 1（有人值守默认运行）**：Given 用户点名一张 approved spec，When 开工确认
  呈现分层图 + 预检报告 + 并行档点选（默认推荐档 2）+ 值守模式点选（默认有人值守），
  Then 确认后按档 2 异步多子代理运行，人工交互恰两次（开工确认 + 合并确认），
  其余行为与现行一致。
- **场景 2（无人值守挂机）**：Given 用户在开工确认点选无人值守与某并行档并确认
  开跑后走开，When 运行中预演红灯，Then 大模型自行开 fix 票入图重算并继续运行
  （不停机、不问人），决策留痕进票 Progress；运行全绿后停在合并确认等用户回来。
- **场景 3（无人值守设计级自主处置）**：Given 无人值守运行中编排评审发现接口级
  问题，When 大模型自行定方案、受影响票重开实现，Then 运行不停，决策留痕进
  票 Progress 与出口报告，事后可审计推翻。〔对应 D6〕
- **场景 4（点名档 1）**：Given 用户在开工确认点名档 1，Then 本次运行按整图单运行
  形态执行（spec 0013 机制承载），值守模式照常点选生效。

异常流：

- **异常 1（无人值守合回冲突）**：merge-tree 预检序候选仍全冲突 → 大模型自行解
  冲突继续（留痕）；有人值守下仍停下问人（现行语义不变）。〔对应 D6〕
- **异常 2（无人值守 spec 缺口）**：大模型自行修订 spec、新票/改票并入图重算后续
  （留痕）；有人值守下仍停机问人。〔对应 D6〕
- **异常 3（合并确认拒绝）**：无人值守运行停在合并门，盘上状态即运行状态（§7
  续接），不强推、不清理。〔对应 FR-5〕
- **异常 4（有人值守零回归）**：有人值守全部决策点仍停下问人，现行 §8 五类异常
  语义零变化。〔对应 D4〕

## 假设与风险

- **A1（设计风险，D6 接受）**：无人值守设计级自主定方案无人工把关——定错方案
  返工整条下游链；缓解 = FR-6 留痕可审计推翻；代价已由 D6 拍板接受。
  〔验证通过（20261107-23b0）：演练①设计级阻断自定方案 + 3 条决策留痕可审计，缓解机制实测在案〕
- **A2（循环风险，显式不设防）**：无人值守自主处置可能循环打转（同票反复 fix、
  反复改方案烧时间与 token）；D6 拍板"全部交大模型"未选熔断档，本 need 不设
  处置次数上限——实际运行出现打转时再议（round 2 候选）。
  〔本轮未触发（20261107-23b0）：4 次演练运行无同票反复 fix/反复改方案；风险保持 round 2 候选〕
- **A3（外部依赖）**：无人值守"中间零停机"依赖宿主权限模式不在工具调用中间打断
  （如权限确认弹窗）；技能层只能约定运行内决策行为，宿主权限配置归运行环境前提，
  spec 须显式声明该前提。
  〔验证通过（20261107-23b0）：前提在开工确认显式声明（声明不阻断），全自动化宿主全程未被打断〕
- **A4（边界影响，交 spec 处理）**：FR-4 与 SKILL.md 禁止事项"不自动解冲突、
  不自动改 spec"字面冲突——无人值守档须把禁令改为按值守模式分档表述（有人值守
  绝不、无人值守留痕解），具体条文改写归 spec。
  〔验证通过（20261107-23b0）：蓝图 v1.25/SKILL.md §8 分档条文落地；有人值守禁令全量生效与
  无人值守"不脱离纪律重试"双向实证〕

    被该门禁自指拦死；经用户拍板走 [trivial] 豁免修复（done 豁免，retro 审计），
