# @hankghchen/infra：一条命令把套件资产安装进目标项目（技能为第一类资产）

## 背景与业务目标

本套件当前唯一的安装方式是人肉拷贝：README《快速上手》第 1 步要求使用者「把 skills/ 下各子目录拷贝或软链到智能体的技能目录（ZCode 为 `~/.zcode/skills/`）」（README.md:50，2026-11-14 检索）。31 个技能逐个拷贝，路径因智能体而异，接入门槛高、易装错版本、无升级路径。

需求发起人（套件维护者）的目标（2026-11-15 升格）：做一个**个人基建初始化器**——体感对标 `pnpm create vite`：在自己项目的仓库根目录跑一条裸 npx 命令进交互菜单，选类型、勾条目、落盘安装；技能（skills）只是第一类安装内容，未来可扩展规范等其他资产类型。可验证目标：在一个全新 git 项目目录内，`npx @hankghchen/infra` 执行完后 `.agents/skills/` 下出现所选套件技能，项目内智能体（ZCode / Claude Code）能发现并调用它们；一条命令可升级；新增资产类型时经映射表加行扩展而安装器骨架不改。不做的代价：外部用户接入停留在手工拷贝，套件传播受限，装完的版本与上游漂移无从对账；名下其他基建资产（规范等）将来各装各的，无统一入口。

**内联查证关键结论（2026-11-14，本机实测）**：生态内已有现成安装器 vercel-labs/skills CLI（`npx skills add <owner>/<repo>`，开源），对本仓库零改动即可跑通——发现（`--list` 列出全部技能，中文 description 正常展示）与项目级安装（技能落 `./.agents/skills/`，对检测到的 agent 目录建软链，`./skills-lock.json` 记账）均实测通过，作为行为参照与降级备选。发起人拍板不走生态 CLI、自建 npm 命令行。另实测：npm registry 本机可达（候选包名查询正常返回），GitHub 直连克隆 300s 超时——npm 发布渠道对国内网络显著更友好。**包名 `@hankghchen/infra` npm 实测可用（2026-11-15 查询，scope `hankghchen` 无任何占用）。**

- **FR-2** 安装完成后，项目内使用的智能体能发现并调用已装的套件技能（溯源：原话「安装到项目内的 .agents/skills 里」——安装的目的即被智能体使用；参照实测：universal 目录 + 对检测到的 agent 目录建软链，目标目录不存在时跳过并提示）。
- **FR-3** README 等面向人的文档把一条命令安装写成官方安装方式，替换现有「拷贝或软链」指引，并写明升级、卸载命令与网络受限时的缓解路径（溯源：原话「把技能做成可被安装到项目内的命令行」——对外的安装故事）。
- **FR-4** 安装器按「套件资产」（GLOSSARY 项目术语章）组织安装内容，资产模型为**「资产类型 → 安装目标」映射表**扩展点：本轮映射仅一行——技能 → `.agents/skills/`；规范等其他资产类型在本轮菜单中显示占位、不实现安装逻辑；新增类型按映射表加行扩展（具体安装目标路径归 spec/design）（溯源：原话「skills只是其中一项安装内容」「套件的专属资产，现在有技能，以后可能还有规范之类」2026-11-14/15、预想④「全对」2026-11-15）。

## 场景

**主流程（交互安装）**
- Given 使用者在一个全新 git 项目根目录（如 `my-app/`）
- When 裸跑 `npx @hankghchen/infra`
- Then 进入两层菜单：第一层选资产类型（技能可选；规范等未来类型显示占位不可选）；第二层勾选该类型下的条目（如 31 个技能多选）
- And 选毕安装：技能落 `.agents/skills/<技能名>/`（含 SKILL.md 与 references/），对检测到的 agent 目录建软链（不存在则跳过并提示），锁文件记账（机制细节归 spec/design）
- And 项目内智能体新会话能触发已装技能

**脚本化安装**：When 带非交互旗标跑（如全装），Then 免交互完成安装（对应 FR-6）。

**升级**：When 使用者重跑安装命令（或升级命令），Then 已装资产对账上游更新（机制归 spec/design，行为参照生态 CLI 的 update/check）。

**异常流 A（网络受限）**：安装内容随 npm 包分发、不经 GitHub；When 使用者访问 npm registry 受限，Then README 写镜像/代理等缓解路径（对应 FR-3、A2 残余风险）。

**异常流 B（装了技能但未接门禁）**：Given 项目只装了技能、未跑 `/setup-workspace`，Then 技能可被智能体触发，但流程门禁（`.sdlc/check.sh`）不存在——技能入口的工作区校验会拒绝流程技能并指路 `/setup-workspace`；安装文档按「先安装、后 `/setup-workspace` 接入门禁」的顺序写明两步关系（Q3 拍板 2026-11-14：CLI 不代做初始化，见非目标）。

## 假设与风险

- **A1（风险）agent 目录约定跟进**：自建 CLI 的安装目标要覆盖各智能体的技能目录约定（`.agents/skills/`、`.claude/skills/` 等），约定随各家演进。代价：新 agent 出现或目录变更时需跟进适配；不确定度：低（`.agents/skills` 已是跨智能体 universal 约定，vercel-labs/skills 支持 20+ agent 可作参照清单）。
- **A2（风险）安装内容的网络可达性**：国内网络 GitHub 直连克隆易超时（2026-11-14 实测 300s 超时一次）。npm 发布后，安装内容随 npm 包分发、不经 GitHub，npm registry 本机实测可达（2026-11-14/15 查询正常返回）；残余风险仅剩使用者访问 npm registry 本身受限的场景，README 写镜像/代理缓解路径（对应 FR-3）。
- **A3（风险）自建 CLI 的维护与内容同步成本**：自建拍板接受的成本——打包、npm 发布纪律、issues 维护，以及 npm 包内容与 `skills/` 目录的一致性（发布流程须保证随包资产与仓库同版本）。代价：每次资产改动多一道发布动作；不确定度：低（机制问题，spec/design 可解）。
