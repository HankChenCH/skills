# dev-overview：开工前的体验总览评审

## 背景与业务目标

管线 clarify→spec→plan 的产物全是分解物：need 拆业务、spec 拆行为、工单拆交付——没有任何产物回答"功能实现成什么样"。管线里唯一能"看"的能力（可点 HTML 原型，dev-clarify references/prototype.md）锁在 clarify 阶段且用完即弃；spec 的集成级验收场景是现成的"整个系统演一遍"剧本，但演出时点在实现之后。

用户原话（2026-11-02）："拆完 needs、spec、tickets 之后我依然不知道功能会实现成什么样，想要设计一个技能生成总览给我评审。"

业务目标（可核销）：
- 下一个多票功能在第一票开工前完成一次走查，走查暴露的缝隙在开工前归置清零（缝隙清单零未归置项）。
- 评审人读完总览能逐条指认每个能力给谁用、在哪张票交付，全程不读源码。
- 不做的代价：形状错误实现后才发现，返工以票为单位；"票全做完、产品没做成"的 Patton 式失败无门禁拦阻。

## 干系人与用户

| Actor | 要完成什么 | 成功标准（可核销） |
|---|---|---|
| 用户（需求人/评审人） | 开工前看懂功能全貌并拍板 | 走查后能复述体验、逐条指认能力↔票的归属；缝隙归置清零后总览置 reviewed |
| 实现会话（dev-implement） | 开工入口合规 | 多票 spec 无 reviewed 总览时被拦并指路 /dev-overview；单票 spec 直接放行 |
| 流程本体（check.sh） | 门禁机械可查 | `ticket` 子命令校验含总览检查项，判定规则机械、无判断空间 |

## 系统能力需求

- FR-1 合成总览：能从 need + spec + design（若有）+ 名下全部工单纯读合成一份总览文档（固定五节：全景一行/全景矩阵/黄金场景走查/样张/差距清单），全程不产新决策，正文每段可溯源到既有产物。
- FR-2 全景矩阵：能给出 actor × FR × 验收场景 × 工单号映射；任何格子指不回工单或场景时，按缺口暴露给评审人。
- FR-3 黄金场景走查：能生成 2–3 条用户视角的端到端走查叙事（含至少一条异常流），剧本取自 spec 验收场景（优先集成级）。
- FR-4 样张按对象类型选媒介：UI → 三态（正常/空/错误）可点 HTML 原型，落系统临时目录不进仓库；CLI → 输出样例（输出即线框）；API → 调用序列 + 请求/响应样例。样张中写不出的格子一律进差距清单，不许现场拍板。【拍板 D2】
- FR-5 差距清单三路归置：走查暴露的缝隙逐条归置——回 dev-spec（补 FR/改场景）、回 dev-plan（补票/重切）、写非目标；拍板落点永远在 spec/工单上，总览是脚手架，不是第二真相源。
- FR-6 过程档生命周期：总览落 `docs/overviews/`，进 `.gitignore` 排除、不进任何提交；spec 验收通过后随蒸馏清扫删除。【拍板 D4】
- FR-7 开工硬门禁：触发点 = 票拆完、开工前【拍板 D1】。spec 名下工单 ≥ 2 时，dev-implement 入口（`check.sh ticket`）校验存在 reviewed 状态的总览，缺失即拒绝开工并指路；名下单票豁免（此时总览≈单票的"做什么"，冗余）。【拍板 D3】

## 场景

主流程：
- Given spec NNNN approved 且名下 3 票 ready，When 评审人让生成总览并完成走查，Then 全景矩阵无指不回的格子，暴露的缝隙逐条三路归置（对应 spec/票已更新），总览置 reviewed，第一票准予开工。

异常流：
- 走查暴露 spec 缺 FR/场景 → 回 dev-spec 修订（回路，不是失败）→ 来源：方案纪律"总览只暴露缝隙，不产新决策"
- Given 多票 spec 且无 reviewed 总览，When dev-implement 入口校验，Then 拒绝开工并列出缺口（无总览/总览 draft）与指路 /dev-overview【拍板 D3】
- Given 单票 spec，When 开工，Then 入口不查总览直接放行【拍板 D3 豁免分支】

## 假设与风险

- A1 总览沦为装饰或影子 spec：写了没人用，或与 spec 漂移成第二真相源。代价最高（门禁形同虚设 + 双真相源）。→ FR-1 溯源纪律与 FR-5 三路归置是靶心防御。round 1 靶心：在真实多票功能上跑通一次"生成→走查→归置"闭环，且走查确实暴露 ≥1 处会返工的缝隙。【验证结果（2026-11-03 验收 0001）】验证通过（带注记）：闭环在真实运行（run/0014，PR #99）中承重实测——门禁拦截真实开工请求、用户走查拍板 reviewed、正文逐段溯源、归置零修订即无漂移面；注记：「暴露 ≥1 处会返工的缝隙」未触发（dogfood 内容零缝隙，缝隙暴露能力由 0029 工单级孤儿 FR 演练另证），见下方残余风险 1。【验证结果（2026-11-08 验收 4fe6，round 2）】验证通过（带注记）：自动衔接链让"生成→走查→归置→reviewed"在 frontier 呈现前完成——主腿 6 条用户输入零条触发合成；合成纯读（指纹前后一致）；走查暴露 3 处会使不同票各自实现不一致行为的缝隙、全部 reviewed 前清零（真实内容缝隙暴露能力补证 round 1 零缝隙缺口）；注记：fixture 为验收代理自建，非真实多票功能，真实人机交互误读风险未覆盖。【验证结果（2026-11-08 验收 eb9e，round 3）】验证通过（带注记）：门禁承重实拦 4 次（draft 态 ×2、回置 draft 推迟走查 ×2，均 exit 1 + 指路），放行均发生在语义正确时；回置腿五节正文 diff 逐字节不变、总览文件数全程恒 1、claim overview 仅 1 次——补票路径上总览义务以"回置重走查"而非"新建副本"履行（A1 靶心防御 round 3 新证据）；溯源密度 `来源：`×6、票/spec 引用 ×12。
- A2 并票逃逸：为绕门禁把大功能并成单票。→ dev-plan 既有纪律"装不下单个新会话上下文就再切"天然抑制；retro 审计兜底。【验证结果（2026-11-03 验收 0001）】本轮未触发：spec 0014 拆 4 票、改动面独立、blocked-by 成链，无并票动机出现。【验证结果（2026-11-08 验收 4fe6）】本轮未触发：两张 fixture spec 均垂直切片拆 3 票；探针另证门禁按名下全部票计数，出口 ready 口径绕不过门禁（见 round 2 残余风险 1）。【验证结果（2026-11-08 验收 eb9e）】本轮未触发（3 票垂直切片）；补证：overview_gate 计数不分状态（in-progress 计入 own，实操 own=2/3 均触发总览义务），出口同口径后 round 2 逃逸面已关闭，补票仍被链式回置兜住。
- A3 媒介判定不准：AI 从 spec 实现决策判 UI/CLI/API 判错。→ 判不准时亮牌问用户，误判成本低（一张决策卡）。【验证结果（2026-11-03 验收 0001）】验证通过：dogfood 判定 CLI 一次命中（判定理由成文于总览样张节），未出决策卡、未误判。【验证结果（2026-11-08 验收 4fe6）】易判情形验证通过：两张 fixture spec 依实现决策一次判 CLI；混合/难判情形本轮未触发。【验证结果（2026-11-08 验收 eb9e）】易判情形再证通过：实现决策明示 CLI → 一次判定三态输出样例，未出决策卡；混合/难判情形未触发。
- A4 上游含糊导致合成不出：need/spec/票写得含糊时总览填不满。→ 这恰是设计意图：合成失败即上游含糊的证据，走差距清单回上游，不现场补写。【验证结果（2026-11-03 验收 0001）】本轮未触发：合成一次通过、validate 首过、差距清单为空。【验证结果（2026-11-08 验收 4fe6）】验证通过：spec 未写明的 3 处行为显形为「？？」格子进差距清单，经拍板回写 spec 非目标后才置 reviewed；总览未现场补写，validate 首次即通过。【验证结果（2026-11-08 验收 eb9e）】本轮未触发：fixture 上游清晰，合成一次完成、validate 首过、差距清单无缺口。

## 范围与非目标
