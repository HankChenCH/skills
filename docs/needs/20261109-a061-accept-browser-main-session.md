# accept 浏览器场景当前会话验收

## 背景与业务目标

spec 20261108-2fe1 确认"恰一个隔离验收代理（强制）"：宿主原语仅限主会话时视同缺失走降级，不得由主会话代操作（dev-accept/SKILL.md:56、61）。ZCode 宿主的内置浏览器操作原语（browser-use / computer-use 类，经 node_repl 承载）自述 main agent only、仅主会话可用——用户在 dev-execute 串联 dev-accept 的实现会话中实测命中（2026-11-09 陈述）。结果是 Web 界面场景验收在 ZCode 宿主上永远走降级路径——启动服务 + 脚本 + 截图，拿不到真实浏览器操作证据（打开、点击、输入的实操记录）。

业务目标：Web 界面场景的验收回到真实浏览器操作取证，不再因"原语仅限主会话"而降级；非浏览器介质（CLI / API / 文档）的判断隔离保持不变。不做的代价：ZCode 宿主上浏览器场景验收报告永远带【降级】标记，使用方走查轴（GLOSSARY：判断依据 = need 全文、spec「验收场景」节、design「界面设计」述标、可点原型、BASE_REF 集成后交付物）在 Web 交付物上名存实亡。

反转理由（2026-11-09 陈述确认）：判断隔离的收益 < 浏览器场景永远降级的代价——拿不到真实操作证据，Web 场景验收形同虚设。

## 干系人与用户

- 验收使用方（消费方视角）：拿到带真实浏览器操作证据的验收报告——Web 场景行含截图路径与操作序列、无【降级】标记；逐场景可核销。
- 主会话 / 编排会话：浏览器场景走查的执行者与判定者（仅当浏览器原语对其子代理不可用时）。
- 隔离验收代理（恰一个子代理承载、只装使用方走查轴材料清单的验收执行体）：非浏览器介质场景的执行者，机制不变。
- dev-execute 编排（档 1 图内 / 档 2–4 串联）：串联验收时按本 need 约束分配走查承载。

## 系统能力需求

- FR-1：浏览器原语仅限主会话的宿主上，Web 界面场景的验收能由当前会话真实操作浏览器完成（打开、点击、输入），以截图与操作记录取证，不走降级路径。（源：用户原话"改回当前会话浏览器验收避免降级"，2026-11-09）
- FR-2：浏览器原语对验收子代理可用时（可用性以工具自述为准），Web 界面场景仍由隔离验收代理承载——隔离优先，当前会话仅作隔离不可行时的兜底。（源：D1 拍板 + 定稿读法确认 2026-11-09："隔离原则只在让位不可避免处让位"）
- FR-3：主会话承载浏览器场景走查时，判定（过 / 挂）由主会话亲做；仍只装使用方走查轴判断依据材料、排除禁装清单（工单 Progress、实现交接记录、实现会话上下文）。（源：D2 拍板，2026-11-09）
- FR-4：验收报告形态行能如实声明混合形态（例：「隔离验收代理（非浏览器介质）+ 主会话浏览器走查（浏览器介质）」）；【降级】标记只用于确无可用浏览器操作原语的情形。（源：D1 / D2 拍板 + 现行报告契约 dev-accept/SKILL.md:101）
- FR-5：dev-execute 各档串联验收时，"浏览器场景当前会话承载"约束对档 1 图内验收代理阶段同样成立；图内停回主会话的承载方式归 dev-spec。（源：澄清切分拍板 2026-11-09；承载机制已查证存在——dev-execute/references/run-mechanics.md:226"升级提问/洞穴在图内停下问人"）

## 场景

主流程：
- Given 浏览器原语仅限主会话、spec 验收场景含 Web 界面场景，When 验收序列执行到 Web 场景，Then 当前会话真实操作浏览器（打开 / 点击 / 输入）取证并判定，报告形态行声明混合形态，该场景行无【降级】标记（FR-1、FR-3、FR-4）。

异常流：
- Given 浏览器原语对验收子代理可用，When Web 界面场景执行，Then 仍派隔离验收代理承载（FR-2）。
- Given 宿主完全无浏览器操作原语，When Web 界面场景执行，Then 维持现行降级路径（启动服务 + 脚本 + 截图 + 【降级】标记），降级不降标准（FR-4 的【降级】语义不变）。

## 假设与风险

- A1（① round 1 靶心）：主会话在 dev-execute 编排上下文中亲做亲判不受实现上下文污染（禁装清单纪律足够）。错了伤：验收放水（实现者自验嫌疑），验收公信力受损。验证：混合形态首次真实落地走查并留报告痕，retro 审计判断独立性。→ **本轮未触发**（验收 20261109-4e65：round 1 交付为纪律文本，无 Web 场景实操；载体 = 下次含 Web 交付物验收首验后 retro 审计）。
- A2（④ 随手拍板 → 已进 FR-2）："浏览器原语对子代理可用"以工具自述为准判定。错了伤：隔离优先分支误判（该隔离没隔离，或反之）。验收序列开工时按现行派发单能力声明机制（dev-accept/SKILL.md:56）枚举原语可用性即可消掉，不以假设形态存在。→ **验证通过**（验收 20261109-4e65：能力声明三态已落盘并随派发生效，dev-accept/SKILL.md:58 + 蓝图 §11.9；本轮派发单即实例）。

round 1 靶心建议：FR-1 + FR-3 + FR-4（dev-accept 介质选择规则反转 + 报告形态枚举扩展）先行；FR-2 / FR-5 的承载细节同批交 dev-spec。

**验收折回（20261109-4e65 passed，round 1）**：残余风险——① 混合形态真实落地行为（浏览器亲做取证 / 两来源聚合 / 形态行声明混合）仅临时仓库演练佐证（蓝图 §13.2），真实宿主行为待下次含 Web 交付物验收首验；② 宿主 IAB 可信点击/按键事件不投递页面（蓝图 §13.2 实录），下次点击类取证需页面内事件激活兜底；③ 档 1 图内停回主会话整链未经真实编排运行验证（同 FR-5 集成级载体）。下一轮建议——下次含 Web 交付物 spec 验收首验 FR-1 集成级 + 混合形态全链并预留点击兜底方案；下次档 1 真实运行首验 FR-5 集成级；两处首验后 dev-retro 审计 A1 判断独立性。

## 范围与非目标

- 非目标 1：不改非浏览器介质（CLI / API / 文档）的隔离验收代理机制——need 20261108-c788 其余条款保持。
- 非目标 2：不在本 need 决定档 1 图内验收停回主会话的承载方式（洞穴停点 / 验收段移出图）——归 dev-spec。
- 非目标 3：不改变"降级不降标准"原则与完全无浏览器原语宿主的降级路径。
- 非目标 4：不扩展只读证据代理（只能 Read PNG 的 visual-judge 类代理）的浏览器操作能力——"浏览器操作原语"仅指宿主提供的浏览器操控类原语（browser-use / computer-use）。
