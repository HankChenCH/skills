# dev-execute 收口链验收前置：合并候选先验收、passed 才卡合并门

## 背景与业务目标

现状收口链（dev-execute §6）顺序为：运行全绿 → PR 准备 → 合并确认（人工单向门）→ 执行合并 → 票 done → 清理 → 自动验收（dev-accept）→ 出口报告。验收发生在合并之后，验收对象是 BASE_REF（主分支）上的集成代码——验收 rejected 时缺陷已经进了主分支，需要回滚或开修复票才能恢复主线干净。

目标：验收 rejected 的改动不进主分支。可核销：rejected 终态的运行结束后，`git log BASE_REF` 中无该运行分支的提交。负责人在合并门决策时手握验收证据——验收 passed 的报告编号与结论随 PR 正文呈现："通过了没打问题，才卡合并门告知负责人"（用户原话）。

不做的代价：每次验收 rejected 都污染主分支历史，协作者拉到缺陷代码，回滚产生额外提交噪音。

## 干系人与用户

- **负责人**（用户，合并门决策者）：要完成的是"凭验收证据决定是否合并"；成功标准 = 合并门前能看到验收报告编号、终态（passed）与硬伤/瑕疵结论。
- **执行编排**（dev-execute）：重排收口链顺序、承载验收 rejected 后的 fix 重验环。
- **验收执行**（dev-accept）：验收承载适配——现行入口门禁第 3 条机械要求"当前分支 = BASE_REF"，须支持在运行分支（合并候选）上验收。
- **缺陷修复**（dev-fix）：rejected 时接收 fix 票（入运行图，与既有异常流同机制）。

## 系统能力需求

- FR-1：dev-execute 能在合并前对运行分支上的合并候选执行验收（集成级自动化段须全绿 + 人工段实操走查，dev-accept 现行判定分级判据不变）——dev-accept 支持按调用方声明选择验收承载（编排串联 = 运行分支合并候选；单独手动调用保持现状 = BASE_REF），入口门禁相应适配（工票全 implemented 且逐票评审 approved、预演绿、当前分支 = 所声明承载分支）。
- FR-2：验收 passed 后才允许进入合并确认门；PR 正文 Evidence 含验收报告编号与终态，负责人在合并门直接看到验收结论。
- FR-3：验收 rejected（第一轮）时自动开 fix 票入运行图：修复 → 评审 → 合回运行分支 → 预演 → 重新验收；passed 后回主流程合并门。
- FR-4：重验环限一轮——第二次验收仍 rejected 时运行停在待判断点等人（全模式保留人工，无人值守不豁免；语义同合并门）。
- FR-5：票 done、蒸馏、清扫、spec 置 done、need 置 fulfilled 确认门的时序保持合并后不变；验收 passed 即放行合并门，不在合并前做 fulfilled 确认。
- FR-6：验收未 passed（重验环在办）期间运行分支与运行 worktree 保留——现状"合并未执行不清理"扩展为"验收未 passed 不清理"。

## 场景

主流程：
- Given 运行全绿（全部工票 implemented、逐票评审 approved、预演绿）When 收口启动 Then 在运行 worktree 上对合并候选执行验收 → passed → 准备 PR（Evidence 含验收报告编号）→ 卡合并门告知负责人 → 负责人确认合并方式 → 合并 → 票 done → 清理 → fulfilled 确认门（运行后停点）→ 出口报告。

异常流：
- 验收 rejected（第一轮）→ 自动开 fix 票入图 → 修复→评审→合回→预演→重新验收 → passed → 回合并门（→ 拍板 D1）。
- 验收 rejected（第二轮）→ 运行停在待判断点等人，分支与 worktree 保留，出口报告载明两轮验收结论（→ 拍板 D1）。
- 负责人在合并门拒绝合并 → 运行停在合并门，盘上状态即运行状态，不强推、不清理（现状语义保持）。
- 无人值守：验收段全自动跑到 passed 停在合并门等人；第二轮 rejected 的停点待人同样不豁免（→ 拍板 D1）。

## 假设与风险

- A1（代价中、不确定度低）：合并候选上验收 passed 等价于合并后验收——合并后不做二次验收。若主分支在验收后有新提交或合并产生冲突解决差异，存在缺陷漏进主线的残余风险；`check.sh all` 预演与逐票评审覆盖其中大部分。残余风险处置：出口报告如实载明"验收承载 = 合并候选（合并前）"。——验证通过（验收 20261111-fabf：run-mechanics 冲突后不二次验收条文落盘、出口报告载明句演练实测 runX-08:8）。
- A2（代价低、不确定度低）：有人值守时验收段交互（复述确认、实操走查）前置到合并门前发生，"运行内人工交互恰两次（开工确认 + 合并确认）"的定位改为：人工停点 = 开工确认 + 验收段交互（有人值守）+ 合并确认门 + rejected 待判断点（如触发）。——验证通过（验收 20261111-fabf：活本"恰两次"零残留、分档表述三处同批、演练中验收段交互实测先于合并确认）。
- 残余风险折回（验收 20261111-fabf，均不阻塞）：①场景文"验收报告首行"与交付口径「场景结果」节首行形态行的措辞偏差（已按实际边界修订 spec 场景 9）；②bad9 实录卫生（占位符残留与初核口径错误均有更正段）；③演练事件 1 起——§8.6 前置步骤（评审报告同步）是丢失唯一防线，操作疏漏可复发（runX-06a）；④无人值守与档 1 图内链整链行为未实测，留真实编排运行首验；⑤A1 固有残余（本条，已拍板接受）。
- 下一轮建议折回（验收 20261111-fabf）：无人值守/档 1 整链集成行为随下次真实编排运行首验；评审报告同步前置步骤的操作防呆（机械核对加固）值得评估。

## 范围与非目标

- 非目标 1：不限轮数的全自动重验闭环（D1 拍板：限一轮，第二轮待人判断）。
- 非目标 2：fulfilled 确认门移到合并前（D2 拍板：保持合并后）。
- 非目标 3：验收承载迁移到部署环境/集成环境——验收仍在运行 worktree 本地承载。
