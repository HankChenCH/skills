# ref-b-side-design：B 端体验设计方法论参考技能

## 背景与业务目标

design-* 链在 B 端项目上有缺口：design-brief 做信息架构与功能归类、design-ui 出 B 端特有界面（大屏、定制组件、权限模块）时，目前靠模型通用知识，无仓库内章法。ref-refactoring-ui 补了视觉层，但它是通用界面视觉方法论（源自《Refactoring UI》），不覆盖 B 端的结构层问题（功能怎么归类才互相独立、功能命名用谁的语言、业务流程怎么编排）与 B 端特有场景（高客单价大屏、定制化项目组件复用、权限模块体验）。

《B端体验设计入门课》（林远宏/汤圆，极客时间付费专栏）「体验设计」6 讲——08 信息架构、09 业务流程、10 关键界面设计、11 大屏设计、12 组件设计、13 典型模块设计（权限）——系统给出这套章法。用户已购买该专栏（登录态全文可读），原话："我想把体验设计这6讲设计为技能"。用户已拍板：挂 design 链（design-brief + design-ui）、范围仅这 6 讲、分册按方法论重组（非讲次一一对应）。

业务目标（可验证）：
- B 端项目走 design 链产出设计时，设计决策能指回本技能分册规则（含来源讲次）。
- 公开仓库（github.com/HankChenCH/skills）内零付费内容原文——版权风险为零。

不做的代价：design-brief 归类功能、起信息架构时继续裸靠通用知识；B 端特有场景无仓库内判据，产出质量不稳定，同一套 B 端问题各项目重推一遍。

## 系统能力需求

- **FR-1**（独立技能）：`skills/ref-b-side-design/`（命名默认，定稿可改）为 ref-* 形态独立参考技能：SKILL.md 含 B 端体验总纲（复杂守恒定律等公共标准）与任务路由表，`references/` 分册按方法论维度重组——结构层（信息架构、语言体系、业务流程，来源 08/09）与界面执行层（关键界面、大屏、组件、权限模块，来源 10–13）两个方向，具体分册切法归 dev-spec；软链入 `~/.zcode/skills/` 后可被 Skill 工具加载。（来源：用户原话"设计为技能" + 拍板"按方法论重组"）
- **FR-2**（6 讲全覆盖 + 可溯）：08–13 每讲核心章法（方法、步骤、判据、反模式）在分册中有落点，重组后无讲次遗漏；每条规则标注"来源：第 N 讲"保可溯。（来源：用户拍板"仅 6 讲" + "按方法论重组"的可溯性补偿）
- **FR-3**（版权安全）：技能内零原文段落、零图片、零音频；全部重写为方法论表述（步骤、判据、反模式、检查清单）；课程案例仅保留结构化要点（如"明厨亮灶：告警曾耦合两处，按巡查/评分/追溯/数据监控重组"），不搬运叙述文本。（来源：专栏页面版权声明，外部硬约束）
- **FR-4**（挂载生效）：design-brief 与 design-ui 的 SKILL.md（frontmatter description 与装载指引）均可查到本技能装载指令；B 端设计任务能按路由表找到对应分册。（来源：用户拍板"design 链挂载"）
- **FR-5**（互补不冲突）：本技能管 B 端结构层与业务章法；视觉细节章法仍路由至 ref-refactoring-ui，两者在 design-ui 并存不重复。（来源：建议 3，挂载现状查证 design-ui 已挂 ref-refactoring-ui）

## 场景

**主流程 1（结构章法）**
- Given B 端项目在 design-brief 阶段需要做功能归类与信息架构
- When 执行会话装载本技能，按路由读结构层分册
- Then 产出的功能架构按 MECE 互相独立归类、功能命名采用客户语言体系（"巡查/追溯"而非"违规/监控"），设计决策可指回分册规则与来源讲次

**主流程 2（界面执行章法）**
- Given design-ui 为 B 端项目出关键界面/大屏/组件/权限模块设计
- When 执行会话装载本技能读对应执行层分册，视觉细节同时有 ref-refactoring-ui
- Then B 端特有场景有仓库内判据支撑，两技能章法互补不冲突

**异常流 1（非 B 端任务）**
- Given 任务无 B 端属性（纯 C 端视觉微调、CLI/文档视觉）
- When 路由表无命中信号
- Then 不装载本技能，走既有路由，design 链行为不变

**异常流 2（讲次覆盖缺口）**
- Given 验收抽验发现某讲核心章法在分册中无落点
- When 按"来源：第 N 讲"标注逐讲核对
- Then 判 FR-2 不通过，补齐后重验——重组不得造成讲次静默丢失

## 假设与风险

- **A1（构建素材依赖登录态）**：构建期需通过内置浏览器登录态逐讲读取 08–13 付费全文，临时目录存放、不入仓库、用后清扫；若登录过期需用户重新扫码。（外部依赖：极客时间账号；代价：构建中断，重登可续）
- **A2（版权边界残余风险）**："付费内容 → 方法论重构"属个人学习笔记性质、不构成再分发——零原文/零图片/零音频 + 全量重写是硬门禁，但重构与转载的边界无权威判据，残余风险由用户拍板接受；若边界判断失误，代价是公开仓库内容撤回重写。
- **A3（重组致遗漏）**：按方法论重组可能造成个别讲次要点丢失；缓解：FR-2 来源标注 + 验收按讲次抽验。

## 范围与非目标

- 非目标 1：不做「体验设计」之外的讲次（前期分析 03–07、研发实现、体验迭代等）——将来值得做另立 need。（用户拍板"仅 6 讲"）
- 非目标 2：不修改 design 链既有行为与路由，仅新增两处挂载。
- 非目标 3：不搬运课程音频、视频与原文截图。
- 非目标 4：不在技能内做可交互原型或工具，纯方法论参考。
