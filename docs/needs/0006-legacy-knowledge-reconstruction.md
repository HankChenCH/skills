# 存量项目知识逆向：扫描沉淀，冷启动免全量扫描

## 背景与业务目标

现状：本技能套件的知识沉淀（need / spec / adr / GLOSSARY 项目术语 / standards）随正向流程（dev-clarify → dev-accept）逐步积累，假定项目从零开始。存量项目接入时是白纸：没有任何沉淀物，agent 每个新会话都要全量扫描代码才能开工，同一份"理解这个项目"的代价被反复支付。

来源：用户 2026-10-29 原话——"没有用过任何技能套件的存量项目没有 needs、adr、spec 的历史知识沉淀，需要一个技能扫描，尽量逆向出沉淀物，让智能体不至于每次都全量扫描再开始工作，提升效率"。

业务目标（成功标准，2026-10-29 用户确认）：

- S1 已扫描的项目，新会话 agent 只读沉淀物（不跑全量扫描）即可正确接续开发。
- S2 沉淀物中每条行为断言有代码证据（文件:行）可回溯。

## 干系人与用户

- 仓库主人（主 Actor）：对存量项目运行扫描；审查产物并确认后写入项目；验收 S1/S2。
- agent 会话（执行 Actor）：运行扫描——分轮读码、推断、带证据落盘；受"低置信显式标注 + 人工抽查"纪律约束（用户拍板）。
- 未来 agent 会话（受益 Actor）：只读沉淀物接续开发，不重复全量扫描。
- 既有件（不变或轻改干系人）：setup-workspace（未接入仓库的落盘前置——由本技能按其全流程完成接入）、check.sh validate（逆向产物校验，扩展随开放问题 D1）、GLOSSARY 项目术语章、AGENTS.md、docs/standards/、dev-docs 的"先核验后落笔"纪律（复用）。

## 系统能力需求

- FR-1 独立运行：扫描技能（归 setup-\* 家族，暂名 setup-excavate，终名 dev-spec 定——拍板 D5）可在未接入本套件流程的仓库上运行，不依赖 check.sh 已存在（来源：用户拍板"可以独立使用"）。
- FR-2 逆向产物：扫描产出本套件知识档形态的沉淀物——含 need / adr / spec 形态（用户原话点名）并折叠进既有载体 AGENTS.md、GLOSSARY 项目术语章、docs/standards/（来源：用户拍板"a+c"）。逆向 need/spec 落盘即置新状态 `status: reconstructed`——frontier 与 next-mode 不列为待办，check.sh 状态机表为此扩展一处（来源：拍板 D1）。
- FR-3 证据纪律：产物中每条行为断言带文件:行级证据；低置信度推断显式标注（来源：用户拍板"接受"）。
- FR-4 逆向范围：覆盖架构、领域概念/术语、编码标准、历史决策（ADR 候选）、业务规则（来源：用户拍板"按你说的范围"）。
- FR-5 分轮与覆盖度：大仓库支持分轮扫描、按需补扫；产物显式标注扫描基线（commit/日期）与覆盖范围，未覆盖区不得被读成"不存在"（来源：用户拍板"接受分轮"；覆盖度显式化为 AI 补写，随全文确认生效）。
- FR-6 确认后落盘：扫描产物经用户确认后才落盘；确认语义不走 dev-\* 流程——不是"批准待实现规格、可拆工单"，而是"扫描要产出的东西与用户确认后写入"（来源：用户 2026-10-29 拍板）。落盘按仓库接入态分两路：未接入——按 setup-workspace 全流程完成接入（check.sh、hooks、AGENTS.md 哨兵块等），随后写入逆向产物，一次完成；已接入——仅写入逆向产物，不重跑接入（来源：用户 2026-10-29 修正"写入前提有误差"）。
- FR-7 增量对齐：重跑扫描时只更新与代码漂移的部分，不推倒重来；完成后更新产物中的扫描基线（来源：拍板 D3）。

## 场景

主成功场景：

- Given 一个未接入本套件的存量仓库。
- When 用户运行扫描技能，agent 分轮扫描并产出带证据与置信标注的沉淀物草案。
- Then 用户审查确认后落盘：仓库未接入流程时，先按 setup-workspace 全流程完成接入、随后写入逆向产物；已接入时仅写入逆向产物。此后新会话 agent 读沉淀物即可正确接续开发，无需全量扫描（S1、S2 可核销）。

异常流：

- E1 仓库过大单轮扫不完：分轮扫描，产物标注未覆盖区（FR-5），用户可发起补扫。
- E2 用户审查后不确认：产物不写入项目（FR-6 前置）。
- E3 确认后项目继续演化、代码与沉淀物漂移：重跑扫描做增量对齐（FR-7），更新扫描基线。

## 假设与风险

- A1 沉淀物时效风险：正向开发持续改变代码，沉淀物过时会误导后续开发。蒸馏机制（need 0005）在已逆向项目上是否自然续上、重扫对齐的触发时机，留 spec 论证。（代价：错误知识被固化进开发决策；不确定度：中）（验证：通过——spec 0008 A1 论证双轨互不污染成立，验收中逆向产物未进 frontier、正向门禁零改动；重跑语义在票 0004 成文并经夹具演练；长期漂移的实际重扫触发本轮未触发）
- A2 逆向推断幻觉风险：以 FR-3 证据纪律 + 人工抽查缓解；残余风险是抽查覆盖不住的长尾。（代价：同 A1；不确定度：中）（验证：通过——验收 round 1 的人工抽查实证有效：18 处证据引用抓出 1 处错引并修正；长尾保留为残余风险，见下）
- A3 超大仓库/monorepo 的单轮扫描预算未知：分轮机制兜底，轮次切分依据留 spec。（代价：单轮超时或截断；不确定度：低）（验证：本轮未触发——分轮协议已实装并在 PyJWT 验收夹具按 round 1 分轮落盘、未覆盖区显式标注；超大仓库压力未测）
- 残余风险：长期时效——重扫由用户手动触发（按设计），重扫前漂移知识持续存续（影响：过期知识误导开发；不阻塞——扫描基线 commit 显性化可判新鲜度）；抽查长尾——未被抽查命中的错误断言可能留存（影响：低；不阻塞——低置信标注与开放问题机制收窄面）；落盘机械规则缺口——GLOSSARY 项目术语章判存/追加位置与证据行号现场核对未成文（影响：执行歧义；不阻塞——验收 round 1 两次踩坑均被抓出修正）（折回自验收报告 0001）
- 下一轮建议：setup-reconstruct 参考文档补"GLOSSARY 项目术语章判存与追加位置"机械规则（按 `^## 项目术语` 章头与占位行定位，占位行存在时插于其后，禁宽关键词判存）与"证据行号以现场打印为准、不凭记忆"一条（折回自验收报告 0001）

## 范围与非目标

- 非目标 1：不迁移外来技能套件（matt / superpower）的产物——那是另一张 need（套件迁移，本次对话后续立项）的范围（来源：用户本次对话将两想法分列）。
- 非目标 2：不改动正向流程技能（dev-clarify / dev-spec / dev-implement 等）的既有行为（来源：用户拍板范围内未涉及）。
- 非目标 3：check.sh 除逆向状态 `reconstructed` 的状态机表扩展（拍板 D1）外，既有校验零改动（来源：定位拍板 D4）。
- 非目标 4：不进 sdlc next-mode 自动串联链，路由表不加行，用户手动触发（来源：定位拍板 D4，仿 dev-docs 定位）。
