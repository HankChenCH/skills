# 存量项目套件迁移：matt / superpower 产物与规则接入本套件

## 背景与业务目标

现状：已在用其他技能套件的存量项目，其工作流规则与产物散落在外来体系里。查证（2026-10-29，本机 `~/.zcode/skills/`）：matt Pocock 套件的生命周期产物主要发布在 issue tracker——to-spec 原文"publish it to the project issue tracker"并打 `ready-for-agent` 标签——本地仓库几乎不留过程档；superpower 套件本地未安装，结构未知。这类项目接入本套件时两套规则并存会互相干扰：蓝图 §10.3 已识别"Matt 生命周期技能允许模型自动调用，可能绕开本套件门禁链"。

来源：用户 2026-10-29 原话——"使用了 matt、superpower 这些技能套件的存量项目，需要迁移到本技能套件下的规范中"。

业务目标（成功标准，2026-10-29 用户确认）：

- S1 本套件门禁在该仓库生效（check.sh / hooks 接入）。
- S2 外来套件的生命周期类技能不再被自动触发（移除或归档）。
- S3 每一件外来产物有明确归宿（映射 / 归档 / 显式弃置），且有一张对账清单可查。

## 干系人与用户

- 仓库主人（主 Actor）：发起迁移、审查对账清单与翻译产物、验收 S1–S3。
- agent 会话（执行 Actor）：识别外来痕迹、执行翻译映射、处置 tracker issue 与旧技能文件、落对账清单。
- 未来 agent 会话（受益 Actor）：在已迁移仓库中只按本套件规则工作，不被外来技能分流。
- 既有件（不变或轻改干系人）：setup-workspace（未接入仓库的接入前置，拟与 need 0006 FR-6 同两态语义）、check.sh / hooks（门禁承载）、trackers 投影适配器（处置外来 issue 的操作面）、dev-research（superpower 结构调研）、蓝图 §10.3（共存判据先例）。

## 系统能力需求

- FR-1 套件识别：识别 matt 与 superpower 两个点名套件的安装痕迹（技能目录、规则文件、产物落点）（来源：用户拍板"两个点名套件"；通用识别器不做，见非目标 1）。
- FR-2 全量翻译映射：外来产物逐件翻译成本套件产物形态，不以原样归档替代翻译（来源：用户拍板"a"）；产物对产物、状态对状态的映射表在 spec 定。分态规则（拍板 D2）：未完成的外来工作（如 matt 仍开着的 ticket issue）翻译后进正向流程现态（如 `ticket.ready`），照常走本套件流程；已完成的历史产物翻译为沉淀形态，落盘即置 `status: reconstructed`（复用 need 0006 新增状态——拍板 D1：行为与逆向产物一致，check.sh 状态机只扩那一处；"迁移 vs 逆向"来源区分由产物正文来源行与对账清单承载）。
- FR-3 tracker issue 处置：外来套件发布在 tracker 的 issue（matt 套件主产物场）迁移后关闭并注明"已迁移"；对账清单记录 issue 编号与新产物路径（来源：用户拍板"注明已迁移"）。
- FR-4 生命周期技能处置：外来套件生命周期类技能不再被自动触发——移除或归档；处置判据沿用蓝图 §10.3（生命周期类归档/移除，写作类保留）（来源：用户拍板 S2；判据确认于 2026-10-29）。
- FR-5 门禁接入：迁移完成时本套件门禁生效；未接入仓库按 setup-workspace 全流程接入，已接入仓库仅补迁移产物（与 need 0006 FR-6 两态一致，2026-10-29 确认）。
- FR-6 对账清单：迁移产出一张对账清单——每件外来产物一行：来源（本地路径 / issue 编号）→ 归宿（新产物路径 / 归档位置 / 显式弃置及理由）；产物形态待 spec 定（来源：成功标准 S3）。
- FR-7 可选串联逆向：迁移完成后可选串联 need 0006 的知识逆向扫描补齐沉淀，由用户自选、不强制（来源：用户拍板"可选串联"）。
- FR-8 调研前置：superpower 套件结构在迁移实现前先出调研报告（dev-research 纪律：带来源引用与检索日期）；调研不可行时该套件支持范围回用户决策（来源：2026-10-29 确认；承接假设 A1）。

## 场景

主成功场景：

- Given 一个已使用 matt 套件的存量仓库（技能装在技能目录，spec / ticket 在 issue tracker）。
- When 用户运行迁移技能（暂名 setup-migrate）。
- Then 识别全部外来痕迹 → 产物逐件翻译映射 → tracker issue 关闭并注明已迁移 → 生命周期技能移除或归档 → 门禁接入（未接入仓库两态合一，已接入仅补产物）→ 对账清单落盘（S1–S3 可核销）。

异常流：

- E1 识别出非点名套件的痕迹：不在本技能范围内，对账清单标注"未处理"并提示用户（FR-1 范围边界）。
- E2 翻译中某件产物语义无法对应本套件形态：对账清单标"显式弃置"并给理由，不硬造产物（S3）。
- E3 外来 issue 关闭失败（凭据/权限）：对账清单标注失败明细，不阻断本地翻译与门禁接入，事后人工补处置（FR-3 边界）。

## 假设与风险

- A1 superpower 结构未知（本地未安装）：以 FR-8 调研前置缓解，或由用户提供样本项目；调研不可行时该套件支持范围回用户决策。（代价：superpower 支持不完整或延期；不确定度：中高）——**验证通过（spec 0010 验收 0001，2026-10-30）**：调研报告先行落盘（docs/research/0002，v7.0.1 快照带来源），识别与处置清单按报告落地并由断言锁定；"不可行回用户"分支未触发。真实 superpower 仓库迁移未实测（残余 R1）。
- A2 翻译映射失真：外来产物语义与本套件八类不完全对齐（如 matt 的已完成 ticket 属外来过程档），错译会污染正向流程状态机。（代价：错误状态产物干扰 frontier / next-mode；不确定度：中；见开放问题 D1/D2）——**验证通过（验收 0001，2026-10-30）**：分态规则全程走既有状态值，frontier 无污染；E2 显式弃置出口在集成夹具真实触发（已失效 ADR 不硬落 accepted）。
- A3 tracker 操作是外部副作用：关闭外来 issue 不可由门禁回滚，误关需人工重开；以对账清单留痕缓解。（代价：低，可恢复；不确定度：低）——**本轮部分触发（验收 0001，2026-10-30）**：本地 tracker 关闭归位实证无外部副作用；平台真实关闭未实测，E3 失败留痕经 stub 注入验证（残余 R2）。
