# 测试套件框架迁移调研

## 背景与业务目标

本仓库的 SDLC 门禁引擎（`.sdlc/check.sh`，853 行）由 4415 行的 bash 测试套件
（`skills/setup-workspace/tests/run-tests.sh`，528 条用例）守护。2026-11-10 的评估
（结论经用户拍板锁定为前提）认定：运行时（check.sh、trackers、l4-guard）维持 bash；
最值得迁出 bash 的是测试套件——它占全部脚本代码量的 64%，且已留下 bash 3.2
引号坑的实证注释（`run-tests.sh:82-83`、`run-tests.sh:3694`）。

但「迁到哪个框架、成本多少、有什么风险」未经系统调研，上轮结论只是单方判断。
本 need 的业务目标：产出一份够拍板的调研报告，让「迁/不迁、迁到哪」的决策有据可依，
无需再补调研即可直接开 spec。

不做的代价：迁移决策继续悬在会话记忆里，下次提起仍要从头评估；或仓促迁移选错框架，
528 条用例返工。

## 干系人与用户

- **仓库维护者（用户本人）**：读调研报告，作出「迁/不迁、迁到哪」的拍板。成功标准：
  报告含选型推荐、成本估算、风险清单三要素，读完即可拍板，不需要再查任何资料。
- **后续 spec 阶段（dev-spec）**：以报告为唯一输入起草迁移 spec。成功标准：报告的
  推荐方案 + 成本概要 + 风险清单足以支撑 spec 的实现决策与测试决策，无需回头补调研。

## 系统能力需求

- **FR-1 调研报告能回答框架选型**：对至少四条路线横向对比并给出单一推荐与否决理由——
  ① pytest（Python）；② node/ts 系测试框架（vitest 或同类）；③ bats-core（bash 测试
  框架，原地升级路线）；④ 保持 bash 现状基线。对比维度至少含：安装形态与离线性、
  以子进程驱动 bash 脚本并断言其退出码/输出的能力、失败诊断质量（差异与上下文输出）、
  macOS（bash 3.2 宿主）兼容性、维护成本。若推荐为「保持现状」，须给出否决迁移的
  具体依据（收益不抵成本的量化对照），同样构成可拍板结论。
- **FR-2 调研报告能给出迁移成本估算**：对 528 条用例按类别（`t` / `tn` / `oseq` /
  夹具助手 `new_repo`/`wfile`/`setfm`/`fake_cmd`，见 run-tests.sh:21-105）给出分组
  数量与各组单用例迁移成本估算，汇总为总量级估算；附分批迁移策略概要。
- **FR-3 调研报告能给出风险清单**：至少覆盖三类——迁移期间门禁行为回归的风险与
  防护手段；新旧套件并行/切换/回退策略；选错框架的退出成本。
- **FR-4 推荐方案能守住用例等价红线**：报告须为推荐方案给出 528 条用例断言面等价的
  验证策略（如迁移期新旧套件双跑对照、等价验证完成前旧套件不删）。
- **FR-5 报告以标准产物形态交付**：落盘 docs/research/（`check.sh claim research`
  取号），通过 `check.sh validate` 与 `check.sh publish`。

## 场景

- **主流程（拍板就绪）**：Given 前提已锁定（运行时维持 bash）且报告产出，When 用户
  读报告三要素（FR-1 选型推荐、FR-2 成本估算、FR-3 风险清单），Then 用户可直接宣布
  「迁/不迁、迁到哪」，下游 dev-spec 开迁移 spec 时无需任何补充调研。
- **异常流（结论为保持现状）**：Given FR-1 对比后 bash 基线胜出，When 报告给出量化
  否决依据，Then 「不迁」成为合法拍板结果，评估闭环，不产生迁移 spec。
- **异常流（候选集不覆盖更优解）**：Given 调研中发现候选集外的重要路线，When 该路线
  一手资料可得，Then 报告可扩充候选集并留痕（扩充记录写进报告备注），FR-1 的对比
  维度不变。

## 假设与风险

- **A2（用户定稿确认 2026-11-10）**：「接受完整工具链」指安装期可引入 venv / package.json /
  锁文件 / CI 配置；「离线可跑」指日常执行测试不依赖网络（依赖装好后离线可重复）。
  两约束并存：工具链可以重，跑起来必须离线稳定。——**验证通过**（推荐路线
  submodule 钉 commit 满足双约束；附带发现 `-j` 并行需 GNU parallel/rush，属
  安装期工具链）。
- **R1（来源质量）**：框架对比依赖网络检索，二手结论有污染风险 → 只采一手官方文档，
  二手来源标注出处与检索日期。——**验证通过**（29 URL 全官方域名、内容抽查一致）。
- **R2（等价判定成本）**：528 条用例的「断言面等价」本身难以机械判定 → FR-1 的
  对比维度必须包含等价验证策略，不能只比断言语法。——**验证通过**（报告 §5 三
  要素在案；「按名对号查不出断言削弱」的策略盲区折回下方残余风险）。

**折回的残余风险（验收报告 20261110-9631，全部不阻塞拍板）**：① node:test 否决
理由一条失实（`assert.match` 实测会显示实际输出），推荐不变；② bash 3.2 多字节
展开坑迁移后仍在，bats 不开 `set -u` 时由报错变静默错值——迁移 spec 须承接显式
`set -u`/lint；③ `-j` 依赖 GNU parallel/rush 须入迁移工具链清单；④ 成本上界或

minor）；⑦ 推荐路线 bats 未本机实跑（批 1 试点即实测点）；⑧ 等价对号须细化到
断言参数或双跑注故障；⑨ 逐条索引未入报告（批 1 生成）；⑩ 最终「够拍板」以用户
通读确认为准。

**下一轮建议**：迁移 spec（若开轮）须承接残余风险 ②③⑦⑧（`set -u` 防护、
parallel 工具链、断言参数级对号、批 1 兼宿主实测）；报告瑕疵级文字修订随迁移
spec 顺带。
