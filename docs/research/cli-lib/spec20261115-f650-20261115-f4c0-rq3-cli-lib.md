# RQ3 CLI 库选型调研：五维度对比 + 否决线 + 选型推荐 + 迁移方案（spec 20261115-f650）

## 1. 执行摘要（结论速览）

**推荐 commander 15**（15.1.0，2026-11-07 发布）。逐条要点（一事实一数字）：

- 体积：零运行时依赖；闭包下载 676 KB（否决线 1.2 MB 的 56%）；安装树 236 KiB（§5.1）。
- 冷启动：npx 冷启动中位 2.30 s，低于现行包 3.60 s——现行包冷启动大头来自 @clack/prompts（+2.31 s / +2.3 MB），不是解析层（§5.2）。
- 运行成本：warm 启动全体 ~1.2 s 地板、`import` ≤ 30 ms——解析库"每次运行"成本可忽略（§5.2 读法 3）。
- 原生度：纯 ESM + 自带 typings，与本包 `"type": "module"` 形态对齐（§4）。
- help：`helpInformation()` 覆盖是官方文档支持的定制面；16 案例矩阵逐字节等价（§6.2/§6.3）。
- 维护：open 7 / closed 1165（关闭率 99.4%），2026-11-07 发布 15.1.0（§7）；对应成本 = major 年更节奏（14.0.0 → 15.0.0 相隔 12 个月）。
- **否决**（异常流 D，§8）：yargs 18——闭包下载 2872 KB（否决线的 239%）、安装树 924 KiB、冷启动中位 4.23 s 全场最高。
- **警示**（§8）：clipanion 4.0.0-rc.4——闭包下载 996 KB（83% 线）、安装树 592 KiB 超警示线、最近发布距检索日约 26 个月。
- **迁移核心**（FR-8/FR-5）：库只负责 token 消耗与 help 拦截，顺序敏感状态机保留在我侧（互斥/值必需按 argv 顺序首个命中即抛；配对检查延后到解析结束——对齐 src/cli-args.js 实际语义），报错文案零改动。探针实证：五库各按此模式接入后 16 案例矩阵 stdout/stderr/退出码三通道逐字节一致，commander 另通过多错误先后序 2 案例（§6.3）。
- 证据位置：探针命令、接入模式与关键输出摘录在 §11；矩阵与探针原始输出、探针源脚本已入库 `docs/research/cli-lib/evidence/`。

## 2. 范围与方法

### 2.1 候选集

commander / yargs / cac / citty / clipanion（工单指定五候选）；另设两条参照线：**零依赖基线**（无解析库 fixture，测 npx 地板）与**现行包 fixture**（真实 @hankchen/infra 包形态，仅 @clack/prompts 依赖，测现行冷启动基线）。Node 内建 `util.parseArgs` 不作为候选（无 help 生成、无子命令模型，不满足 RQ3 动机 = 为子命令扩展引入库），作为"不引入"选项记录在 §9。

### 2.2 实测环境与口径（本机一手）

- 环境：macOS 26.6（25G72）、Apple M5（arm64）、node v24.22.1、npm/npx 11.19.1、zsh。
- 隔离：实验全部在 `/tmp/r3-exp/` 下空目录（fixtures / caches / runs 分目录）；仓库目录零安装/打包操作；现行包形态以 `package.json + bin/ + src/ + skills/ + plugins/` 拷贝至 /tmp 后 `npm pack` 取得。
- 冷启动口径：`env npm_config_cache=<全新空目录> npx --yes file:<包tgz>`——npm 缓存与 npx 安装缓存双冷（首装下载 + 解压 + 运行）；计时 `/usr/bin/time -p`（取 real）；每候选 3 个独立冷样本，取中位数，离群值如实标注。
- 下载量口径：冷启动后 `du -sk` 该全新缓存目录（压缩态字节）；安装树口径：`du -sk node_modules`（解压态）。**样本口径：后两样本一致；首样本含 npx 首装元数据开销（约 12 KB + 每包数 KB），取第 2/3 样本为稳定口径。**
- 探针口径：以真实 `parseArgs`/`renderHelp`（src/cli-args.js 的 /tmp 副本）为参照驱动，复刻 bin/infra.js 旗标路径出口（`✗ ${err.message}` + 提示行 + 退出码），16 案例 × 5 库 stdout/stderr/退出码三通道逐字节 diff。
- 单位口径（全文脚注）：`du -sk` 以 1K 块计；本文 KB/MB/KiB 为 1024 进位的等价标注（KB≡KiB、MB≡MiB），不再逐一换算。

### 2.3 版本与来源纪律

候选版本 = npm dist-tag latest（检索 2026-11-15）；特性结论带官方仓库/文档链接（§12），检索日期 2026-11-15；体积/冷启动全部为本机实测（§11 附命令与原始输出）。npm registry 元数据（版本/发布时间/engines）与 GitHub API 查询均为检索当日一手查询。

## 4. 维度一：ESM/TS 原生支持

本包为 `"type": "module"` + 零构建直跑（ADR 20261115-f143），engines `node >= 24.9.0`。五候选 engines 全部兼容：commander `>=22.12.0`；yargs `^20.19.0 || ^22.12.0 || >=23`；cac `>=20.19.0`；citty/clipanion 未声明。

### 5.3 测量注意（如实记录）

- 冷启动单样本受网络波动影响大（commander 首样本 4.23 s vs 后两样本 2.25/2.30 s），故取中位数并列出全部样本（§11.2）。
- 下载量首样本普遍偏大 12–88 KB：npx 首装要额外拉取 registry 元数据（约 12 KB + 每包数 KB），后两样本一致（§2.2 样本口径）。
- 排查留痕：两轮批量补样脚本因 zsh 不对未引用变量分词，`npx` 收到目录路径静默空转（0.12–0.15 s / 缓存 4 KB），定位为脚本缺陷后重跑修正；同因曾致探针矩阵首轮失真（`${=var}` 修正）。有效数据以 §5.1/§5.2 表为准。

## 6. 维度三 + 四：模型扩展性与 help 等价复刻（探针实证）

### 6.1 子命令/旗标模型扩展性（维度三）

现行 CLI 是单命令五旗标；RQ3 动机是给"两层菜单 → 子命令化"预留扩展面。逐候选（模型 / 扩展点 / 风险）：

**commander**
- 模型：`.command()` / `.addCommand()`、嵌套子命令、`isDefault` 默认命令、别名、独立可执行子命令。
- 扩展点：生命周期钩子 `preAction/postAction/preSubcommand`（官方 README；五候选中唯一带钩子模型）；help 分组。社区规模最大（28.5k stars，§7）。
- 风险：major 年更（§7）；15 系内已有破坏性改动先例（`exitProcess` 移除，§10.4）。

**yargs**
- 模型：`.command()` + 位置参数 DSL（`<required>` `[optional]` `[variadic...]`）。
- 扩展点：middleware、`.commandDir()`（官方 docs）。
- 风险：18.x ESM 迁移后周边生态成熟度需逐项复核；体积超否决线（§8）。

**cac**
- 模型：git 风格 `cli.command('lint [...files]', 'desc')`、点嵌套选项（`--namespace.option`）、命令别名、默认命令。
- 扩展点：命令级未知选项校验（README：「Any unknown options will be reported as an error」）——注意该特性是**命令级**的；全局选项形态下不报未知旗标（探针一手确认），若迁移把旗标挂进 default command 则 cac 也能拥有未知检测。
- 风险：help 无法整替（§6.2）；issue 关闭率约 58%（§7）。

**citty**
- 模型：`defineCommand({ subCommands })` 递归嵌套；API 面小（defineCommand / subCommands 两个原语）。
- 扩展点：懒加载子命令（`sub: () => import(...)`）、meta.alias / meta.hidden。
- 风险：0.2.x 未到 1.0（breaking 风险由版本号承载）；issue 关闭率约 36%（§7）。

**clipanion**
- 模型：class 命令 + `static paths` 路由 + 嵌套命令。
- 扩展点：选项代理/取反/连写（batches）、Typanion 运行时校验、内建 version/help 命令。
- 风险：4.0 停留 rc 且维护停滞（§7）；`-h` 短旗标 schema 歧义（§6.2）。

### 6.2 help 生成能力：现行 --help 逐字复刻可行性（维度四）

现行 `--help` 是一段固定文本（src/cli-args.js `renderHelp()`）。等价复刻定义 = `-h`/`--help` 触发时逐字节输出该文本、退出码 0、不掺库自带格式。

| 候选 | 库自带 help | 逐字整替路径 | 探针结果 |
|---|---|---|---|
| commander | 内置渲染（configureHelp/addHelpText/分组） | 覆盖实例 `helpInformation()`；`-h` 交库拦截（`commander.helpDisplayed` → exit 0） | **16/16 字节一致** |
| yargs | usage + 选项表自动排版 | `.help(false)` 关闭内置；`h/help` 声明为普通布尔；状态机自派发 | **16/16 字节一致** |
| cac | 自动 help；`cli.help(callback)` 仅后处理 section（官方 README 无整替口） | 不调 `cli.help()`；解析后检查 `options.h/help` 自派发 | **16/16 字节一致** |
| citty | meta 自动生成；`--help/-h` 自动处理（官方 README），无整替文档 | 不用 `runCommand`（内建 help 不可覆盖），用导出 `parseArgs` + 自派发（绕开库 help/解析层） | **16/16 字节一致** |
| clipanion | 自动 help 页 + 内建 help 命令；`-h` 短旗标 4-rc schema 触发 AmbiguousSyntaxError（探针一手复现） | help 状态机自派发；`cli.process()` 仅作未知旗标/位置参数检测（UnknownSyntaxError 可捕获重映射） | **16/16 字节一致** |

结论：五库都能逐字复刻；cac/citty/clipanion 的"整替"实为绕开库 help 层自派发；只有 commander 与 yargs 在保留库 help 拦截的同时完成整替——commander 的 `helpInformation` 覆盖是文档支持的公开接口（其余多为绕行），且探针额外通过多错误先后序 2 案例，故 round 2 首选该路径。

### 6.3 迁移等价探针（FR-5 防线的实证基础）

方法：参照驱动复刻 bin/infra.js 旗标路径出口（parse → catch 打 `✗ ${err.message}` + 提示行 exit 1；help 打 `renderHelp()` exit 0），16 案例矩阵覆盖：`--help`、`-h`、互斥两向、未知旗标、位置参数、值缺失三态、配对缺失、可重复取并集、逗号分隔、`--all`、合法插件对、无 profile 插件（parse 层返回 profile:null）、零旗标。每案例比 stdout + stderr + 退出码三通道。

**结果：五库探针全部 16/16 与现行 CLI 字节一致**；commander 探针另通过 2 个多错误先后序案例（`--all --skills dev-spec --foo` 互斥先行、`--foo --all --skills dev-spec` 未知旗标先行）。矩阵原始输出与探针源脚本已入库 `docs/research/cli-lib/evidence/`（ref-driver.js / probe-ref-matrix.txt / probe-<lib>.txt / probe-ordering-extra.txt / probe-*.js / runmatrix.sh）。

各库达成等价所需的接入模式（round 2 工程蓝图，按"语义状态机保留"分层）：

- **commander**：`helpInformation()` 覆盖 + `exitOverride()` + `configureOutput({ writeErr: () => {} })`（抑制库自带 `error: ...` 行）+ `showSuggestionAfterError(false)`（关 "did you mean"）+ `allowUnknownOption()` / `allowExcessArguments()`（未知旗标与位置参数的检测顺序让给状态机）+ 错误码通道（`commander.helpDisplayed` → exit 0）。库保留职责：token 消耗、`-h/--help` 拦截、值类型化。
- **yargs**：`.help(false)` + `.strict()` + fail 处理器消息重映射 + `h/help` 声明为普通布尔；逗号分隔由我们的 coercion 完成（yargs 类型化消耗 `--skills a,b` 得 `['a,b']` 单元素，需自行 split）。
- **cac**：无全局未知旗标校验、无 strict → 未知/位置参数全部由状态机预扫描承担；库只做类型化值消耗与（可选的）help 后处理。
- **citty**：导出 `parseArgs` 无 schema 值消耗、无 strict，`runCommand` 内建 help 不可逐字覆盖 → 库近乎只剩 token 化底座。
- **clipanion**：`cli.process()` 抛 `UnknownSyntaxError`（可捕获、消息含未知旗标/多余位置参数原文）做检测通道；`-h` 短旗标 4-rc schema 歧义（AmbiguousSyntaxError）→ help 自派发。

诚实结论：等价的关键不是"选哪个库"，而是"语义状态机必须保留在我们这侧"。五库在此模式下等价；差异在库还能承担多少（未知检测：commander/yargs/clipanion 有、cac/citty 无；值消耗：commander/yargs/cac/clipanion 有、citty 无 schema 时无；help 拦截保留在库侧：仅 commander/yargs 可行）。

## 9. 结论：选型推荐（FR-8）

**推荐 commander 15。** 五条理由，每条 = 结论句 + 数据句：

1. 体积/冷启动全绿。——闭包下载 676 KB（否决线 56%）、安装树 236 KiB、冷启动中位 2.30 s 低于现行包 3.60 s；warm 与地板同值、import ≤ 30 ms（§5）。引入后的可感知成本只有首次 npx 约 +1 s，其后无差异。
2. ESM/TS 原生度第一档。——纯 ESM 对齐本包形态；自带 typings + 官方 extra-typings 侧包可选强化（§4），匹配全仓 TS 直跑方向。
3. 子命令扩展面最大。——`.command()` 模型 + 生命周期钩子（五候选中唯一带钩子模型，官方 README）；「成熟」为判断性结论，其佐证是钩子能力、文档面与社区规模（28.5k stars，§7），非本报告实测项。
4. help 逐字整替走官方口子。——`helpInformation()` 覆盖是文档支持的公开定制接口，五库中唯一"整替 + 库继续拦截 help 时机"两全（§6.2）；探针 16 案例 + 多错误先后序 2 案例全绿（§6.3）。
5. 维护面五库最健康。——关闭率 99.4%（7/1165）、2026-11-07 发布 15.1.0（§7）。如实记入的成本：major 年更节奏（14→15 相隔 12 个月），round 2 引入即锁定年度升版预算。

**备选**：cac 7——最轻量线（56 KiB / 484 KB / 2.32 s，纯 ESM + TS）；代价 = help 无法整替需自派发、全局形态无未知旗标检测、关闭率约 58%、社区面小（§7）。citty——模型干净但 0.2.x 未到 1.0，关闭率约 36%（§7）。

**不推荐**：yargs（否决，§8.2 三重数据）；clipanion（警示：近否决线 + rc 停滞，除非 design 接受其体量与维护风险）。

**"不引入"选项记录在案**：Node 内建 `util.parseArgs`（零字节零冷启动增量）无 help 生成与子命令模型——若 round 2 判断两层菜单子命令化不再需要，维持手写 cli-args.js（spec 已锁定本轮不替换）与引库相比是合法保守解；引库的前提正是子命令扩展诉求。

## 10. 迁移方案（FR-8；FR-5 防线 = 报错文案逐字不变）

以推荐库 commander 15 为蓝本。目标形态：`src/cli-args.js` 对外接口（`parseArgs(argv)` / `renderHelp()`）不变，内部由"手写循环"换为"commander 解析 + 语义状态机校验层"，bin/infra.js 零改动。

### 10.1 现行旗标语义映射表

| 现行（cli-args.js） | 语义 | commander 15 表达 | 等价要点 |
|---|---|---|---|
| `--all` | mode='all'，出现即生效 | `program.option('--all', '安装技能类型全部条目（免交互）')` | 布尔旗标；互斥判定**不**用 `.conflicts()`（库文案不可控），保留在状态机层 |
| `--skills <名[,名...]>` | 可重复、逗号分隔、并集保序 | `program.option('--skills [names]', …, collectFn)`；collectFn 内 split+trim+filter+按首现去重 | 值消耗交库；并集语义在 collectFn 复刻 |
| `--plugins <名[,名...]>` | 同上；与 --profile 配对 | `program.option('--plugins [names]', …, collectFn)` | 同上；registry 包名不做形态校验（与现行一致） |
| `--profile <名>` | 只与 --plugins 配对，顺序无关 | `program.option('--profile [name]', …)`（required=false） | 配对校验保留在我们层（解析后判定），不产生库文案 |
| `-h` / `--help` | 即时派发 help，优先于其后错误 | `helpOption('-h, --help', '显示本帮助')` + `helpInformation()` 覆盖 | 逐字输出 + `commander.helpDisplayed` → exit 0 |
| 未知 `--xxx` | 未知旗标文案 | `allowUnknownOption()` 关库检测；状态机 default 分支检测后抛我们的文案 | 检测顺序让给状态机 = 与 cli-args 触发顺序一致（探针实证） |
| 位置参数 | 位置参数文案 | `allowExcessArguments()` 关库检测；状态机 default 分支检测 | 同上 |
| 旗标清单文案 | `FLAGS.join('、')` | 常量照搬 | 文案零改动 |

### 10.2 互斥校验等价方案

不使用库的 `.conflicts()` / `.check()`（其错误文案与触发时机不可控，FR-5 会破）。方案 = 保留 cli-args.js 的顺序敏感状态机为后置校验层：commander 解析成功后按 argv 顺序走状态机（--all/--skills/--plugins/--profile/未知/位置参数/值缺失），在与现行完全相同的触发点抛逐字相同的 `Error`；bin/infra.js 的 catch 出口不动。探针已证明该层复刻 cli-args 全部错误触发顺序（16 案例矩阵 + 2 多错误先后序案例）。保留状态机还天然保住两条现行边角语义：值缺失判定"旗标后无 token 或空串"（不看是否以 `-` 开头）；配对检查延后到解析结束（`--profile` 与 `--plugins` 顺序无关）。

### 10.3 错误口径等价方案（FR-5 防线：文案逐字清单 + 出口通道映射）

逐字文案清单（迁移后必须一字不差，含全角标点与空格）：

1. `--all 与 --skills 互斥：全装与按条目指定只能选一`
2. `--plugins/--profile 与 --all/--skills 互斥：插件安装与技能安装只能选一`
3. `--skills 需要至少一个技能名（如 --skills dev-spec,dev-plan）`
4. `--plugins 需要至少一个名字（如 --plugins a,b）`
5. `--profile 需要一个 profile 名（如 --profile dev）`
6. `--profile 需与 --plugins 配对使用（插件安装指定目标 dsh profile）`
7. `未知旗标 ${arg}；可用旗标：${FLAGS.join('、')}（--help 查看示例）`
8. `不接受位置参数「${arg}」：本命令只认旗标，条目请用 --skills/--plugins 指定（--help 查看示例）`

外加 bin 层两行（不在本票改动面，列出为完整性）：`✗ ${err.message}` 前缀行、`  运行 npx @hankchen/infra --help 查看全部旗标与示例。` 提示行；`--help` 正常路径输出 `renderHelp()` 全文（§10.1 整替保证）。

commander 出口通道映射表：

| commander 通道 | 处置 |
|---|---|
| `CommanderError code=commander.helpDisplayed`（-h/--help 拦截完成） | 直接 `exit 0`（helpInformation 覆盖已输出我们的文本） |
| 库自带 stderr `error: unknown option '--x'` 行 | `configureOutput({ writeErr: () => {} })` 静音（库检测已让位给状态机，静音为保险） |
| "did you mean" 建议行 | `showSuggestionAfterError(false)` 关闭 |
| `commander.excessArguments` | 已由 `allowExcessArguments()` 关闭，位置参数交状态机（保触发顺序） |
| 未知选项 | 已由 `allowUnknownOption()` 关闭，交状态机 |
| 选项值消耗（含逗号串） | collectFn 内 split+trim+filter+按首现去重（等价 cli-args mergeValues + Set） |
| CommanderError 其他码 | 兜底 `fail(未预期的解析错误：…)`（探针哨兵，矩阵未触发） |

等价性验收方法（round 2 直接复用）：把 §6.3 探针矩阵 + 2 多错误案例 + 既有 e2e（install.test.js 旗标用例）作为迁移回归集，断言三通道字节一致；既有全量测试（spec FR-5：--help 文本、互斥报错、版本拦截文案逐字不变）为最终防线。

### 10.4 残余边界与风险（如实列出，交 round 2/design 消化）

1. `--skills -h` 类"值以 `-` 开头"。
   - 现象：cli-args 取 `-h` 为 --skills 的值（mergeValues 收 `['-h']`）；commander 类型化消耗可能把 `-h` 认作旗标。
   - 影响：解析结果分歧（skills 取值 vs help 派发）；探针矩阵未含此案例。
   - 建议动作：迁移时在状态机层保持"值缺失判空"语义并实测该案例；round 2 回归集纳入。
2. 裸 `--` 分隔符。
   - 现象：cli-args 将 `--` 报"未知旗标 --"；commander 将其作为选项结束符吞掉（不进 argv）。
   - 影响：该输入行为不一致；无既有 e2e 覆盖。
   - 建议动作：若要保逐字行为，parse 前预扫描 `--`；是否值得保真交 design 拍板。
3. 未知旗标与语义错误共存时的先后序。
   - 现象：探针覆盖 2 例（互斥先行 / 未知旗标先行）均一致；更多组合（值缺失 + 未知旗标等）未排。
   - 影响：状态机方案下顺序由我们保证，理论无分歧；缺实证覆盖。
   - 建议动作：round 2 回归集全排组合案例。
4. commander major 年更。
   - 现象：14→15 相隔 12 个月；15 系内已有破坏性改动先例（`exitProcess` 移除 → `exitOverride`，本票探针一手踩到）。
   - 影响：引入即锁定年度升版预算。
   - 建议动作：round 2 引入时 lockfile 钉 minor，年度升版写进依赖维护清单。
5. 库的 help 拦截时机。
   - 现象：`-h`"即时派发优先于其后错误"由 commander helpDisplayed 通道保证（矩阵 `--help`/`-h` 两例验证）。
   - 影响：若 round 2 调整 helpOption 配置，该语义可能漂移。
   - 建议动作：调整配置后必须重跑探针矩阵。
