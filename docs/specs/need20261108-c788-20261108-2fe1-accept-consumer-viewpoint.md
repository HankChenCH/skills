# dev-accept 使用方视角实操验收 + dev-execute 收口自动串联

## 问题陈述

dev-accept 的验收是**实现者视角跑脚本**：在集成后代码上逐条执行 spec 集成级场景 + `check.sh all`，证据是命令输出；操作类场景"脚本跑通"不等于"人能操作"。用户观测（2026-11-08）：最近几次交付验收 passed 后仍返工 1–2 次，问题类型是**行为不符合预期——脚本跑通，但人在操作上不对**。同时验收执行与实现共享会话上下文（连带实现上下文跑验收脚本），"实现者觉得做完了"污染"使用方觉得能用"。

dev-execute 收口止于**指路手动 /dev-accept**（spec 0006 拍板"收口不自动调 dev-accept，用例圈定圈掉"）。无人值守运行停在人不在场的验收门前——用户原话："没有证据证明确实实现完了，还要人去看"；每次人工验收 = 手动跑 accept + 自己上手点一遍，耗时 ≥30 分钟。

## 方案

**dev-accept：从"跑脚本"改造为"使用方视角实操验收"。** 验收执行派发**恰一个隔离验收代理**（评审轴清单制同款结构：轴名 + 判断依据材料清单 + 产出节），只装载使用方视角材料——need 全文、spec 验收场景、design 述标与原型、集成后交付物本身；禁止装载实现过程材料（工单 Progress、实现交接、实现会话上下文）。按交付物类型选介质**真实操作**（Web → 浏览器实操、CLI → 终端调用、API/库 → 真实调用、文档 → 打开阅读），证据 = 实操记录。发现按**硬伤 / 瑕疵**两级分级：硬伤（功能缺失 / 操作行为不符预期 / 比原型差）阻塞 rejected，瑕疵（不影响完成任务的样式、文案、措辞）留痕不阻塞。关联原型按"基本完成原型场景功能为过、缺失或比原型差为挂、更优为过"核销。

**dev-execute：收口从"指路手动"改为"自动串联 dev-accept"。** 清理完成后自动启动验收：有人值守按 dev-accept 现行交互走，无人值守全自动到报告；passed/rejected 判定无人值守下由 AI 作出，**need 置 fulfilled 一律停点留人**（沉默不算接受残余风险，现行纪律不变）。

本 spec 显式推翻 spec 0006"收口不自动调 dev-accept"拍板；理由 = need 20261108-c788 业务目标四条（passed 无硬伤、报告以硬伤为主、原型可优不可差、人工投入降到只做最终确认）。

## 用户故事

- 作为 need 提出人，我想让验收以我的任务场景**实际操作交付物**取证据，以便"脚本跑通但人用不了"的交付在验收就被拦下，不再 passed 后返工。
- 作为无人值守发起人，我想让运行合并后**自动完成验收并产出自证报告**，以便回来时看到的是结论与实操证据，而不是停在验收门前。
- 作为拍板人，我想让 need 置 fulfilled **始终由我确认**，以便残余风险的接受永远出于我的显式拍板。
- 作为有原型关联的交付方，我想让验收逐原型场景实操对照、**可优不可差**，以便原型承诺的功能不缩水。
- 作为无浏览器原语宿主的用户，我想在降级验收时得到**如实声明**，以便知道该份报告的证据弱点并决定是否人工补验。
- 作为验收执行体，我想只装载使用方视角材料，以便不被实现叙事污染判断。

## 实现决策

- **验收轴清单制（评审轴同构）**：验收轴 = 一条独立验收纪律单元，三要素 = 轴名 + 判断依据材料清单 + 产出节。当前清单恰一条：**使用方走查轴**——判断依据：need 全文、spec「验收场景」节、design 产物「界面设计」节（述标）、`docs/designs/assets/` 可点原型、BASE_REF 上的集成后交付物；产出节：验收报告「场景结果」「假设验证」「残余风险」。**禁装清单**：工单 Progress、实现交接记录、实现会话上下文。聚合方（主会话 / 编排会话）只聚合验收代理的报告，不重验、不改写。
- **恰一个隔离验收代理（强制）**：有子代理原语的宿主（原语对照见 docs/research/0003），验收执行派发恰一个子代理、只装上述材料清单；主会话 / 编排会话不得亲做实操走查。无子代理宿主降级为单上下文亲做，报告声明降级形态。
- **介质选择规则**：按场景操作对象选介质——Web 界面 → 宿主浏览器操作原语（browser-use / web-gui-tester 类）真实打开、点击、输入，截图与操作记录取证；CLI → 真实终端调用；API/库 → 真实调用取输出；文档 → 打开阅读。浏览器原语缺失 → 降级路径：启动服务 + 脚本 + 截图证据，报告对应行声明降级（降级不降标准，不因缺原语拒收）。
- **原型基线核销（三档判定）**：FR/场景关联原型时逐原型场景实操对照——原型场景功能**基本完成 = 过**；**缺失原型场景功能或交付比原型差 = 挂（硬伤）**；**实现优于原型 = 过**（可记亮点）。无述标（无 design 产物或缺「界面设计」节）→ 沿用现行"降级不降标准"：按工单验收标准核销，报告注明"无述标"。
- **问题分级（替代"任一场景没过即 rejected"粗判）**：**硬伤** = 功能缺失、操作行为不符预期、交付比原型差——阻塞，rejected；**瑕疵** = 不影响使用方完成任务的样式、文案、措辞类偏差——不阻塞 passed，写进「残余风险」与「下一轮建议」。rejected 判据更新为：存在硬伤，或 `check.sh all` 红灯。分级由验收代理出具并附证据，报告呈现分级依据；"判定是机械的"修订为"分级有判据、判定按判据机械执行"。
- **证据形态**：「场景结果」每行证据 = 实操记录原样引用（截图路径、操作序列、命令与输出），口径是"使用方能完成任务"；只有自动化脚本绿灯、无实操证据的**操作类场景不得判过**。读代码推定不算证据（现行禁令保留）。
- **收口自动串联（推翻 spec 0006 拍板）**：dev-execute 收口链末段"出口报告指路手动 /dev-accept"改为"清理完成后自动启动 dev-accept"。有人值守：验收按 dev-accept 现行交互推进（复述确认 → 实操走查 → 判定 → 报告 → 收口序列）。无人值守：验收全自动跑完（含蒸馏、清扫、spec 置 done），fulfilled 门停点等人；运行中间的"复述确认"降为**声明留痕**（不问人）。出口报告 = 运行摘要 + 验收报告编号。档 1 整图单运行：验收阶段入图（图内验收代理阶段 + fulfilled 升级提问）；运行内人工交互恰两次定位不变（开工确认 + 合并确认），fulfilled 门是运行后停点、不计入运行内交互。
- **无人值守判定权**：passed/rejected 判定按分级判据机械执行，无人值守下由 AI 作出；need 置 fulfilled 必须留人显式确认（含逐条接受残余风险），无人值守不豁免。
- **边界联动**：dev-execute 边界节"dev-accept 不被收口自动调用"删除；禁止事项"收口出口自动调用 dev-accept——收口止于指路"删除并反转为义务。dev-accept 入口门禁不变（工单全 done + BASE_REF）——自动串联时合并已完成，机械满足。
- **新术语**：GLOSSARY 登记「使用方走查轴」（评审轴同构三要素）与「硬伤 / 瑕疵」（验收发现分级：硬伤阻塞 rejected、瑕疵留痕不阻塞）。
- **治理顺序（先文档后技能，spec 0016 先例）**：蓝图 dev-accept 条目验收纪律句重写、dev-execute 条目收口句、验收产物行、§13.2 两技能自测行、修订记录新版本顺位；技能侧改 dev-accept 验收纪律节与出口节、dev-execute 收口链节与边界节、run-mechanics 收口细则节。全部随实现工票落。

## 验收场景

- [FR-9 | 工单级] Given 有子代理原语的宿主，When dev-accept 进入验收执行（手动或串联触发），Then 恰派发一个隔离验收代理、只装使用方视角材料清单（need 全文 / spec 验收场景 / design 述标与原型 / 交付物）、不装工单 Progress 与实现交接（grep 纪律文本强制措辞与禁装清单可核验）。
- [FR-9 | 工单级] Given 无子代理原语宿主，When 验收执行，Then 单上下文亲做并声明降级形态。
- [FR-1 | 工单级] Given 操作类集成级场景，When 验收代理判过，Then 证据为实操记录（截图 / 操作序列 / 命令与输出）；仅脚本绿灯、无实操证据不得判过（grep"实操"义务措辞可核验）。
- [FR-2 | 工单级] Given 四类交付物场景各一，When 验收执行，Then 按介质规则取证：Web → 浏览器实操、CLI → 真实终端调用、API/库 → 真实调用取输出、文档 → 打开阅读。
- [FR-3 | 工单级] Given 宿主无浏览器操作原语，When Web 场景验收，Then 走降级路径（启动服务 + 脚本 + 截图）且报告对应行声明降级，不因缺原语拒收。
- [FR-4 | 工单级] Given FR 关联原型（述标 + docs/designs/assets/ 原型），When 逐原型场景实操对照，Then 基本完成 = 过、缺失或比原型差 = 挂（硬伤）、更优 = 过；无述标 → 按工单验收标准核销并注明"无述标"。
- [FR-5 | 工单级] Given 验收发现含硬伤与瑕疵样本各一，When 出报告，Then 硬伤 → rejected、瑕疵 → 进「残余风险」与「下一轮建议」不阻塞 passed；rejected 判据 = 存在硬伤或 `check.sh all` 红灯。
- [FR-6 | 工单级] Given dev-execute 收口链文本，When 清理完成，Then 自动启动 dev-accept（义务措辞）；旧"指路手动"句与"不被收口自动调用"边界句移除（grep 可核验）。
- [FR-7 | 工单级] Given 无人值守验收 passed（无硬伤、全绿），When 走收口序列，Then 蒸馏 / 清扫 / 置 done 自动完成后在 need 置 fulfilled 门停点等人，沉默不算接受残余风险（grep"沉默不算"句保留）。
- [FR-8 | 集成级] Given 一次真实验收（手动或串联触发），When 读验收报告，Then 每个过 / 挂场景行的证据为实操记录原样引用，报告无需人到场即可自证（随下次真实验收首验）。
- [FR-6 | 集成级] Given dev-execute 无人值守运行全绿且合并确认通过，When 收口完成，Then 验收自动执行并产出报告，出口报告含运行摘要与验收报告编号（随下次真实编排运行首验；档 1 验收阶段入图同验）。

## 非目标

- 不改 dev-implement、dev-review 纪律本体与 `.sdlc/check.sh`（spec 0016 先例延续）。
- 不改 rejected → dev-fix 链路本体（need UC-7 拍板：本 need 不改）。
- 不改 dev-execute 运行调度（派发 / 评审 / 合回 / 预演）与异常流语义——只改收口链末段与边界声明。
- 不实加浏览器操作原语——用宿主既有能力（browser-use / web-gui-tester 类），缺则降级；不自研浏览器驱动。
- 不改有人值守 dev-accept 的交互门本体（复述确认、决策问题、蒸馏四路、清扫、置 done 序列）——只增实操义务、隔离执行与分级判据。
- 不改 need 置 fulfilled 的末轮条件语义（成功标准全核销 + 残余风险逐条显式接受）。
