# implement 测试纪律强制化：异常流与集成级承载规则落盘

## 问题陈述

跨多轮 implement 实践，ref-testing 六类测试方法只有红绿循环被真实触发：异常流程
（校验失败、越界输入、错误路径）无人测，集成级场景全部落到 dev-accept 人工核销。
查证到的因果链是规则缺口而非方法缺失——dev-spec 起草验收场景时只查 FR 覆盖不查
异常流（need 场景节的异常流在 spec 环节断链，下游 plan 机械映射、implement 按票测，
票里没异常条目就没有东西可测）；集成级场景"落测试或进人工清单"被实践普遍选成人工；
红绿循环条款未写明异常条目也是行为。测试质量靠模型自判，实践中已失效。

## 方案

把异常流与集成承载的规则写死进流程技能，从上游供料、下游消费两端封死缺口：

- **dev-spec**（供料端）：验收场景强制异常流条目——有 need 必须继承其场景节主要异常流；
  含错误处理的 FR 按五类判据补条目；条目按具体失败模式逐条枚举、每条可独立测试、
  禁止笼统概括；集成级场景逐条带承载声明（自动化承载票 / 人工加理由）。
- **dev-implement**（消费端）：红绿循环显式包含异常流条目；表格驱动保持信号自判。
- **dev-plan**：按承载声明为集成级场景指定承载票，承载票验收标准含集成测试编写。
- **dev-accept**：先跑全量集成级自动化测试（须全绿）再走人工段，核销证据注明
  测试名或人工理由。
- **ref-testing**：路由表与 integration.md 的承载措辞适配承载票制。
- GLOSSARY 新术语（承载票 / 承载声明）已随 need 登记，本轮不动。

## 用户故事

- 作为仓库主人，我想让 spec 起草时异常流条目成为强制项且按失败模式枚举，以便异常
  期望在上游就有独立来源、不由 implement 阶段发明。
- 作为仓库主人，我想让红绿循环显式覆盖异常条目，以便票里的异常验收标准不会被
  正常路径测试蒙混勾选。
- 作为仓库主人，我想让每条集成级场景有明确承载（自动化测试承载票 / 人工声明），
  以便"整个 spec 规定的场景有对应的实现测试"可核销。
- 作为仓库主人，我想让 dev-accept 先跑全量集成级自动化测试再走人工段，以便跨票
  协作缺陷在人工验收之前被自动化拦截。

## 实现决策

- **承载声明格式（全链路统一，机器可读）**：工单级场景不带承载声明（天然由映射票
  承载）；集成级场景标签带第三段，两形态：`[FR-N | 集成级 | 承载票 NNNN]`（可
  自动化）、`[FR-N | 集成级 | 人工：<理由>]`（不可自动化，理由必填）。该格式被
  dev-spec（起草）、dev-plan（消费并指定承载票）、dev-accept（消费分流自动化/人工）、
  ref-testing（路由指向）四处引用，字面必须一致。
- **异常流判据与枚举粒度（落 dev-spec 起草纪律）**：五类判据——校验、解析、边界、
  外部 IO 失败、状态转换拒绝路径；枚举条款——按具体失败模式逐条、每条对应可独立
  测试的期望、禁止"上传失败时提示用户"一类笼统概括（载上传例：超上限拒绝并报上限值 /
  超时报错且可重试 / 格式不符报支持格式列表）、以主要失败模式为界不追求穷尽；
  继承条款——有 need 必须继承其场景节主要异常流。
- **异常入红绿（落 dev-implement §3 红绿循环条）**：加一句"每个行为包括验收标准中的
  异常流条目"；不新增表格驱动强制路由条款，保持 ref-testing 场景路由表信号自判
  （need 拍板 D4-B'）。
- **承载票制（落 dev-plan 场景映射）**：每条 `[FR-N | 集成级 | 承载票 NNNN]` 场景
  的承载票验收标准含"集成测试编写（真实协作者 + 受控外部替身）并可在集成后运行"；
  人工声明场景仅进 dev-accept 人工段清单。
- **accept 分流（落 dev-accept 验收流程）**：集成级场景按承载声明分流——自动化段
  先跑全量且须全绿，有红停下指路 dev-fix；人工段按声明逐条执行；核销证据注明
  自动化测试名或人工理由。
- **validate 机器化边界**：round 1 不改 check.sh——异常流继承与承载声明靠 dev-spec
  起草纪律与 spec 批准门把关；孤儿 FR 式机器校验（含"集成级场景必带承载声明"）留
  实践失灵后 round 2 备选（对应 need 假设 A2）。
- **GLOSSARY**：承载票 / 承载声明已随 need 登记（根本与 setup-workspace 资产模板
  双份同步），本轮零改动。
