# Dock 页样式美化 round 2：token 化样式层（纯视觉残余）

## 问题陈述

round 1 功能验收 passed、已发布 0.2.0（need 20261118-11f8 fulfilled），但客户端面板实现为裸 createElement HTML、无样式层——渲染为浏览器默认观感（默认字体/按钮/无主题色）。发起人验收后反馈（原话「样式太丑且与 dsh 风格不统一」2026-11-18）： Dock 页与宿主 Web Client 视觉割裂，图形化体验不成立。

## 方案

round 2 = 纯视觉残余（分轮拍板 2026-11-18：功能零变更入非目标）：

1. **按 design 0004 述标契约建 token 化样式层**（approved，2026-11-18）：布局 9 条（面板头/行卡/异常内联/行内操作条/添加表单/行内编辑/空态/错误降级/加载态）+ 视觉决策 7 项（全量 `var(--dsw-alias-*)` 取色、不写死字体、14/12px 两档、radius token 阶梯、px 直值间距、面板弱层次、状态徽章四态可辨识）；≤767px 断点下表单竖排按钮换行。
2. **实现校验点三件**（述标带走）：bundle 内零 `#[0-9a-f]{3,6}` 直值色、零 font-family 写死、取色全走 token——样式契约进自动断言。
3. **版本 bump + 双包发布核销延续**：插件包版本升级（具体号归实现），按 plugin-assets.md §1.4 双包顺序发布，registry 对账沿既有发布版 test 形态。

## 用户故事

- 作为 dsh web 使用者，我想要 Dock 页的配色、字体、控件形态与 dsh Web Client 整体一致，以便面板像宿主原生部分而非外挂物。
- 作为 dsh web 使用者，我想要异常 server 一眼可辨（状态徽章 + 内联原因提示条），以便扫一眼即知健康度。
- 作为 dsh web 使用者，我想要行内操作按钮轻量顺眼、动作有即时中间态反馈，以便高频管理不打断、不迷惑。
- 作为套件维护者，我想要样式契约进自动断言（零硬编码色值），以便后续 UI 演进不回退成裸样式。

## 实现决策

- **样式层契约（design 0004 述标 approved 为准）**：全量 `var(--dsw-alias-*)` 取色（bg-layer/border/label/state-error/button 族）；不写死 font-family（继承宿主三路用户设置）；字号 14px 正文 + 12px 辅助两档；圆角 radius-md/lg/xs/pill token；间距 px 直值参照官方组件实况（基线「无全局 spacing token」口径）；面板 border-l2 弱边框无重阴影；≤767px 断点表单竖排。布局 9 条与视觉决策 7 项逐条以 ui 草稿 0003（approved）为基准实现，本 spec 不重述。
- **功能零变更契约**：`data-mcp-*` 属性钩子、watch/update/mutate/restart/probe 调用形态、管理服务单点共调——全部不动；样式层只改呈现。既有替身契约测试与集成测试零修改通过 = 功能零变更的机械证明。
- **样式契约自动断言**：发布态校验扩展（或单测）断言 client 产物内无 `#[0-9a-f]{3,6}` 直值色、无 `font-family:` 写死（token 快照注释内的演示值除外——断言面只扫产出代码）。
- **发布纪律**：版本 bump 语义化演进（具体号归实现）；发布前 `npm view` 兼容星座核验留痕（ADR ad91）；发布后 registry 发布版对账 test 通过（版本对账目标随 bump 更新）。

## 测试决策

- **seam 清单**：①样式契约断言（client 产物零 hex 直值色/零写死字体）；②既有替身契约测试回归零修改通过（功能零变更证明）；③既有 e2e 集成回归零修改通过（web 形态真跑不变）；④发布面（版本 bump 后 verify-bundle/verify-pack/registry 对账沿既有形态）。
- 既有先例：round 1 `test/unit/dsh-mcp-plugin.test.ts` 替身契约（data-mcp-* 属性断言——样式层不改属性钩子即天然兼容）、`test/e2e/dsh-mcp-e2e-integration.test.ts`（真跑前置门四条件，ADR ad91）。
- UI 呈现与点击交互的人工浏览验收沿 round 1 人工段口径（截图留痕），不引入浏览器自动化。

## 验收场景

- [FR-1 | 工单级] Given 替身 ctx 与客户端面板渲染，When 列表/异常内联/状态徽章呈现，Then 视觉形态符合 design 0004 决策 2/3（行卡 radius-md + border-l2、徽章四态可辨识、原因内联提示条），且 `data-mcp-*` 属性钩子不变。
- [FR-1 | 集成级 | 人工：浏览器渲染与视觉品味需真浏览器观察（round 1 D6 口径）] Given dsh web 会话，When 打开 Dock 页人工浏览（浅色/深色主题各一遍），Then 面板观感与宿主风格一致（无浏览器默认裸样式残留），截图留痕对照 design 0004 原型。
- [FR-2 | 工单级] Given 添加表单，When 两 transport 切换呈现，Then 字段组切换形态符合 design 0004 决策 5（同表单切换、输入框 token 化样式），模板串提示文案保留。
- [FR-3 | 工单级] Given 行内编辑表单，When 呈现与保存，Then 凭据字段脱敏占位与「未重输即保留」提示可见（design 0004 决策 6），保存路径不变。
- [FR-4 | 工单级] Given 行内操作条，When 启停/移除/重试呈现与触发，Then ghost 按钮组 + 中间态文案（connecting…/probing…）符合 design 0004 决策 4，调用形态不变。
- [FR-5 | 工单级] Given 空清单，When 渲染，Then 引导文案样式符合基线（label-tertiary、虚线框、无按钮），文案内容不变。
- [FR-6 | 集成级 | 人工：npm publish 属单向门，发布动作在验收时点由维护者执行] Given 版本 bump 完成，When 双包发布并跑 registry 对账，Then `npm view` 版本与仓库一致、registry 发布版对账 test 通过。
- [FR-7 | 工单级] Given 两面编译发布态，When verify-bundle/verify-pack，Then 样式层随 client 产物入 tarball、五查通过、样式契约断言（零 hex 直值色/零写死字体）通过。
- [FR-8 | 集成级 | 承载票 NNNN] Given 兼容星座真跑组合，When 真实 boot dsh web，Then 既有集成测试零修改通过（combo 路由 + Remote 数据链路回归——功能零变更的机械证明），且 client bundle 含样式层。
- [FR-8 | 集成级 | 人工：与 FR-1 人工段同源] Given UI 人工浏览，When 全操作走查（列含状态/添加/编辑/启停/空态/失败内联），Then 交互行为与 round 1 验收一致（零功能变更），视觉符合本 round 规格，截图留痕。

## 非目标

- 功能变更（watch/写通道/管理服务调用形态全部不动——round 1 已验收语义）。
- 布局重构（布局 9 条已在 design 0003/0004 定稿，本 round 只实现不重设计）。
- 基线修订（design-web.md 生效基线不重建；偏离才需声明，本 round 全程跟随零偏离）。
- 浏览器自动化依赖引入（D6 口径延续）。
- `@hankchen/infra` 侧机制改动（编目/安装/对账复用既有）。
