# dev-accept 浏览器场景当前会话验收（混合验收形态）

## 问题陈述

spec 20261108-2fe1 确认的介质规则把"仅限主会话"的宿主原语**视同缺失**走降级、"不得由主会话代操作"（dev-accept §3 介质选择规则末句）。ZCode 宿主的内置浏览器操作原语自述 main agent only、仅主会话可用，于是 Web 界面场景验收在该宿主上永远走降级路径——启动服务 + 脚本 + 截图，拿不到真实浏览器操作证据（打开 / 点击 / 输入的实操记录）。实测证据：蓝图 §13.2 dev-accept 演练实录（两轮演练 Web 介质均走降级，代理以 CDP 脚本真实事件 + 截图取证——是脚本代操作，不是主会话实操）；need 20261109-a061 用户陈述（2026-11-09，execute 串联 accept 实现会话命中同一问题）。结果 = ZCode 宿主上 Web 交付物验收报告永远带【降级】标记，使用方走查轴（GLOSSARY：使用方能完成任务吗）在 Web 交付物上名存实亡。

## 方案

**介质规则三态反转 + 混合验收形态。** 浏览器操作原语按可用性分三态处置（以工具自述为准）：① 对验收子代理可用 → 仍派恰一个隔离验收代理承载（隔离优先）；② 仅主会话可用 → Web 界面场景由当前会话（执行体 / 编排会话）**亲做亲判**——真实操作浏览器、截图与操作记录取证、场景行自己出具，其余介质场景仍归隔离验收代理，报告首行声明**混合验收形态**（GLOSSARY 新词：隔离验收代理承载非浏览器介质 + 主会话承载浏览器场景）；③ 确无可用原语 → 现行降级路径不变（降级不降标准）。【降级】标记语义收窄：只用于态 ③。

**档 1 图内停回主会话（need FR-5 归本 spec 裁决的承载方式）。** 整图单运行的图内验收代理阶段遇"态 ② + spec 含 Web 界面集成级场景"→ 经升级提问停回主会话：主会话按走查轴纪律实操取证亲判，逐场景结果行作答回填，验收代理聚合出报告后运行续走。该停点由主会话（编排会话）作答、**非人工门**——两值守模式均不停等人，无人值守运行仍全自动到报告（§8.7 语义保持）。

本 spec 显式推翻 spec 20261108-2fe1 拍板"原语以验收代理可用为准：仅限主会话视同缺失走降级，不得由主会话代操作"；理由 = need 20261109-a061 业务目标（Web 场景真实浏览器取证不降级）+ 反转理由（判断隔离收益 < 永远降级代价）。2fe1 已 done 不回改，验收介质行为以本 spec 为准。

## 用户故事

- 作为 ZCode 宿主用户，我想让 Web 交付物的验收场景由当前会话真实操作浏览器取证，以便验收报告不再永远带【降级】标记。
- 作为验收使用方，我想在混合形态报告里看到真实浏览器操作序列与截图，以便逐场景核销"使用方能完成任务"。
- 作为拍板人，我想让隔离原则只在浏览器介质上让位（子代理能用浏览器时仍隔离），以便 CLI / API / 文档场景的判断隔离不受影响。
- 作为档 1 编排用户，我想让图内验收代理把浏览器场景停回主会话承载后继续运行，以便整图单运行的验收段不因介质能力中断。
- 作为无人值守发起人，我想让浏览器承载停点由主会话作答而无需等人回来，以便无人值守运行仍全自动到报告。

## 实现决策

- **介质选择规则三态反转（推翻 2fe1 拍板）**：dev-accept §3 介质选择规则末句"原语以验收代理可用为准：仅限主会话视同缺失走降级，不得由主会话代操作"替换为三态规则——① 子代理可用（以工具自述为准）→ 隔离优先，仍派恰一个隔离验收代理；② 仅主会话 → Web 界面场景由当前会话亲做亲判（浏览器真实打开 / 点击 / 输入，截图与操作记录取证），CLI / API / 文档场景仍归隔离验收代理；③ 确无可用原语 → 降级路径不变（启动服务 + 脚本 + 截图 + 【降级】标记）。原语可用性判定依据 = 工具自述（如 main agent only 字样），随派发单能力声明机制枚举，不新增探测手段。
- **混合形态承载纪律**：主会话亲做浏览器场景时按使用方走查轴判断依据材料**自装**（need 全文、spec「验收场景」节、design「界面设计」述标与原型、BASE_REF 集成后交付物），禁装清单（工单 Progress、实现交接记录、实现会话上下文）对执行体同样生效；浏览器场景行由主会话出具（亲做亲判），其余场景行由验收代理出具；报告聚合两来源分节原样、不重验、不改写——聚合纪律原文语义保持。执行体薄上下文条（§2"正因如此执行体不得亲做走查"）同步限定：亲做禁令收窄到非浏览器介质。
- **报告形态行三态枚举**：验收报告「场景结果」首行形态声明从两态扩三态——`<恰一个隔离验收代理 | 混合（隔离验收代理 + 主会话浏览器走查） | 单上下文降级>`；蓝图 §6.5 acceptance 产物行同步。【降级】标记只用于态 ③ 场景行。
- **能力声明三态**：派发单随附宿主介质能力声明从两态（可用 / 不可用）扩为三态（子代理可用 / 仅主会话 / 缺失）——态 ② 下派发单注明"浏览器场景由执行体承载，验收代理不涉 Web 场景"。
- **档 1 图内停回主会话**：run-mechanics §4 验收代理阶段补细则——图内验收代理遇"态 ② + spec 含 Web 界面集成级场景"→ 经升级提问停回主会话，主会话亲做亲判、逐场景结果行作答回填，验收代理聚合出报告后续走；回填后验收代理**先落盘报告 draft** 再走后续场景（中断续接按 §5.6 判读，已出结论场景不重跑，浏览器证据不悬在对话里）。该停点由主会话作答、非人工门——不计入运行内人工交互（恰两次定位不变），两值守模式不停等人；无人值守在 journal 与出口报告留痕混合形态声明。
- **§8.7 值守分档同步**：有人值守行"实操走查（恰一个隔离验收代理，按介质规则实操取证）"补混合形态一句；无人值守行补"档 2–4 执行体即主会话、浏览器场景直接亲做不停机；档 1 经升级提问停回主会话承载、运行不停"。
- **新术语**：GLOSSARY 登记「混合验收形态」（根 + assets 双份，dual-copy-assets 纪律随票同步）。
- **治理顺序（spec 2fe1 先例，先文档后技能）**：蓝图（§11.9 dev-accept 验收纪律句介质规则句、§6.5 acceptance 形态行、修订记录新版本顺位、§13.2 自测注记随实现票补录）→ 技能侧（dev-accept §2 / §3 介质规则与能力声明 / §4 报告模板形态行 / 禁止事项亲做禁令限定；run-mechanics §4 验收代理阶段 / §8.7）。全部随实现工票落。

## 验收场景

- [FR-1 | 工单级] Given 浏览器原语仅限主会话（工具自述 main agent only）且 spec 含 Web 界面集成级场景，When dev-accept 介质选择规则执行，Then 规则指示 Web 场景由当前会话真实操作浏览器取证亲判、不走降级（grep：三态措辞命中，"视同缺失走降级""不得由主会话代操作"两旧句移除）。
- [FR-2 | 工单级] Given 浏览器原语对验收子代理可用，When Web 界面场景验收，Then 仍派恰一个隔离验收代理承载（grep：隔离优先措辞 + 能力声明三态枚举命中）。
- [FR-3 | 工单级] Given 主会话承载浏览器场景走查，When 出具场景结果行，Then 亲做亲判、自装走查轴材料、不读禁装清单（grep：禁装清单对执行体同样生效措辞命中）。
- [FR-4 | 工单级] Given 混合形态验收报告，When 读首行形态声明，Then 三态枚举含混合形态、浏览器场景行由主会话出具且无【降级】标记、【降级】仅用于确无可用原语的场景行（grep：报告模板与蓝图 §6.5 两处三态枚举命中）。
- [FR-5 | 工单级] Given dev-execute 档 1 整图运行且浏览器原语仅限主会话，When 图内验收代理阶段遇 Web 界面场景，Then 细则指示经升级提问停回主会话亲做亲判、结果行回填、验收代理聚合后续走、停点非人工门（grep：run-mechanics §4 细则与 §8.7 值守分档句命中）。
- [FR-1 | 集成级] Given 真实验收（本仓库宿主，浏览器原语仅限主会话），When Web 界面场景执行，Then 主会话真实操作浏览器取证亲判、报告形态行声明混合形态、该场景行无【降级】标记（随下次含 Web 交付物的真实验收首验）。
- [FR-5 | 集成级] Given 档 1 真实编排运行含 Web 交付物，When 验收代理阶段执行，Then 停回主会话承载后续走、验收报告聚合两来源、出口报告载验收报告编号（随下次档 1 真实运行首验）。

## 非目标

- 不改非浏览器介质（CLI / API / 文档）的隔离验收代理机制与聚合纪律本体。
- 不改"降级不降标准"原则与态 ③（确无原语）宿主的降级路径。
- 不实加浏览器操作原语、不自研浏览器驱动——用宿主既有能力，缺则降级。
- 不改 dev-implement / dev-review 纪律本体与 `.sdlc/check.sh`（2fe1 非目标延续）。
- 不改 fulfilled 门、rejected 出口、收口序列（蒸馏 → 清扫 → 置 done → 原子提交）本体。
- 不扩展只读证据代理（只能 Read PNG 的 visual-judge 类）的浏览器操作能力。
