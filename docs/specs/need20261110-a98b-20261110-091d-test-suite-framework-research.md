# 测试套件框架迁移调研报告（round 1）

## 问题陈述

4415 行 bash 测试套件（528 条用例）守护 853 行门禁引擎，bash 3.2 引号坑已留下实证
注释。「迁/不迁、迁到哪」至今只有一份未经系统调研的单方评估——决策无据可依：
若仓促迁移可能选错框架导致 528 条用例返工；若不调研则决策持续悬置，每次提起都要
从头评估。need 20261110-a98b 已把前提锁死（运行时维持 bash），本轮交付物是
一份够拍板的调研报告。

## 方案

产出一份调研报告（docs/research/ 标准产物），对四条候选路线——① pytest（Python）、
② node/ts 系测试框架（vitest 或同类）、③ bats-core（bash 测试框架原地升级）、
④ 保持 bash 现状基线——做五维度横向对比（安装形态与离线性、子进程驱动断言能力、
失败诊断质量、bash 3.2 宿主兼容、维护成本），给出单一推荐与否决理由，配套迁移成本
分组估算、三类风险清单与 528 用例等价红线验证策略。「保持现状」是合法结论，须给出
量化否决依据。报告经 validate + publish 后，用户据此直接拍板，下游开迁移 spec 时
无需补调研。

## 用户故事

- 作为仓库维护者，我想要一份含选型推荐、成本估算、风险清单三要素的调研报告，以便
  读完即可拍板「迁/不迁、迁到哪」，不需要再查任何资料。
- 作为仓库维护者，我想要每条对比结论都带一手来源与检索日期，以便拍板依据可回溯，
  不被二手结论污染。
- 作为后续迁移 spec 的起草者（dev-spec），我想要分组成本估算与等价红线验证策略在案，
  以便起草实现决策与测试决策时零补充调研。

## 实现决策

- **报告结构（固定六节）**：① 执行摘要（推荐 + 一句否决理由）；② 对比矩阵（候选
  路线 × 五维度，每格含结论与来源标注）；③ 迁移成本估算（按用例类别分组）；④ 风险
  清单（三类）；⑤ 等价红线验证策略；⑥ 来源列表（一手官方文档优先，二手标注出处与
  检索日期）。
- **调研方法分层**：系统调研由执行工单装载 dev-research 技能承接（need 澄清期已
  按 research.md 方法文件把「不知道」分层：可当场查的已查掉进 need 正文，框架对比
  属多来源对比留待系统调研）；本 spec 已知事实（用例统计、运行时在册情况）直接
  进报告背景，不重复调研。
- **成本估算口径**：以 `t` / `tn` / `oseq` / 夹具助手（new_repo、wfile、setfm、
  fake_cmd）四组分别统计数量（2026-11-10 实测：t+tn+oseq 合计 528 条），按组的
  断言形态给出单用例迁移成本量级（如 oseq 的滑动窗口断言迁移代价高于 t 的子串
  断言），汇总为总人日量级估算并附分批策略概要。
- **等价红线判定**：以「断言面覆盖」为等价判据——新套件对 check.sh 各子命令的
  断言覆盖不低于旧套件清单（旧套件 528 条的断言面在报告中建索引）；验证策略须含
  迁移期双跑对照或同等手段，且等价验证完成前旧套件不删。
- **候选集扩充规则**：调研中发现候选集外重要路线且一手资料可得时可扩充，扩充记录
  （路线名 + 扩充原因）写进报告备注；五维度对比口径不因扩充改变。
- **报告以 research 产物落盘**：`check.sh claim research <slug> spec <本specID>`
  取号带谱系前缀，正文覆盖占位文件，过 `check.sh validate`（research 类型受理）与
  `check.sh publish`。

## 测试决策

- seam：`check.sh validate`（research 产物受理与 status 流转）、grep/wc 机械核验
  报告六节结构与对比矩阵行列数、来源标注格式（每条结论带来源+检索日期）、成本估算
  四分组齐备。
- 既有同类先例：本仓库文档型交付物的机械校验先例为 spec 0003（wc 行数硬校验 +
  grep 条款登记）；测试套件行为回归不在本轮（交付物是文档，不动任何脚本）。
- 人工验收：报告「够拍板」属主观判定，走 dev-accept 人工验收场景（用户通读后
  确认可直接拍板）。

## 验收场景

- [FR-1 | 工单级] Given 报告落盘 docs/research/，When grep 对比矩阵节，Then 至少
  四条候选路线（pytest / node 系 / bats-core / bash 现状基线）× 五维度（安装形态与
  离线性 / 子进程驱动断言能力 / 失败诊断质量 / bash 3.2 宿主兼容 / 维护成本）每格
  有结论，执行摘要给出单一推荐与否决理由。
- [FR-1 | 工单级] Given 报告任一对比结论，When 核对来源标注，Then 该结论带一手来源
  （官方文档链接）或标注二手出处与检索日期，无来源结论不存在。
- [FR-2 | 工单级] Given 成本估算节，When 核对分组，Then 含 t / tn / oseq / 夹具
  助手四组，各组有用例数量与单用例迁移成本量级，汇总总人日量级估算，且附分批策略
  概要（≥2 批的切分依据）。
- [FR-3 | 工单级] Given 风险清单节，When 逐条核对，Then 三类齐备：门禁行为回归的
  风险与防护手段、新旧套件并行/切换/回退策略、选错框架的退出成本。
- [FR-4 | 工单级] Given 推荐方案的等价红线节，When 核对验证策略，Then 含断言面
  覆盖索引或同等等价判据、迁移期双跑对照（或同等手段）、等价验证完成前旧套件保留
  三要素。
- [FR-5 | 工单级] Given 报告产物文件，When 运行 `check.sh validate` 与
  `check.sh publish`，Then validate 通过（research 受理）且 publish 投影成功。
- [FR-1 | 工单级] Given 对比后 bash 现状基线胜出，When 报告出具否决迁移依据，Then
  含迁移收益与成本的量化对照（收益项逐条对照成本项），「不迁」构成可拍板结论，
  不产生迁移 spec。
- [FR-1 | 工单级] Given 调研中发现候选集外重要路线且一手资料可得，When 报告扩充
  候选集，Then 备注含扩充记录（路线名 + 原因），五维度对比口径不变。
- [FR-1 | 工单级] Given 某维度一手资料不可得（官方文档缺失或闭源），When 撰写该格
  结论，Then 该格标注「来源不足」并降级为显式假设进风险清单，不以二手结论或推测
  填充。
- [FR-5 | 集成级 | 人工：报告「够拍板」是主观判定，须用户通读后确认] Given 报告
  三要素齐（选型推荐、成本估算、风险清单），When 用户通读报告，Then 用户能直接
  宣布「迁/不迁、迁到哪」的拍板结论，无需任何补充查证。
