# dev-execute 运行形态选择：并行模式点选与值守模式

## 问题陈述

dev-execute 的运行形态由系统自动决定，用户只能听声明、不能选：

1. **并行形态自动命中**：派发回退链（档 1 整图单运行 > 档 2 后台子代理 >
   档 3 同步子代理 > 档 4 串行逐票）按能力探测自动取最优先档，档 1 命中时
   主会话要生成并校对整图工作流脚本——小 spec 上脚本成本超过收益，且整图
   编排的逐票进度流不如逐票派发直观（用户 2026-11-07 拍板 D1 动机）。
2. **值守无选择**：所有决策点一律停下问人（开工确认、评审阻断、§8 五类
   异常流、合并确认），人想挂机跑一张 spec 做不到——中途任何异常都会停机
   等一个不在场的人（用户原话"无人值守时按大模型判断选最优解"）。

## 方案

把运行形态从"系统自动决定"改为"**开工确认双点选**"：

1. **并行档点选**：开工确认呈现能力探测后的全部可用档（宿主缺能力的不出现），
   默认推荐档 2 后台子代理（理由随建议声明：脚本生成成本 + 进度透明）；用户
   可点名任意可用档含档 1。回退链降格为**能力约束**（决定菜单里有什么），
   不再是**优先序**（不再决定默认落哪档）；档 1 机制与 spec 0013 交付原样保留，
   仅退出自动首选位。
2. **值守模式点选**：开工确认一并点选有人值守（默认，行为与现行零差异）或
   无人值守。无人值守 = 发起时一次点选（含开工确认）后，运行中除"合并到
   主分支"外全部决策点由大模型按流程纪律自主选优并继续：设计级阻断自行定
   方案、合回冲突自行解、spec 缺口自行修订、预演失败自行开 fix 票入图重算；
   每次自主决策逐条留痕（决策点、候选与所选、一句理由）进该票 Progress 与
   出口报告；合并到主分支仍是需显式确认的单向门——运行全绿后停在合并门
   等人回来。人工交互恰两次不变：开工确认（发起时）+ 合并确认（回来后）。
3. **治理顺序**（spec 0012 确立的"先蓝图后技能"）：蓝图 §11.17 与 §8 决策点表
   先行修订，再落 dev-execute SKILL.md / run-mechanics，最后临时仓库演练。

## 用户故事

- 作为仓库主人，我想在开工确认时从可用并行档里点选（默认推荐异步多子智能体），
  以便小 spec 不被整图脚本编排拖慢、逐票进度随时可见。
- 作为仓库主人，我想点名档 1 整图单运行，以便大 spec 想一把梭时仍用声明式
  工作流全图编排。
- 作为仓库主人，我想在开工确认时选有人/无人值守，以便白天盯紧、晚上挂机。
- 作为仓库主人，我想让无人值守运行自行处置红灯、冲突与设计级问题，以便
  一觉醒来只差一次合并确认。
- 作为仓库主人，我想让合并到主分支始终要我显式确认，以便单向门不因
  无人值守而失守。
- 作为仓库主人，我想让无人值守的每次自主决策留痕可查，以便事后审计、
  推翻重跑有据。

## 实现决策

- **点选承载在开工确认（§3.3 既有门，不新增人工门）**：探测仍开工确认前
  一次、运行中不重探测（既有约定）；探测结果从"命中即声明"改为
  "**可用档菜单 + 默认建议**"——逐档可用性由既有四档判据（run-mechanics
  §4）判定，缺能力档不进菜单并声明缺什么；默认建议档 2（宿主无档 2 能力时
  建议次优可用档，理由声明）。用户点名即定档；不点名即按默认建议走。
  开工确认声明口径从"本次形态与命中原因"扩为"**本次并行档（点选或默认）
  + 本次值守模式 + 形态差异说明**"（命中档 1 仍说明与逐票档的编排模型差异）。
- **档 1 退出自动首选位**：四能力齐备判据保留（用于判定"可用"、进菜单），
  自动命中优先序废除——档 1 仅经点名进入；档 2/3/4 间的宿主退化序保留
  （无后台子代理原语的宿主落档 3 起步的既有判据不变）。无子代理宿主菜单
  可能只剩档 4：无从点选，自动落唯一可用档并声明（退化链兜底不变）。
- **值守模式语义分档**（GLOSSARY 已登记三术语）：
  - **有人值守（默认）**：现行全部语义零变化——开工确认、评审阻断处置、
    五类异常流、合并确认全部停下问人。
  - **无人值守**：决策点归属改写，逐点落定——
    - 评审机械问题：修后重审（现行已自动，不变）。
    - 评审设计级阻断：大模型自行定方案，受影响票重开实现，运行不停。
    - 预演失败：按 dev-fix 纪律自行开 fix 票并入运行图重算后续（档 1 经
      脚本修订补图、缓存复用；档 2–4 主会话重算），继续运行。
    - 合回冲突（预检序候选全冲突或实合冲突）：大模型自行解冲突内容后继续
      合回（标准动作仍含先 `git merge --abort` 还原再处置的既有停机动作，
      处置者从"人"换为"大模型"）。
    - spec 缺口：按 dev-spec 修订纪律自行修订 spec，新票/改票并入图重算。
    - **合并确认：保留人工**——全绿停在合并门，问清内容（方式 + tag）与
      单向门语义不变，沉默不算确认、拒绝则停在门上、合并未执行不清理。
  - 自主处置是**纪律化处置**（走 dev-fix / dev-spec / 既有冲突处置动作），
    不是盲目重试——"不自动重试"禁令在无人值守下改述为"不脱离纪律重试"。
- **禁令分档表述（need A4 收口）**：SKILL.md §8 / 禁止事项 / run-mechanics /
  蓝图 §11.17 的"不自动解冲突、不自动改 spec、不自动重试"改为按值守模式
  分档——有人值守全量生效；无人值守改为"自主处置 + 留痕"（上述逐点语义）；
  "沉默不算确认、合并未执行不清理"两条例外：**不分档、全模式生效**（合并门
  是人机交互，语义不因无人值守松动）。
- **留痕承载（FR-6）**：自主决策记录条目 = 决策点类型 + 候选与所选 + 一句
  理由；逐条进该票 Progress（随既有物化/翻转副本同步机制进运行 worktree，
  ADR 0003 裁决 2 既有链路）+ 出口报告新增"自主决策记录"清单（现行"异常
  与处置"节的无人值守形态）。有人值守无此要求（对话即记录）。check.sh
  零改动（留痕是会话内陈述，不新增产物类型、不进门禁）。
- **无人值守 × 档 1 组合**：档 1 图内人工门（升级提问/洞穴）在无人值守下
  语义替换——五类异常的升级提问改为图内**自主决策阶段**（选优 + 留痕，
  journal 记录），合并确认升级提问保留人工（图内仍停等人答）；恰两次人工
  交互定位不变。无人值守 × 档 2–4：主会话自主决策（无人可问即自选）。
- **宿主权限前提声明（need A3 收口）**：无人值守的"中间零停机"以宿主权限
  模式不在工具调用中间打断为前提（如全自动化权限模式）；开工确认点选
  无人值守时向用户声明该前提，未满足时提示先行配置——声明不阻断（宿主
  配置归运行环境，技能层只约定运行内决策行为）。
- **收口与验收边界不变**：收口链步序不变（fresh 全量检查 → PR → pre-push →
  合并确认 → 合并 → done → 清理 → 出口报告）；dev-accept 不被自动调用
  （含无人值守，全绿止于指路）。
- **治理顺序**：先蓝图——§11.17 dev-execute 规格修订（双点选 + 值守分档 +
  留痕 + 禁令分档）、§8 决策点表 dev-execute 行（人工门次数按值守模式
  分档表述）、修订记录新条目（v1.25 顺位——立项时写 v1.23 系误信蓝图滞留
  旧版本行，v1.23/v1.24 已被 design-* 套件与评审轴清单制占用，2026-11-07
  实现期订正）；§7.2 引用矩阵与 §10.1 技能
  清单零改动（无新技能）。后技能——SKILL.md description / §2 / §3.3 / §5 /
  §6 / §7 / §8 / §9 / 禁止事项与 run-mechanics §4 / §5 / §6 / §7 / §8 同批
  修订（description 与 §2/§5/§6 为衔接收口同改）。最后演练。

## 验收场景

- [FR-1 | 工单级] Given ZCode 宿主能力探测完成，When 开工确认，Then 呈现
  全部可用档菜单与默认建议（档 2 + 理由：脚本生成成本与进度透明）；用户
  点名档 1 时本次运行按整图单运行形态执行且声明了编排模型差异。
- [FR-1 | 工单级] Given 宿主无后台子代理原语，When 开工确认，Then 菜单
  不含档 2 且默认建议落次优可用档，缺能力档声明缺什么——能力约束决定
  菜单，不硬编码优先序。
- [FR-2 | 工单级] Given 四能力齐备宿主且用户未点名任何档，When 运行建立，
  Then 本次运行落档 2 而非档 1——档 1 仅点名进入。
- [FR-3 | 工单级] Given 开工确认呈现值守模式点选，When 用户选无人值守并
  确认开跑，Then 运行中间不再出现停下问人（除合并确认门），且开工确认
  声明了宿主权限模式前提。
- [FR-4 | 工单级] Given 无人值守运行中编排评审发现接口级问题，When 大模型
  自行定方案，Then 受影响票重开实现、运行不停，决策留痕进票 Progress。
- [FR-4 | 工单级] Given 无人值守运行中 merge-tree 预检候选序全冲突，When
  大模型自行解冲突，Then 合回继续、留痕在案；同场景有人值守仍停下问人
  （零回归对照）。
- [FR-4 | 工单级] Given 无人值守运行中预演红灯，When 按 dev-fix 纪律自行
  开 fix 票入图重算，Then 运行继续至全绿，fix 处置留痕（档 1 经脚本修订
  补图，已完成步缓存复用不重做）。
- [FR-5 | 集成级] Given 无人值守运行全绿，Then 运行停在合并确认门：沉默或
  拒绝 → 不合并、不清理，盘上状态即运行状态（中断续接可用）；显式确认 →
  按确认方式执行合并后走完收口链。
- [FR-6 | 工单级] Given 无人值守运行产生多次自主决策，When 查出口报告
  "自主决策记录"清单与各票 Progress，Then 每条含决策点类型、候选与所选、
  一句理由，可按票号追溯；有人值守运行的出口报告无此清单（对话即记录）。
- [FR-4 | 集成级] Given 演练仓库三层依赖链 spec 以无人值守 + 档 2 整链运行，
  When 中途注入预演红灯与一次合回冲突，Then 全程零人工停机到达合并门，
  人工交互恰两次（发起点选 + 合并确认），自主决策逐条留痕。
- [FR-3 | 集成级] Given 有人值守默认档同款演练整链运行，Then 行为与现行
  零差异：恰两次人工交互、五类异常停机问人、不自动解冲突/改 spec 禁令
  全量生效——零回归门。
