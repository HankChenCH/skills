# 存量项目知识逆向扫描技能（setup-reconstruct）

## 问题陈述

存量项目接入本套件时是知识白纸：没有 need、ADR、spec 历史沉淀物，正向流程（dev-clarify → dev-accept）假定项目从零开始，对存量项目无从积累。后果是每个新会话的 agent 都要全量扫描代码才能开工，同一份"理解这个项目"的代价被反复支付；且未接入仓库连套件形态的落盘位置（docs/ 产物目录、GLOSSARY 项目术语章、standards）都不存在，扫出的理解没有归宿，更无法被下个会话复用。仓库主人要的是：对存量项目跑一次扫描，尽量逆向出套件形态的沉淀物落盘，让后续会话只读沉淀物即可正确接续开发。

## 方案

新增 setup-\* 家族按需服务技能 setup-reconstruct（技能总清单 21 → 22）：在目标 git 仓库分轮读码，逆向推断并产出本套件知识档形态的沉淀物——逆向 need（业务规则与系统边界）、逆向 spec（系统行为与模块职责）、逆向 ADR（历史决策候选），折叠内容进 AGENTS.md（哨兵块外）、GLOSSARY 项目术语章、docs/standards/ 与 CODING_STANDARDS.md 索引；每条行为断言带 文件:行 证据，低置信推断显式标注；每张产物带扫描基线（commit、日期、覆盖与未覆盖范围）。产物全程只读扫描、草案先行，经用户显式确认后才写入：未接入仓库先按 setup-workspace 全流程完成接入、随后写入逆向产物，一次完成；已接入仓库仅写入逆向产物。逆向 need/spec 落盘即置新状态 `reconstructed`——不进 frontier 与待办语义，check.sh 状态机表为此扩一处。重跑 = 增量对齐：按扫描基线 commit 与 HEAD 的 diff 定位漂移，只重验与更新漂移部分，不推倒重来。定位按需服务（同 dev-docs）：不进 sdlc 自动串联链，用户手动触发。

## 用户故事

- 作为仓库主人，我想对存量项目跑一次扫描得到带证据的套件形态沉淀物，以便新会话 agent 只读沉淀物即可接续开发，不重复全量扫描。
- 作为仓库主人，我想让每条行为断言都能回溯到 文件:行，以便抽查核验扫描没有编造。
- 作为仓库主人，我想在产物写入仓库前逐张审查确认，以便低置信推断不冒充事实入库。
- 作为未接入仓库的主人，我想让扫描流程顺带完成套件接入，以便一次会话从白纸到可用。
- 作为仓库主人，我想重跑扫描时只更新与代码漂移的部分，以便已确认的内容不被推倒重来。
- 作为扫描超大仓库的用户，我想让扫描分轮推进并显式记录未覆盖区，以便未扫到的部分不被误读为"不存在"。
- 作为未来 agent 会话，我想从扫描基线一眼看出沉淀物对应哪个 commit、覆盖哪些范围，以便判断知识新鲜度。

## 实现决策

**技能定位与结构（FR-1）**：终名 setup-reconstruct（D5 授权 dev-spec 定名：与状态 `reconstructed`、GLOSSARY 词条"逆向产物"同词根），归 setup-\* 家族，按需服务定位同 dev-docs——sdlc next-mode 路由表不加行，出口形态 = 报告 + 指路，不自动串联。技能由主文档与按需加载的参考文档构成：主文档管入口门禁、流程骨架与禁止事项；参考文档承载逆向扫描协议（分轮切分、证据采集与置信标注）、产物模板与证据格式、增量对齐协议。可在任意 git 仓库运行，不要求 check.sh 已存在；入口前置只查 git 仓库与技能自身文件完整。

**逆向产物形态（FR-2、FR-4）**：五路落点，全部与本套件既有产物模板同构，靠"形态兼容"换 check.sh 零改动——

1. 逆向 need（业务规则与系统边界）：落目标仓库 docs/needs/，编号接目录内最大号 +1（空目录从 0001 起），need 模板七节齐备；「系统能力需求」节列逆向出的业务规则 FR-N，「开放问题」节收扫描推断不了、须仓库主人补答的问题。落盘即 status: reconstructed。
2. 逆向 spec（系统行为与模块职责）：落 docs/specs/，spec 模板八节齐备，need 字段指向对应逆向 need——孤儿 FR 校验照常生效，迫使行为断言覆盖全部逆向业务规则；「验收场景」条目保留 [FR-N | 工单级 / 集成级] 标签，语义复用为"单模块内可对照证据核验 / 跨模块协作行为"。落盘即 status: reconstructed。
3. 逆向 ADR（历史决策候选）：落 docs/adr/，status: accepted——描述的是当前在生效的决策，既有 adr 状态机（accepted / superseded）零扩展。
4. 折叠内容：AGENTS.md 哨兵块外追加项目速览段（架构一句话、入口位置、各沉淀物索引），不动哨兵块与既有内容；GLOSSARY 项目术语章按既有格式追加领域术语；docs/standards/ 落逆向编码标准文件并在 CODING_STANDARDS.md 索引登记。已接入仓库同名标准文件与同名术语不覆盖，报告冲突交用户处置（setup-workspace 同名不覆盖先例）。
5. 每张逆向产物带「扫描基线」节：commit SHA、扫描日期、已覆盖范围、未覆盖范围、一句声明"未覆盖区不得读成不存在"。此节为逆向产物专属附加节——validate 只查必填节不排新增节，零改动兼容。

**证据与置信纪律（FR-3）**：每条行为断言句末带统一格式的证据引用（相对路径:行号），多处证据并列可写；查无证据的推断不得写成断言——要么补扫取证，要么显式标低置信 + 一句理由 + 补证路径，要么移入「开放问题」。证据格式全文统一可 grep，为增量对齐的漂移定位提供机械抓手。

**确认与落盘（FR-6）**：扫描全程只读，产物先以草案呈报——逐张列产物要点、关键断言、证据抽样、低置信清单、未覆盖区——用户显式确认后才写入，不确认不落盘（E2）。落盘两路：无 check.sh 的仓库先按 setup-workspace 全流程执行接入（含其决策点），随后写入逆向产物，一次会话完成（D2）；已接入仓库仅写入逆向产物，不重跑接入。技能本身不做 git 提交，落盘后报告提示仓库主人自行提交（纯文档改动适用 [trivial] 豁免）——同 setup-workspace 家族先例。

**增量对齐（FR-7、D3）**：重跑时先读逆向产物的扫描基线 commit，取基线 commit 到 HEAD 的变更文件集；按证据引用把存量断言分为涉漂移与未涉漂移两组，只重验涉漂移断言（证据失效则重取证或与用户确认后标过时），新增文件产出增量断言草案；全部更新走同一确认门后合并写入，不推倒未漂移部分；完成后逐张更新扫描基线为新 commit。基线缺失（如手写产物）回落全量扫描。

**分轮协议（FR-5、A3 轮次切分依据）**：切分依据 = 顶层模块边界（monorepo 按子项目，单仓按目录子树或分层），入口优先——构建入口、路由注册、schema 定义先扫，被引用多的模块次之；每轮以"可独立确认的一组沉淀物"为界收口一次确认；轮末更新基线的覆盖与未覆盖清单；用户可对未覆盖区发起补扫，补扫 = 带范围参数的重跑，在增量对齐协议下只动该范围（E1）。

**check.sh 状态机表扩展（D1、非目标 3 边界内）**：状态机表 need 行与 spec 行各追加 `reconstructed` 一个合法值——check.sh 唯一改动处。其余全部零改动且行为可推：frontier 只读工单不受影响；phase 原样显示新状态；done 残留门禁不触发（reconstructed ≠ done）；孤儿 FR 校验对逆向 spec 照常生效。改动落在活本，与 setup-workspace 生成资产整文件复制同步。

**蓝图与清单同步**：蓝图（唯一设计真相源，治理规则"先改本文档再改技能"）新增 setup-reconstruct 规格节（§11.18）、技能总清单 21 → 22、版本修订记录一条；README 技能表 setup-\* 区加一行。METHOD.md 与 GLOSSARY 活本零改动（METHOD 不列技能清单；逆向产物 / 扫描基线两词条 need 阶段已登记）。

**A1 论证（蒸馏与逆向双轨互不污染）**：正向开发在已逆向仓库上照常开新 need/spec（正常状态机），dev-accept 蒸馏只折回正向产物——逆向产物不在 frontier 与待办语义内，蒸馏永不触碰，两轨天然分离；逆向产物的时效由扫描基线显性化（对应哪个 commit、多旧），重扫触发时机 = 用户手动按需（非目标 4），重跑即增量对齐，错误知识不被静默固化——漂移可见、更新过确认门。

## 测试决策

- seam 1：状态机表扩展——run-tests.sh 的 new_repo 夹具喂 reconstructed 状态的 need 与 spec 文件：断言 validate 通过；逆向 spec 带 need 字段时孤儿 FR 规则照常生效（覆盖齐 → 通过，缺 → 报孤儿 FR）；reconstructed 不触发 done 残留门禁；frontier 输出不受逆向产物影响。
- seam 2：check.sh 双份逐字一致 diff 断言——补当前缺失的"活本 vs 生成资产"断言（双份同步标准第 1 条的存量缺口）；按第 2 条先观察红（改活本未同步时断言失败），整文件复制同步后转绿。
- seam 3：setup-reconstruct 主文档文本契约（dev-accept 先例）——断言主文档含关键词：reconstructed 状态、证据格式、确认前置（未确认不落盘）、两路落盘判定（接入与否）、扫描基线节、增量对齐协议，防技能文档漂移。
- 既有用例基线不降：publish 组、git hook 端到端组、双份 METHOD/GLOSSARY diff 组原样通过。
- 真实存量仓库的完整扫描、确认、落盘流程不进自动化（集成级留验收阶段，L4 hook / 蒸馏清扫先例）。

## 验收场景

- [FR-1 | 工单级] Given 一个无 check.sh 的 git 仓库，When 运行 setup-reconstruct，Then 技能正常进入扫描流程（不因流程资产缺失拒绝），扫描阶段源码与用户文件零改动。
- [FR-2 | 工单级] Given 扫描草案获用户确认、目标仓库未接入流程，When 落盘，Then check.sh 等接入资产齐全，逆向 need/spec/ADR 各自通过 validate 且 need/spec 状态为 reconstructed。
- [FR-2 | 工单级] Given 目标仓库已接入流程，When 落盘逆向产物，Then 仅新增逆向产物与折叠内容，接入资产逐字不变；既有同名标准文件与同名术语不被覆盖。
- [FR-3 | 工单级] Given 已落盘的逆向产物，When 逐条抽取行为断言的证据引用，Then 每条断言带至少一处 文件:行 引用且指向真实存在的文件与行；低置信推断带显式标注与理由。
- [FR-4 | 工单级] Given 一轮完整扫描落盘完成，When 盘点五路落点，Then 架构与历史决策有逆向 ADR、领域术语进 GLOSSARY 项目术语章、编码标准进 docs/standards/ 且 CODING_STANDARDS.md 索引登记、业务规则与系统行为有逆向 need/spec、AGENTS.md 哨兵块外有项目速览段。
- [FR-5 | 工单级] Given 分轮扫描落盘完成，When 读任一逆向产物的扫描基线节，Then 含 commit SHA、扫描日期、已覆盖范围、未覆盖范围及"未覆盖区不得读成不存在"声明。
- [FR-5 | 工单级] Given 仓库过大单轮未扫完（E1），When 用户对基线标注的未覆盖区发起补扫，Then 补扫只产出该范围的增量产物并更新基线覆盖清单，已确认的存量产物不被重写。
- [FR-6 | 工单级] Given 扫描草案未获用户确认（E2），When 会话结束，Then 目标仓库零新增文件、零改动。
- [FR-7 | 工单级] Given 已落盘产物、扫描基线 commit 之后代码改动了 2 个被断言引用的文件并新增 1 个文件，When 重跑扫描并确认，Then 仅涉漂移断言被重验或更新、新文件产出增量断言、未涉漂移的产物内容逐字不变、全部产物的扫描基线更新为新 commit。
- [FR-2、FR-3、FR-5 | 集成级] Given 一个真实存量仓库完成扫描确认落盘，When 新开 agent 会话只读沉淀物回答项目架构、术语、标准与业务规则问题，Then 无需全量扫描即回答正确，且抽查断言的证据可回溯（S1、S2 核销）。（留验收阶段）
- [FR-1 | 集成级] Given 真实未接入仓库，When 一次会话内完成接入、扫描、确认、落盘，Then check.sh phase 与 frontier 正常输出，逆向产物 validate 全库通过。（留验收阶段）

## 非目标

- 不进 sdlc next-mode 路由表，不加路由行，不自动串联（D4，仿 dev-docs 定位）。
- check.sh 除状态机表 need/spec 两行追加 reconstructed 外零改动：不改 validate 结构校验，不为证据引用加机械校验，不动门禁与 publish（D4）。
- 不改正向流程技能（dev-clarify / dev-spec / dev-plan / dev-implement / dev-review / dev-ship / dev-accept）行为；蒸馏永不触碰 reconstructed 产物。
- 不迁移外来技能套件（matt / superpower）产物——need 0007 范围。
- 不做自动漂移检测与定时重扫——重扫一律用户手动触发（非目标 4 推论）。
- 不做跨仓库聚合扫描与多仓统一工作区（另立项）。
- METHOD.md 与 GLOSSARY 活本零改动。
