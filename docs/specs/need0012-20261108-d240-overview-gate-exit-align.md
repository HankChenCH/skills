# round 3：出口触发口径对齐门禁（D3）+ reviewed 总览遇补票回置走查

## 问题陈述

round 2（spec 20261108-c196，验收 passed 2026-11-08）交付的 plan 出口自动衔接在真实演练中被隔离验收代理探出两个语义空白（验收报告 20261108-4fe6 残余风险 R1/R2，用户拍板开本轮）：

1. **出口触发口径 ≠ 门禁口径（R1）**：dev-plan §4.4 出口按"名下 **ready** 票数"统计是否链式调 dev-overview；开工门禁 `check.sh ticket`（overview_gate）按拍板 D3 原文按"名下**全部**票数"判定。补票情形（单票 spec 首票开工转 in-progress 后补出第二票）实测：出口统计 ready=1 判"单票"不调 dev-overview，但新票开工与在办票重入均被门禁拦（"名下 2 张票，缺 reviewed 总览"）——出口承诺的豁免不成立，用户被意外拦下需手动 /dev-overview 恢复。门禁偏严无误放，但出口指路与门禁要求脱节。
2. **reviewed 总览遇补票落空（R2）**：dev-overview §1.4 重入分支只认 draft 总览。reviewed 之后补票，链式/手动进入按文本落到**新合成**（同一 spec 出现第二份总览）；若用户推迟走查，门禁按"存在 reviewed 总览"放行，而该总览不含补票（矩阵票号列出现 0 次）——推迟走查支线上补票可不经走查开工，绕开 need 0012 立项核心（走查在开工前暴露形状错误）。

## 方案

全部在技能文本层对齐，门禁本体（check.sh overview_gate）、METHOD、产物契约、状态机零改动：

1. **出口触发口径对齐（FR-1）**：dev-plan §4.4 出口统计口径从"名下 ready 票数"改为"名下**全部**票数"（与 overview_gate 同口径，即拍板 D3 原文"名下工单 ≥2"）。单票豁免语义不变（名下恰 1 张票、任意状态 → 不调用）。dev-plan description 已是"名下票 ≥2"表述，核对不动；蓝图 v1.31 修订记录与 §11.5 出口行同批把"ready 票数 ≥2"成文改为"名下全部票数 ≥2"（dual-copy-assets 同批枚举纪律）。dev-overview 免点名入口与 §1.3 前置校验（≥1 票 ready）不动——链式进入时至少有一张待开工的 ready 票，前置恒满足。
2. **reviewed 遇补票回置走查（FR-2）**：dev-overview §1.4 重入分支扩展——进入时发现既有总览 `status: reviewed` 且名下票集超出总览覆盖（§4.1 矩阵-票集核对存在指不回的新票）→ **不重新合成**，把既有总览回置 draft（frontmatter 翻转并注明补票回置缘由），从 §4 走查续接：先更新产物（回 dev-spec/回 dev-plan/非目标三路照旧），再按 §4.1 更新矩阵票号列（先票在盘再动格子），差距清单清零后经**用户显式确认**重新置 reviewed。回置 draft 期间门禁照旧拦截（≥2 票 spec 无 reviewed 总览）——推迟走查的绕行通道被关闭：补票后必须重走查才能开工新票。既有 draft 分支、手动点名路径、免点名链式路径行为不变。

## 用户故事

- 作为需求人，我在单票 spec 开工后补票时，plan 出口会自动把总览补齐的路径摆到我面前（链式调起或指路续接），而不是等我在开工入口撞门禁才发现要手动跑 /dev-overview。
- 作为评审人，补票之后总览不会再出现"两份总览、reviewed 那份不认识新票"的状态——要么单一总览随补票回置 draft 等我重走查，要么我在走查里把新票指回矩阵后重新拍板。
- 作为流程维护者，两处对齐都只动技能文本：门禁判定与阈值（≥2、单票豁免）保持 round 1 以来的单一出处，不出现第二份门禁逻辑。

## 实现决策

- **dev-plan 出口口径（FR-1）**：§4.4 第 4 步统计句改为统计本 spec 名下**全部票数**（docs/tickets/ 中 `spec: NNNN` 指向本 spec 的工单，不分状态），≥2 → 链式调用 dev-overview（携带本轮 spec 编号），单票 → 不调用。其余衔接语义（合成走查归置结束后回 frontier 与开工点名、推迟走查/中断指路、未安装兜底）零改动。蓝图 v1.31 修订记录 + §8 dev-plan 出口 cell + §11.5 出口行同批成文。
- **dev-overview 补票回置（FR-2）**：§1.4 重入分支从"只认 draft"扩展为两支：① 既有 draft → 照旧从 §4 续接；② 既有 reviewed 且 §4.1 核对发现指不回的新票 → 回置 draft（注明缘由）后从 §4 续接；③ 既有 reviewed 且核对全覆盖 → 无补票发生，总览不动（不回置、不重合成），直接告知已 reviewed 即可。回置动作本身不需显式确认（降级方向安全）；重新置 reviewed 沿用显式确认门（沉默不算）。矩阵更新次序守 §4 既有"先产物后总览格"。
- **check.sh 与 METHOD 零改动**：门禁计数口径、单票豁免、阈值 ≥2、总览状态机（draft→reviewed）均不动——本轮是把技能层编排口径对齐到门禁既有的 D3 口径，不是改门禁。

## 测试决策

- seam ①（FR-1）：真实 spec 演练复现 R1 情形——单票 spec 首票开工（豁免放行）→ 置 in-progress → 补第二票 → dev-plan 重入续拆走到出口 → 统计全部票数=2 → 自动链式调起 dev-overview（round 2 验收 R1 的拦截情形转绿）。
- seam ②（FR-2）：reviewed 总览遇补票演练——链式/手动进入 → 不重复合成（总览文件数不变、正文指纹除矩阵格与 frontmatter 外不变）→ 回置 draft 缘由注明 → 矩阵票号列更新指回新票 → 显式确认重新 reviewed；推迟走查时门禁拦（draft 态 exit 1）；全覆盖情形（无补票）总览不动。
