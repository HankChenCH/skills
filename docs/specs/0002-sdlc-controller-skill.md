# sdlc 总控技能（只读调度 + next 模式 + 上下文水位线）

## 问题陈述

流程技能各自为政时，"现在该做什么""下一步""项目进展"没有统一入口，用户只能逐个产物翻状态；手动推进流水线靠会话记忆，容易绕过门禁或凭记忆推进（AGENTS.md 哨兵块第 4 条所指的风险）；下一步动作与盘上状态的对应关系（路由）没有任何文档承载——METHOD.md 生成自蓝图 §2–§6，不含 §8 自动化契约与决策点表；此外 next 模式连续调用技能会持续吃上下文，上下文过满时模型表现下降，在跌出"聪明区"前没有收口机制。

## 方案

新增第 2 个流程技能 sdlc（蓝图 §10.1 清单位次），三件事：

1. **默认模式（只读盘点）**：调 `check.sh phase` + `frontier`，按固定四段结构报告——当前阶段 / 可做的事 / 被挡在哪 / 循环状态（轮次、残余风险）。
2. **next 模式（自动推进）**：按优先级路由表（盘上状态 → 下一个该调用的技能 → 停在哪）确定目标技能，用 Skill 工具调用，推进到下一个决策点即停；多张 ready 工单问询（带默认建议）；目标技能未安装报断链并指路。
3. **上下文 token 水位线**：每次调用目标技能前评估会话上下文 token 用量占窗口百分比——绿 <30% 正常推进、黄 30%–50% 只推进单阶段且出口不自动串联、红 ≥50% 停止推进并建议新会话从盘上续接（档位为用户 2026-10-27 定档）。

- **FR-1**：默认模式产出四段结构盘点报告，全程零写盘。
- **FR-2**：next 模式按路由表把流水线推进到下一个决策点，断链可指路。
- **FR-3**：next 模式调用目标技能前完成水位定档，黄/红档按档位收窄或拦停并给出带默认建议的话术。

## 用户故事

- 作为仓库主人，我想随时问"现在该做什么"并得到以盘上状态为准的盘点，以便不凭记忆推进流程。
- 作为仓库主人，我想说"继续推进"就让流水线自动走到下一个需要我决策的点，以便重复劳动归流水线、我只管决策。
- 作为仓库主人，我想让自动推进在上下文过满前主动收口，以便模型始终在聪明区内工作、续接交给盘上状态。

## 实现决策

- **只读铁律**：总控不写产物、不改状态，状态变更只由对应 dev-* 技能执行；只读性可被 `git status` 机械验证。
- **知识落点**：路由表落技能 `references/next-mode.md`、水位线落 `references/context-watermark.md`，进入 next 模式才按需加载（§13.1 附件规范）——METHOD.md 不含 §8 契约，路由与水位知识必须随技能自带。
- **治理顺序**：先改蓝图（v1.3：§11.2 操作化 + 修订记录）再写技能；SKILL.md 只留控制流（56 行）。
- **断链处理**：目标技能不在可用列表 → 报告"流程走到 dev-X，该技能未实现"，指路蓝图批次或 METHOD.md 手动推进，禁止越权代劳写入。

## 测试决策

- seam：`.sdlc/check.sh phase/frontier` 的输出；技能入口的 `.sdlc/check.sh` 存在性检查。
- 按蓝图 §13.2 执行六项自测（触发/拒绝/重入/产物校验/衔接/水位线）；只读性以 `git status` 前后 diff 为证据；衔接以本仓库真实状态（3 票 implemented 且被 approved 评审覆盖 → 路由 dev-ship → 断链）实测。

## 验收场景

- [FR-1 | 工单级] Given 已接入工作区，When 运行默认模式，Then 报告含当前阶段/可做的事/被挡在哪/循环状态四段且一切以 check.sh 输出为准。
- [FR-1 | 工单级] Given 无 `.sdlc/check.sh` 的 git 仓库，When 进入技能，Then 停止并指路 /setup-workspace，不做盘点。
- [FR-2 | 工单级] Given 本仓库 3 票 implemented 且全被 approved 评审覆盖，When next 模式路由，Then 命中 dev-ship 并如实报断链（该技能未实现），无越权写入。
- [FR-3 | 工单级] Given 会话上下文用量落入黄/红档，When next 模式推进前评估，Then 输出含用量、档位、本轮边界三要素且默认建议放第一项；红档不调用任何技能。

## 非目标

不实现 dev-ship / dev-accept / dev-spec / dev-plan / dev-implement 等其余批 1–3 技能；不改 `.sdlc/check.sh` 门禁逻辑；不做 tracker 适配器；不为默认模式加水位门（默认模式零写入，无推进风险）。
