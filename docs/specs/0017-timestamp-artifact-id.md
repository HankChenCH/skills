# 时间戳派生产物编号与谱系前缀

## 问题陈述

产物编号现行规则是「每类独立、从 0001 起、取目录内最大号 +1」。过程档（ticket /
review / acceptance / overview）验收后随蒸馏清扫删除，目录最大号回落，新产物把历史号
重新分配——票 0024 已双生（issue #87 与 #118）、acceptance 0001 已复用 9 次。审计链
主承载是 tracker 投影与提交 `[#NNNN]` 引用，号复用使 git 历史引用无法定位唯一工单，
工票 blocked-by 按号查票会查到复用后的另一张票。同时「读目录→写文件」两步无原子性，
且过程档被 gitignore、git 拦不住同名冲突，多个会话并发开 spec / 开票会取到同一个号。

## 方案

产物号改为**时间戳派生 ID**：`YYYYMMDD-4位小写十六进制随机段`（如 `20261104-b7c1`）。
号不依赖目录现存文件或 tracker map 推导，唯一性由「原子创建产物文件占号 + 撞号重掷
随机段」保证，多会话并发与清扫后不复用由机制本身成立，无需中央计数器。

取号收敛为**单一原子入口**：一次调用完成「生成候选号 → 以排他创建（O_EXCL / noclobber）
落占位文件 → 撞号则重掷重试 → 返回最终产物文件名」。占位文件随即由调用会话写入正文
（同路径覆盖写，不释放占位）。九个产物技能（clarify / spec / plan / fix / review /
accept / overview / research / retro）的「目录内最大号 +1」内联规则全部替换为调用该入口。

**谱系前缀**：凡父产物为知识档（永不清扫）的取号，文件名一律带父产物号前缀——
`<父类型><父ID>-<本产物ID>-slug.md`，如 spec `20261030-k3p9` 派生工票
`spec20261030-k3p9-20261104-b7c1-slug.md`。父为过程档的（评审挂票）不带前缀，
避免指向将被清扫的号；谱系权威记录仍是产物 frontmatter 字段，文件名前缀是可读投影。

**双格式过渡**：check.sh 门禁与定位同时接受旧四位纯数字号与新 ID 格式；在途旧格式
产物（当前盘上 tickets 0019–0023 及全部未清知识档）按旧格式走完生命周期，不回改。

**旧账处置（need 0014 D2 拍板）**：tracker map 末尾追加「历史号复用消歧」注释段
（双 0024 的两个 issue 链接、九个 acceptance 0001 的对应关系），不改既有行。

## 用户故事

1. 作为并发开票的会话，我想要取号入口一次原子调用返回唯一号，以便不与任何其他会话
   协调也不撞号。
2. 作为并发开 spec 的会话，我想要同样的原子取号覆盖知识档，以便两会话同时开 spec
   也不撞号。
3. 作为实现技能，我想要按号定位产物的入口同时识别新旧两种格式，以便在途旧票走完
   生命周期期间引用不断链。
4. 作为提交门禁，我想要校验新格式工单引用（`[#20261104-b7c1]`）并继续放行旧格式
   在途引用，以便过渡期双格式提交都可通过。
5. 作为派生工票的会话，我想要票号携带父 spec 号前缀，以便按号读出归属谱系。
6. 作为审计读者，我想要 map 里的历史号复用歧义有一段消歧注记，以便不翻对话就能
   分清双 0024 与九个 0001 各指哪个平台对象。
7. 作为流程维护者，我想要九个技能文档不再各自内联取号规则，以便规则只有一处定义、
   不再漂移。

## 实现决策

1. **号格式契约**：`YYYYMMDD-4位小写hex`，即 8 位日期 + 连字符 + 4 位随机段；
   frontmatter `id` 字段取该 ID 段（不含父前缀），文件名为
   `[父类型+父ID-]id-slug.md`，validate 校验 id 与文件名 ID 段一致。
2. **原子占号**：取号入口以排他创建落占位文件占号，EEXIST 即重掷随机段重试；
   排他创建是唯一并发控制原语，不引入中央计数器、不引入锁目录。
3. **取号入口归属**：作为 check.sh 新子命令实现（生成、占号、重试、返回文件名
   一次完成）；九个技能文档改为调用该入口，删除全部「目录内最大号 +1」内联规则。
   随机源用系统熵源，不自制伪随机。
4. **前缀规则**：父产物为知识档（need/spec/design/adr/research/standards）的取号
   必带前缀（覆盖 ticket←spec、overview←spec、acceptance←spec）；父为过程档的取号
   不带前缀（review←ticket）；前缀由取号入口按调用参数拼装，技能不手工拼文件名。
5. **双格式定位**：产物定位入口先按新 ID 格式匹配（含前缀文件名），未命中再按旧
   四位纯数字匹配；两条路径都保留至旧格式在途产物自然清零，移除时点为后续决策
   （本轮非目标）。
6. **提交引用格式**：新格式 `[#YYYYMMDD-4hex]`；commit-msg 门禁同时接受新格式与
   旧 `[#NNNN]`，状态校验逻辑不变；Merge/Revert 机械放行不变。
7. **tracker 投影**：适配器按文件路径投影，map 以路径为键，对号格式天然无感知；
   仅校验文件名格式处（若存在）扩展双格式正则。
8. **消歧注记**：map 以注释行追加历史复用对照段；map 既有三字段数据行不动。
9. **演练形态**：模拟仓 = 系统临时目录新建的 git 仓库（不进本仓库），子代理模拟
   多个并发会话同时调用取号入口开 spec 与开票，断言零重号；演练记录落
   docs/acceptance/（自身按新格式 + spec 前缀命名，即吃自己的狗粮）。
10. **同步路径**：九个技能文档改仓库源后经既有镜像同步机制落安装位，与本仓库内
    其他文档变更同一提交原子完成。

## 测试决策

- **seam：check.sh 子命令级**。既有先例：check.sh 各子命令（ticket / commit-msg /
  validate）以 bash 函数为 seam 直接断言行为。本轮新增子命令沿用同一 seam：
  并发占号（多次调用断言全异）、撞号重试（预置同名占位文件断言重掷）、双格式定位、
  门禁引用格式。
- **seam：模拟仓端到端**。演练脚本在临时目录建仓、并发调用取号、断言零重号；
  该 seam 同时是 FR-5 的验收载体。
- 既有同类测试先例：spec 0012 的并发行为验证走演练留痕 + 子命令级断言，本轮沿用。

## 验收场景

- [FR-1 | 工单级] Given 一类产物目录被清空（模拟清扫后状态）When 会话取号新产物
  Then 返回的号不与该类任何历史号（tracker map 已记录号、git 历史引用号）相同。
- [FR-1 | 工单级] Given 取号入口被调用 When 生成号 Then 号形如
  `YYYYMMDD-4位小写hex`，与目录现存文件、map 内容无推导关系（目录与 map 不变时
  两次取号结果不同即证）。
- [FR-2 | 工单级] Given 同一仓库同一时刻并发调用取号入口 N 次（模拟多会话）When
  全部返回 Then N 个号两两互异，无人工协调步骤。
- [FR-2 | 工单级] Given 候选号对应的占位文件已存在（撞号）When 取号入口执行 Then
  重掷随机段并成功返回新号，不报错停机。
- [FR-3 | 工单级] Given 父产物为 spec 的取号调用 When 生成工票文件名 Then 文件名
  形如 `spec<父ID>-<本ID>-slug.md`，frontmatter 谱系字段与文件名前缀一致。
- [FR-3 | 工单级] Given 父产物为工票（过程档）的取号调用 When 生成评审文件名 Then
  文件名不带父前缀。
- [FR-4 | 工单级] Given 提交信息带新格式引用 `[#20261104-b7c1]` When commit-msg
  门禁校验 Then 按新格式定位工单并校验状态，通过。
- [FR-4 | 工单级] Given 提交信息带旧格式引用 `[#0023]`（在途票）When commit-msg
  门禁校验 Then 双格式定位命中在途工单，通过。
- [FR-4 | 集成级] Given map 已追加历史消歧注记 When 审计读者按注记对照双 0024
  与九个 0001 Then 每个历史号都能定位到唯一平台对象链接。
- [FR-5 | 集成级] Given 模拟仓中子代理模拟 ≥3 个并发会话同时取号（含开 spec 与
  开票）When 演练执行完毕 Then 全部产物号两两互异、零重号、零人工协调，演练记录
  落盘 docs/acceptance/ 且自身符合新命名格式。
- [FR-1 | 集成级] Given 九个产物技能文档 When 逐个检查取号规则 Then 全部改为调用
  单一取号入口，无任何「目录内最大号 +1」残留。

## 非目标

- 不回改任何历史产物号、不重写 git 历史（need 0014 非目标）。
- 不移除旧四位格式的门禁支持（待旧格式在途产物自然清零后另行决策）。
- 不做跨仓库全局唯一号空间（need 0014 非目标；前缀加仓标识可作未来扩展）。
- 不改产物分档与蒸馏清扫语义（ADR 0001/0002 维持现状，本变更只换号格式）。
- tracker 平台侧（issue 编号体系）不做任何变更，投影单向性维持。
