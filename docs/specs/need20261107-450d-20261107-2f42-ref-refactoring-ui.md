# ref-refactoring-ui 参考技能（Refactoring UI 九章蒸馏 + 设计链挂载）

## 问题陈述

design-* 链缺一份通用视觉设计章法的参考：design-baseline 引导产出基线分册、design-ui 产出布局与视觉决策时，配色起步、间距阶梯、层级营造这些决策靠模型通用知识，无本仓库内方法论可载。need 20261107-450d 已拍板：以蒸馏形态（不含原文与图片，规避对无授权译文的再分发）从翻译仓库 01～09 章构建 ref-refactoring-ui 技能，挂载进设计链。

## 方案

按 ref-* 家族两级结构建技能：`SKILL.md`（总标准 + 任务路由 + 版权留痕）+ `references/` 九分册（与原书 9 章一一对应，蒸馏规则 + 正反例文字描述）；design-baseline 与 design-ui 的 frontmatter description 各追加挂载语；新术语登记 GLOSSARY。round 1 全量覆盖 need 全部 8 条 FR（用户未在分轮问询中应答，按推荐圈法起草：产物 ≤10 文件体量小，A2 忠实度风险不靠分轮摊，写进 FR-3 验收抽样对照消化——本圈法随本 spec 批准一并生效）。

- **FR-1**：`skills/ref-refactoring-ui/` 技能——SKILL.md 与 references/ 九分册；`~/.zcode/skills/ref-refactoring-ui` 符号链接指向仓库技能目录（与既有 ref-* 同法）。
- **FR-2**：九分册与原书 9 章一一对应——文件名英文短横线体（start-from-ephemeral / hierarchy / layout-spacing / typography / color / depth / images / finishing / advancing），册首注明对应原章序号与原章名（如"← 原书 02 层级就是一切"）。
- **FR-3**：分册内容为蒸馏规则——每条规则可执行、标注来源原章，配正/反例文字描述（不用图片、不贴原文段落）；每册抽 2 条规则可对照快照原文指回原章小节。
- **FR-4**：SKILL.md 任务路由——路由表按"你现在要做什么"的信号行覆盖九册，声明"一次只载一个"；写明适用边界：仅图形界面（Web/移动端/桌面端），CLI 与文档视觉不适用。
- **FR-5**：SKILL.md 来源留痕——翻译仓库 URL（github.com/read-x/refactoring-ui-zh）、内容快照 commit `ec3aa73`、版权声明（译文与图片版权归原书作者、不授许可，本技能为蒸馏不载原文与图片）。
- **FR-6**：设计链挂载——design-baseline / design-ui 两 SKILL.md 的 frontmatter description 各追加「加载 ref-refactoring-ui」挂载语，且两文件正文各补一条 ref-refactoring-ui 装载动作行（照 design-ui 正文既有 ref-writing 装载行先例，置于装载上下文/设计纪律节）——装载指令只写 description 时技能装载后执行者不可见，挂载在执行链路不可达；docs/sdlc-skills-blueprint.md §7.2 引用矩阵补 design-baseline / design-ui → ref-refactoring-ui 装载行；两文件除上述行外内容不动。
- **FR-7**：体量对齐家风——SKILL.md ≤ 60 行（ref-testing 先例 45 行），每分册 ≤ 80 行（ref-testing 分册先例 49–60 行）。
- **FR-8**：术语登记——蒸馏引入的新术语（预计 2–4 条，如视觉层级、间距阶梯）登记 GLOSSARY 项目术语章，注明首次出现位置。

## 用户故事

- 作为设计执行会话（design-baseline / design-ui 内），我想要按当前任务只载入对应的那一册设计细则，以便上下文只为正在做的设计决策付税。
- 作为仓库主人，我想要每条规则标注来源章并配正反例，以便设计决策能指回规则、差例的识别信号可以直接进评审。
- 作为仓库主人，我想要 SKILL.md 记录来源与快照 commit，以便内容有出处可查证、版权边界成文可审计。
- 作为仓库主人，我想要技能内零原文零图片，以便本仓库推公开 GitHub 不构成对原书内容的再分发。

## 实现决策

- **两级结构沿用家族先例**（spec 0003 / ref-testing）：SKILL.md 只留总标准与路由，细则按任务拆分册、按需一次载一册——技能全文每次进上下文是每个会话的税。
- **分册统一骨架**：册首行 = 标题 + 对应原章注记；开场两三句 = 本章解决什么问题；规则列表 = 每条"规则 + 正/反例文字描述 + 来源注记"；册尾自查口令。规则为改写的祈使句，不转录原文。
- **路由表信号行设计**：以"你现在要做什么"描述任务信号（建基线起稿 / 出布局 / 选配色 / 定文字阶梯 / 用图片 / 营造层次 / 收尾打磨 / 从零起界面 / 继续进阶），两可时按最贴近当前产物形态的册选。
- **不独立响应条款**：description 声明内部参考身份——不响应独立的界面设计请求，用户直接要求设计界面时转 design-brief → design-ui 链（对齐 ref-writing / ref-testing 的同款条款）。
- **来源内容获取**：实现时从翻译仓库按快照 commit `ec3aa73` 拉取 01～09 章 raw 文件作蒸馏输入；蒸馏输入与对照均锚定同一 commit，验收可复现。
- **术语登记**：仅登记本技能首次引入且跨册复用的设计术语；原书专名（如"强调策略"）沿用译文仓库术语表（docs/翻译规范与术语表.md）的定名，登记时注明出处。
- **双份资产同步豁免**：GLOSSARY.md 为双份同步资产，本 spec 涉其改动时 `skills/setup-workspace/assets/GLOSSARY.md` 副本按 dual-copy-assets 第 4 条整文件复制随改，改动面视同 GLOSSARY.md 本体（spec 0015 同款先例）。
- **家族枚举同批改**：ref-refactoring-ui 入册 ref-* 内部参考家族时，README 参考层、docs/concepts.md 内部参考条目、蓝图 §7.2 引用矩阵按 dual-copy-assets #5 枚举同批改纪律同步更新（评审 20261107-36a7 阻断 2 的落地口径）。

## 测试决策

- seam：`.sdlc/check.sh validate`（spec/ticket 模板校验）、`wc -l`（行数硬校验）、grep（挂载语、来源留痕、原章注记、GLOSSARY 登记）、`ls`/`git ls-files`（references/ 恰九个 md、无图片文件）、符号链接可解析（`readlink`）。
- 对照型核验：FR-3 抽样对照按快照 commit 的 raw URL 拉原文，核对"规则可指回原章小节且为改写非转录"——每册 2 条。
- 运行时行为（design-ui 会话实际加载并引用规则）不由本 spec 自动化验证，以集成级场景人工核销一次（先例：spec 0003 将运行时验证留待消费者侧）。

## 验收场景

- [FR-1 | 工单级] Given skills/ref-refactoring-ui/，When 机械核验，Then SKILL.md 存在、references/ 恰含 9 个 .md 文件且无图片文件，`readlink ~/.zcode/skills/ref-refactoring-ui` 解析到仓库技能目录。
- [FR-2 | 工单级] Given references/ 九分册，When 逐册核对册首，Then 每册注明对应原章序号与原章名，九册与原书 01–09 一一对应无缺漏、无重复。
- [FR-3 | 工单级] Given 九分册与快照 `ec3aa73` 的原文，When 每册抽 2 条规则对照 raw 原文，Then 规则能指回原章对应小节且为改写规则而非原文转录；任一分册 grep 不到连续 ≥3 行的原文段落。
- [FR-4 | 工单级] Given SKILL.md，When 核对路由表与边界声明，Then 路由表覆盖九册（信号行 + 文件名）、声明"一次只载一个"、含"仅图形界面适用，CLI/文档视觉不适用"边界声明。
- [FR-5 | 工单级] Given SKILL.md，When 核对来源留痕段，Then 含翻译仓库 URL、快照 commit `ec3aa73`、版权声明三要素。
- [FR-6 | 工单级] Given design-baseline / design-ui 两 SKILL.md，When `git diff` 核对，Then 两文件各含 frontmatter description 一行变更（含「加载 ref-refactoring-ui」）且正文各新增一条 ref-refactoring-ui 装载动作行，除上述行外其余内容不变；docs/sdlc-skills-blueprint.md §7.2 含 design-baseline / design-ui → ref-refactoring-ui 装载行。
- [FR-6 | 集成级] Given 新开会话技能列表，When 查找并读 design-baseline / design-ui 的 description，Then ref-refactoring-ui 可被加载且两技能 description 含挂载语（人工在新会话核销一次）。
- [FR-7 | 工单级] Given 全部技能文件，When `wc -l`，Then SKILL.md ≤ 60 行、每分册 ≤ 80 行。
- [FR-8 | 工单级] Given GLOSSARY.md，When 核对项目术语章，Then 新术语已登记且注明首次出现位置（ref-refactoring-ui 技能某册）。

## 非目标

不嵌入原书译文段落与图片（need 决策卡 D1 + 版权约束）；不改 design-ui 五分册路由结构与 design-baseline 流程逻辑（仅挂载：description + 正文装载动作行 + 蓝图矩阵行）；不产出 docs/standards/ 项目设计基线分册（归 design-baseline）；不做原书翻译修正、勘误或补译；不自动验证 design-ui 会话的运行时加载行为（集成级人工核销）。
