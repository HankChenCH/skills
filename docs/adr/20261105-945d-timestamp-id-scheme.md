# 20261105-945d: 产物编号采用时间戳派生 ID 与单一原子取号入口

产物编号从「每类独立、目录内最大号 +1」切换为时间戳派生 ID（`YYYYMMDD-4hex`），
全部取号收敛到 check.sh 单一原子入口 `claim`（排他创建占号、撞号重掷、按父产物
参数拼装谱系前缀）。知识档父产物（need/spec/design/adr/research）派生的产物
文件名必带 `<父类型><父ID>-` 前缀；过程档父产物不带，避免指向将被清扫的号。
号唯一性由「排他创建 + 撞号重掷 + map/git 历史号双源查重」机制成立，无中央计数器、
无锁目录；多会话并发与清扫后号不复用由机制本身保证。

## 背景

旧规则「读目录 → 写文件」两步无原子性，且过程档被 `.gitignore` 排除、git 拦不住
同名冲突：多会话并发开 spec/开票会取到同一个号；过程档验收后随蒸馏清扫删除，
目录最大号回落，新产物把历史号重新分配（票 0024 双生、acceptance 0001 复用
9 次）。审计链主承载是 tracker 投影与提交 `[#NNNN]` 引用，号复用使引用无法
定位唯一工单。

## 备选与取舍

- **中央计数器 / 水位文件**：需要并发协调与额外状态，清扫时还要维护水位；
  否决——无中央状态、并发天然安全的方案成本更低。
- **提高时间戳精度或加长随机段**：撞号概率下降但文件名变长，且不消除竞态；
  否决——重掷成本近零（票 0038 实测 16 次重掷上限内恒收敛），文件名长度收益恒在。
- **纯随机 ID**：失去创建时序信息；否决——日期前缀零成本提供排序线索。

## 后果

- 新旧格式双轨过渡：check.sh 定位、文件名校验、commit-msg 门禁、tracker 适配器
  同时认 `NNNN` 与 `YYYYMMDD-4hex`；旧四位纪元止于存量产物，不移除时点另行决策
  （spec 0017 非目标）。
- 轻产物（retros / migrations）纳入同一取号机制但不入门禁（GLOSSARY 轻产物语义不变）。
- 跨仓库全局唯一号空间不做（need 0014 非目标）；如未来需要，前缀加仓标识即可扩展。
- 验证实证：4 个子代理会话并发取号 12 次（两组并行）零重号（验收报告
  spec0017-20261105-28bf）。
