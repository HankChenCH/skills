# dsh MCP 管理面 Dock 页界面设计约束

## 对象与输入

界面对象：dsh Web Client 内嵌的右栏 Dock 页「MCP Servers」管理面板（浏览器访问的管理控制台 → Web 对象分册，后台操作员画像）。来源：对话原话（「样式太丑且与 dsh 风格不统一」+ 四项现状痛点：信息层次乱、状态辨识差、操作路径不顺、与 dsh 风格脱节，2026-11-18 采集）+ spec 20261118-0de6 用户故事与验收场景。载体现状：`agents/dsh/plugins/dsh-mcp/client/`（已实现并验收 passed，本 brief 约束其美化规格的输入）。

## 角色清单

- **dsh web 使用者（开发者，后台操作员画像）**：管理自己 profile 的 MCP server——查状态、添加、行内编辑、启停、移除、失败重试；高频小操作、单列清单场景。（2026-11-18 用户拍板单角色，不细分重度/轻度）

## 角色约束

### dsh web 使用者（开发者，后台操作员）

**信息优先级**（痛点：状态辨识差、信息层次乱）：
1. 主信息 = server 健康度：连接状态是第一眼信息；异常行（failed / waiting-credentials）优先于正常行被看见——扫一眼即知哪些 server 有问题，无需逐行读。
2. 次信息 = 名称 + transport + 工具数：单行内扫得全，不与状态争视觉权重。
3. 可折叠/内联 = 失败原因线索（lastError）、凭据缺失提示：仅异常行展开呈现，不与主清单争空间。
4. 面板信息层级与 dsh Web Client 整体同构：外层会话为主、本面板为辅——面板内不抢会话区注意力。（假设：由操作员画像推得，请确认）

**密度要求**（痛点：信息层次乱）：
1. 侧栏面板中低密度、单列：面板常态高度下一屏可见 ≥5 条 server 行（典型用量 1–10 个 server，可核口径）。
2. 单行自足：名称/状态/工具数一行扫全，次信息不换行、不折叠。
3. 表单（添加/编辑）按需展开形态，不常驻占位。

**关键操作路径**（痛点：操作路径不顺）：
1. 最高频 = 查状态：打开 Dock 页 → 一眼扫全清单健康度（≤1 步，无下钻）。
2. 次高频 = 启停/重试：行内一步可达，不进二级页；动作后果可见（状态流转 connecting… → connected 等即时反馈）。移除为破坏性操作，可一次确认（假设：由操作风险推得，请确认）。
3. 添加：打开面板 → 提交 ≤3 步；transport 切换不换页、已填字段不丢。
4. 编辑：行内唤起、保存即生效（≤2 步）；凭据字段脱敏显示、不重输即保留（round 1 已实现语义，约束其视觉呈现不打断该语义）。

**跨切约束**（痛点：与 dsh 风格脱节）：
1. 面板视觉语言（配色、字体、控件形态、间距节奏）与 dsh 官方 Web Client 同基线——本约束只要求「同基线」，具体基线由 design-baseline 阶段从官方 Web Client 摸底产出；design-ui 按基线出规格。

## 假设

1. 「面板不抢会话区注意力」——由侧栏从属地位推得，未出自用户原话，请确认或移除。
2. 「移除可一次确认」——由破坏性操作风险推得（round 1 实现为直接移除），请确认或移除。
3. 「异常行优先被看见」的实现方式（排序置顶/高亮强度）归 design-ui，本 brief 只锁优先级要求。
