# 0001: design-* 链路看板——套件呈现物述标与 design 产物共产契约

## 界面设计

### 设计意图

给 design-* 套件（spec 0015）一个可述标的呈现页：验收方"听意图、看界面、提
意见"的载体。取**看板总览布局**承载评审读法——结论行先行（"四技能链已上线
3/4"）、每环节一张卡片、票号可溯（0033/0034/0035/0036）；取**线性精读布局**
承载首次上手读法——环节按链序 01–04 编号、每卡片一句话职责 + 产物落点、
空态直接给出起点（先跑 /design-brief）。四态原型让验收方当场看到三件说不清
的事：空仓时链路什么样（空态=引导起点）、扫描产物时的等待（加载态）、目录
未接入开发流程时怎么办（错误态给修复路径 /setup-workspace）。卡片可点击展开
明细，主流程不用解释即可点通。

### 角色约束

演练输入为简单 spec 0015 及其用户故事原话（无 brief 产物，约束来源标注如下）：

- **首次接触套件的调用方**（spec 用户故事："我想在脊柱三点被建议使用这套技能"）：
  信息优先级=链条全貌与起点；密度=一屏四卡片、每卡片 2–3 行；关键操作路径=
  看到 01 号卡片即知道从 /design-brief 进入。→ 满足：01–04 编号线性排列、
  结论行置顶、空态首行即起点指引。
- **评审/验收方**（spec 用户故事："我想读到设计意图说明并打开可评审的界面
  原型"）：信息优先级=各环节产物落点与状态、异常优先；密度=总览一屏、明细
  点击展开不挤占首屏；关键操作路径=对照票号核销（0033→brief、0034→baseline、
  0035→ui、0036→本页）。→ 满足：票号以辅助字号随卡片常显、错误态置独立
  面板且文字标注、明细按需展开。

### 风格跟随声明

全程跟随基线 docs/standards/design-docs.md，无偏离：配色逐值取自基线语义色板
（正文 #1F2328、主色 #0969DA、次要 #59636E、成功 #1A7F37、警示 #9A6700、
错误 #CF222E、边框 #D1D9E0、代码底 #F6F8FA），未引入表外色值；间距与字号用
套件默认阶梯（基线未收紧）；切换钮常驻视口顶部、当前态高亮、状态名文字+颜色
双编码照基线组件观感节；路径与票号用等宽、不用 emoji、暗色模式不出（基线
假设节口径）。基线假设节预告的"看板类页面多序列图表配色"未触发——本页不含
图表。

## 模块划分

> 本节及以下技术节由 dev-design 并存补写（Phase B，见节末注文）；「界面设计」
> 节归 design-deliver，互不覆盖。

- **dev-design（技术方案生产者）**：职责=技术节四节（模块划分/数据流/seam
  清单/ADR 索引）与 ADR 落盘；对外接口=design 产物 frontmatter 契约
  （id/spec/status/created，approved 时追加 approved）与 approved 门；
  依赖方向=读 spec 与 docs/adr/，不依赖 design-* 套件产物。
- **design-deliver（述标生产者）**：职责=「界面设计」节四小节与
  assets/&lt;design-id&gt;/ 原型定稿；对外接口=同一 frontmatter 契约与同一
  approved 门；依赖方向=读 brief/ui 产物与基线分册，不依赖技术节内容。
- **计数空间（共享资源）**：docs/designs/ 目录内 id 取最大号 +1，brief/ui/
  design 产物同池不重号；两个生产者取号面同为该目录，先落盘者占号。
- 依赖单向：design-deliver → ui 草稿 → brief 约束 → spec；dev-design →
  spec/adr。两生产者互不依赖对方节内容，只在 frontmatter 与 approved 门汇合。

## 数据流

一条典型路径（本产物自身即实例）：spec 0015 approved →（简单 spec，dev-design
判据不命中）design-deliver 直建产物「界面设计」节 + assets 原型，status: draft
→ 述标门第一次询问，沉默 → 保持 draft → 实现中暴露设计级问题（design 产物
双生产者契约，spec 0015 备注预期项）→ dev-design 回到同一产物续接补技术节
（draft 续接，不重起草）→ 述标门第二次询问，显式批准 → status: approved、
追加 approved 日期 → 指路 dev-plan。

状态与所有权：draft 由最后写入的生产者持有待审；approved 是共享终态，推进权
只在述标评审门（用户显式确认），任一生产者不替对方改节。
