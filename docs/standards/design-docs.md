# docs 设计语言基线

## 适用范围

本册约束本仓库的文档与看板呈现：GitHub 渲染的 Markdown（README、docs/ 全树、
GLOSSARY/METHOD 等规则文本）与 docs/designs/assets/ 下 HTML 原型的呈现层。
不约束源码内部实现样式（那归 CODING_STANDARDS 兜底基线的 ref-implementation）。
平台归属：本仓库无 Web 应用/移动端/桌面端界面，界面交付物全部是文档与看板呈现，
故按 design-ui 对象路由落 docs 分册。

## 配色

Markdown 正文不自定颜色——语义靠结构与文字承载（标题层级、列表、粗体），
颜色留给渲染器默认（链接蓝由 GitHub 渲染）。HTML 原型用以下语义色板
（白底 #FFFFFF 上的对比度经 WCAG 公式实算，全部 ≥4.5:1）：

| 语义 | 色值 | 白底对比度 |
|---|---|---|
| 正文 | #1F2328 | 15.80:1 |
| 链接/主色 | #0969DA | 5.19:1 |
| 次要文字 | #59636E | 6.11:1 |
| 成功 | #1A7F37 | 5.08:1 |
| 警示 | #9A6700 | 4.87:1 |
| 错误 | #CF222E | 5.36:1 |
| 边框 | #D1D9E0 | ——（非文字） |
| 代码底 | #F6F8FA | ——（非文字） |

状态不靠颜色单独区分：异常态同时用图标/文字标注（色弱可辨）。

## 字体

- 正文与标题：渲染器默认无衬线系统栈（GitHub 为 system-ui 栈），不引外部
  字体文件——原型零依赖纪律的同款口径。
- 代码、路径、命令、键位、文件名、编号：一律等宽（反引号或 `monospace` 栈），
  不用正文体冒充。
- 数字与正文同字体；表格内数值列右对齐，位数对齐靠等宽字体。

## 密度

- 段落 3–5 句；一句话能说清的不凑段。
- 列表条目 ≤2 行；超了拆嵌套或拆节。
- 表格 ≤6 列；单元格放短语与数值，不放长句段落。
- 一级文档一个 H1；节内标题层级最深到 H4；一节只讲一个主题，超了拆节。

## 间距与字号阶梯

- Markdown 排版随渲染器默认，不自定间距与字号。
- HTML 原型采用套件默认阶梯（与 design-ui 出口口径一致）：
  - 间距：4 / 8 / 12 / 16 / 24 / 32 / 48 px；
  - 字号：12 / 14 / 16 / 20 / 24 / 32 px——正文 ≥14px，12px 仅限标签、
    时间戳等非正文辅助信息；
  - 标题映射：H1 32 / H2 24 / H3 20 / H4 16；
  - 行高：正文 1.5，标题 1.3。
- 基线另有更严值从基线；本册未收紧，即默认阶梯全档可用。

## 组件观感

- **表格**：表头加粗、带分隔线；单元格短语化；一行一个事实。
- **代码块**：首行标注语言（```bash、```markdown），着色交给渲染器。
- **引用块**：一句结论 + 一行出处（路径、编号或链接），不拿引用块当正文段落。
- **强调**：全文一种手段为主（粗体）；"注意/警告"用前缀词表达，不靠彩色
  徽章与高亮混用。
- **HTML 原型**：四态（正常/空/加载/错误）切换钮常驻视口顶部、当前态高亮；
  状态名用文字+颜色双编码；单文件零依赖、≤200 行（design-ui 原型纪律）。

## 反例

1. 像默认 Bootstrap 的未定制观感——默认蓝按钮+灰白卡片直接充当门面页，
   没有经过本册配色与阶梯的决策。
2. 同一段落粗体+高亮+斜体叠加强调——手段混用，删到只剩一种。
3. 标题靠加粗混色冒充层级——层级只用字号阶梯表达。
4. 表格塞长句段落，一行读不完——单元格拆短语。
5. 代码块不标语言，渲染成纯黑文本。
6. emoji 当图标体系使用（装饰性堆砌），状态表达不靠它。
7. 颜色作状态的唯一区分（红绿不分场景标成功/错误），色弱不可辨。

## 假设

- 语义色板取本仓库渲染环境（GitHub Primer 默认值）——脱离 GitHub 渲染的
  文档形态（打印、导出 PDF、其他站点托管）需重定色板再引用本册。
- 暗色模式本轮不定：Markdown 随渲染器自适应，HTML 原型只出白底单主题。
- 看板类页面的图表配色（折线/柱状多序列色）未定，待首个看板型原型出现时
  增补；届时按本册"偏离逐条声明理由"纪律走。
