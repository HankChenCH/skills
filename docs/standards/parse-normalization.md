# parse-normalization —— 引用形态判定与键归约单点化

适用对象：同一概念形态（ID、引用、文件名、键）被多处判定或截取的脚本与代码。
来源：spec 0017 运行中票 0038 的七轮评审核销——五处手写形态判定、节点键/边键键空间
分裂、解析失败静默丢弃、分支缺尾锚，均为同一根因（形态逻辑多点手写漂移）的变体。

## 规则

1. **形态判定单点化**：同一形态的判定 + 截段（如 `YYYYMMDD-4hex` 的 case 正则与
   `${:0:13}` 截取）只允许在一处定义（规整层函数），消费方拿到规整结果后按键长或
   分派键分流。两处以上手写同一判定即漂移温床——本规则源自两轮真缺陷：键空间分裂
   使依赖环检测静默失效（b9a5f92 时代）、唯一键口径分裂造成同 ID 异文件重号（b0db053）。
2. **键空间同源**：图算法（环检测、依赖解析、清扫覆盖匹配）的节点键与边键必须经
   同一归约函数产出；一边归约、一边截断，依赖边将永不命中。
3. **解析失败显式上抛**：被规整层拒绝的输入必须原样交下游显式报错（fail-loud），
   禁止 `|| continue` 式静默丢弃——静默蒸发让门禁覆盖面无声缩窄，且单发坏引用的
   报错失实。
4. **新形态分支带尾锚**：形态分支的正则必须有边界锚（「恰 N 位」与「N 位后必须跟
   分隔符」分开），否则超长非法输入被静默截成合法前缀、命中错误产物（实测 5 位 hex
   引用被截前 13 位后借以过状态门）。

## 自查

grep 一下目标形态的特征子串（正则片段、截取表达式）：命中 > 1 处即违反规则 1；
把非法变体（超长、缺段、裸前缀）逐个喂给解析入口：任一被静默接受或截段命中即违反
规则 3/4。
