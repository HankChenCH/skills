# declarative-artifact-strict-parse —— 声明式工件有效性判断用真解析器

适用对象：被外部系统（CI 平台、包管理器、agent 宿主）解析执行的声明式工件——workflow
YAML、发布清单、配置、DSL——的**有效性（可解析性/合法性）判断**。
来源：need 20261115-fc48 round 2 修复周期（复盘 20261116-8af4）。票 20261115-d5f4 改
workflow 步名时把 `: `（冒号+空格）写进未引号平纯标量，GitHub plan 阶段 0s startup
failure 静默全红 8+ 小时；守护该文件的契约测试用自写子集解析器（KEY_RE），不校验平纯
标量冒号语义，缺陷穿透（票 20261116-0304）。

## 规则

1. **有效性判断 = 真解析器**：判断「工件能否被目标系统接受」必须用真解析器全文件解析
   （js-yaml 之于 Actions YAML；解析器版本随目标系统演进跟进）。解析失败带行列号显式
   报错，报因直指目标系统同款失败形态——本地红 = 远端将红，反馈环同因同位。
2. **自写解析器只承结构契约**：自写/子集解析器用于断言工件的结构契约（步骤链顺序、
   键值面、禁入面——本仓 ci-workflow.test.ts 的 KEY_RE + 步序链），**不得作为可解析性
   的判据**；两防线并陈，各自的覆盖边界在文件头注声明。
3. **平纯标量禁 `: `**：YAML 未引号标量含冒号+空格即被解析器断为新映射键（bad
   indentation）——写步名/键值文案遇冒号必须加引号或改述（先例：`cache: pnpm` 入步名
   致 0s 红，改述为 `pnpm cache needs it on PATH`）。
4. **真跑是最终防线**：解析器防线只缩短本地反馈环（stub-fidelity-integration 同构
   论据：真解析器是替身，GitHub 真实解析者的集成线 = CI run 本身）；推送后观测目标
   系统真实 run 至终态是集成级兑现点，不可省（蓝图 §11.17 运行后观测义务）。

## 范例（好 / 差对照）

差（自写正则判可解析性）：

`KEY_RE 逐行匹配通过 = workflow 合法`——平纯标量冒号、锚点语义、多文档等解析类缺陷
全穿透，本地全绿远端 0s 红。

好（真解析器 + 结构契约双层）：

`js-yaml.load 全文件解析（失败带行列号即红）`承可解析性；自写解析器承步骤链顺序与
禁入面契约；头注声明两防线覆盖边界。
