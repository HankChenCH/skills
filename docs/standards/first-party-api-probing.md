# first-party-api-probing：外部协作者 API 形态的一手源码探针实证

适用场景：实现要调用**外部协作者的公开 API**（官方宿主包、平台 SDK、协议库）时——调研报告、文档页、类型提示里的 API 形态是二手转述，不是契约。本纪律来自 spec 20261117-34d4 运行实录：调研报告对官方 settings.mutate 的形态转述（字符串路径三参）与 `dsh-settings@0.2.2-rc.1` 真实源码（ops 数组 + 第 4 实参求值即抛）不符，集成级承载票三轮探针才坐实，前置两票按调研形态实现后被评审与探针连锁返工。

## 规则

1. **开工前探针实证**：承载对外部协作者 API 调用的工票开工前，对将调用的每个 API 形态跑一次最小探针（node REPL 直调或单测替身先按"证伪形态"镜像官方实现），实证结果写进工单 Progress——调用了什么、真实签名是什么、来源文件路径。调研报告的形态描述只作线索，不作实现依据。
2. **替身契约 = 真实签名镜像**：替身（stub）的签名、抛错文案、返回形态照官方一手源码逐字镜像，注释注明来源文件；写不出官方来源的替身行为是猜测，必须标注"待探针复核"并转入集成复核清单。
3. **集成承载票是探针缺口的兜底门**：凡实现期按二手形态落码、集成期才实证的项，必须逐项写进集成复核清单（随票交接），集成测试对每项给真实链路断言或显式留痕；清单不得折叠进叙述性备注（评审 20261118-99d3 的教训：两个写通道语义盲点折叠后评审轴要求单列）。
4. **形态断裂 = 设计级信号**：探针/集成发现外部 API 真实形态与已实现契约不符时，按设计级阻断处置（停工返工、fix 票对齐真实形态），不得用适配层吞掉形态差异（吞差异 = 把官方语义翻译层变成维护负债）。
5. **探针覆盖协作者的全部调用面，双面盲区是系统性缺口**：同一协作者 API 常有多个调用面，校验形态互不相同（实证：spec 20261118-0de6 验收 e87d——dsh settings 写通道的 gateway 线层 envelope 命名参数形态不经数参校验，client api JS 面却严格按 `descriptor.parameters.length` 数参且不豁免 undefined；线层 e2e 与 2 参替身单测双双全绿，真机浏览器人工走查才暴露全部写通道失败）。写替身与集成断言前先枚举调用面（线层协议 / JS 函数调用面 / 进程内服务面），逐面核对校验形态并按面镜像；只验证一个面的覆盖不得声明"集成绿 = 形态正确"。
