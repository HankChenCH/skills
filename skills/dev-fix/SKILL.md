# dev-fix：缺陷分诊与修复

你只做一件事：把**一个缺陷**变成**一张定级明确、验收可证的 fix 工单，并送进实现链**。
其余一切（不开票直接改代码、把缺陷记在对话里、顺手修不相关的问题）一律拒绝。
拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止，告诉用户"本仓库未接入开发流程，先运行 /setup-workspace"。

## 1. 入口门禁（全部通过才继续）

1. **重入判定先行**：docs/tickets/ 已有 `type: fix` 且 `status: ready` 的票 →
   分诊已完成，列出（编号、标题、定级）请用户点名，点名后直接跳 §4.3；
   `in-progress` 的 fix 票属 dev-implement 重入域 → 指路 /dev-implement 续接，不抢。
2. **确定归属 spec**：缺陷发生在哪个 spec 交付的功能上。用户没说 → 按描述
   判断并运行 `.sdlc/check.sh phase` 列 spec 候选请用户点名，禁止代挑。
   无法归属任何 spec → 这不是缺陷是需求缺口：停下指路 /dev-clarify 或
   /dev-spec，不开票。
3. **复现路径必须存在**：复现步骤、报错输出、错误结果示例，至少其一。
   "好像有点怪"不算——说不出怎么复现的，先问出复现路径再继续。

## 2. 装载上下文

按顺序读：归属 spec 全文（重点 `## 验收场景`——缺陷是违反了哪条场景）→
该 spec 名下工单清单与状态；spec 已 done 的，加读对应 acceptance 报告的
残余风险。然后用三五句话向用户复述：缺陷行为（期望 vs 实际）、归属 spec、
复现路径。有偏差，用户此刻纠正的成本最低。

## 3. 分诊纪律

- **定级四档，按操作性定义不按感觉**，依据写进票：
  - **阻断**：主流程不可用、数据错误或丢失、安全漏洞。
  - **重要**：功能受损但有绕行，影响面大。
  - **一般**：功能受损影响面小，绕行明显。
  - **轻微**：文案、样式、纯文档瑕疵。
- **处置必须问人（决策点，带默认建议）**：现在修 / 排期（票保持 ready 进
  frontier，等点名）/ 不修（理由记进票的 Progress）。沉默不算确认。
- **轻微且纯文档 → 不开票**，走 [trivial] 豁免直接修（豁免通道的合规用法，
  dev-retro 可审计）；源码缺陷一律开票，哪怕很小。
- **一缺陷一票**；同根因的多个表象可并一票，归并理由写进票。

## 4. 出口门禁（全部通过才算完）

1. 用下面的固定模板落盘 `docs/tickets/NNNN-slug.md`（id = 目录内最大号 +1，
   `type: fix`，`spec` 必填），跑 `.sdlc/check.sh validate` 必须通过，再跑
   `publish`。开票提交带 `[trivial]`（流程产物落盘）。
2. **处置 = 排期或不修** → 票留盘（ready）或把不修理由写进 Progress，停，
   不送实现链。
3. **处置 = 现在修** → **立即用 Skill 工具调用 dev-implement** 实现这张票：
   失败测试先行——先写钉住缺陷的红测试（它就是复现），再修复转绿；红绿
   纪律、ref-testing 装载与全量回归以 dev-implement 为准。dev-implement
   未安装 → 停下说明"fix 票 NNNN 已就绪"，指路按 docs/METHOD.md 手动推进。
4. 修复终经 dev-implement 出口自动进 dev-review——本技能不跳过实现链
   直接改代码。

```markdown
---
id: 0007
type: fix
spec: 0001
status: ready
blocked-by: []
created: <date>
---
# 0007: <缺陷一句话>

**定级：** 阻断 | 重要 | 一般 | 轻微（依据一句话）

**做什么：** 期望 vs 实际 + 复现路径（步骤 / 报错输出 / 错误示例）

**验收标准：**
- [ ] 钉住缺陷的失败测试先写并通过（红转绿）
- [ ] `.sdlc/check.sh all` 全绿（回归）

**Blocked by：** 无 | 编号列表

## Progress
（实现过程中追加：做到哪步 / 下一个动作 / 卡在哪，三行以内）
```

## 5. 中断与交接

分诊完成前被打断（定级与处置还没落盘）→ 直接重新分诊，对话态重开成本低。
票已落盘（`ready` / `in-progress`）→ 状态在盘上，重入从 §1.1 续接。
状态在盘上，不在对话里。

## 禁止事项（任何时候）

- 不开 fix 票直接改源码修缺陷（含"顺手修一下"）。
- 验收标准不写"失败测试转绿"就出票——没有红测试的修复不可证。
- 把说不出复现路径的缺陷开成票——先问出复现路径。
- 替用户定级或定处置；沉默或"都行"不算确认。
- 绕过 dev-implement 自己把修复写完。
