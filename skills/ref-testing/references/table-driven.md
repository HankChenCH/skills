# 表格驱动测试（同一逻辑要验证多组输入输出时加载）

同一逻辑有多组"输入 → 期望"（解析、校验、纯函数、边界值）时，把用例摆成表、一个循环跑完。
用例表就是这份逻辑的规格书：列是契约，行是行为。

## 好用例的标准

1. **用例表即规格**：别人不读实现、只读这张表，就能说出"这个函数对什么输入给什么结果"。
2. **一行一个行为，每行有名**：行名说行为（"空串报错""千分位逗号被剥离"），不写 case1；
   某行失败时，行名直接给出失败描述。
3. **期望值来自独立来源**：字面量与手算结果写死在表里——照实现抄期望值，表就失去规格资格
   （见 SKILL.md 通则 2）。
4. **边界与错误行同表**：空输入、极值、恰好越界、期望抛错的行和正常行摆在一起，不散落表外。
5. **表外无特判**：想"这条单独写个测试"时先问为什么它进不了表——进不了，说明它是另一个
   行为，另起一张表，而不是在表外塞特例。

## 范例（好 / 差对照）

差（期望值来自实现，表读不出契约）：

```ts
test("解析 3", () => expect(parseAmount("3")).toBe(3));
test("解析 -1", () => expect(parseAmount("-1")).toBe(-1));
```

-1 是合法行为还是抄错了实现？无从判断——期望值是跑了一下实现抄来的，这两行不是规格。

好（行有名、期望独立、错误行同表）：

```ts
const cases = [
  { name: "正整数原样通过", input: "3", want: 3 },
  { name: "千分位逗号被剥离", input: "1,024", want: 1024 },
  { name: "两个小数位四舍五入", input: "1.005", want: 1.01 },
  { name: "空串报错并指认字段", input: "", error: /amount/ },
];
for (const c of cases) {
  test(c.name, () => {
    if (c.error) expect(() => parseAmount(c.input)).toThrow(c.error);
    else expect(parseAmount(c.input)).toBe(c.want);
  });
}
```

1.005 → 1.01 是手算拍板的（浮点上它其实是 1.00499…，正是要钉住的行为）；四行读完，
`parseAmount` 的契约已经清楚。

## 反模式

- **行无名**：失败只报 case3，定位前还得翻表对号。
- **一行断多个行为**：失败时不知道是输入解析错了还是舍入错了，定位退化为全行排查。

## 自查口令（落表前过一遍）

只读这张表能说出函数契约吗？每行的名字是行为吗？有没有哪格期望值是照实现抄的？
边界行和错误行进表了吗？
