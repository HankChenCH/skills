# design-ui：在约束与基线下做界面设计

你只做一件事：把**设计约束**（brief 产物或用户等价说明）变成**多平台布局与视觉
决策 + 四态原型**，出口过硬指标清单自查。其余一切（采集角色约束、建基线分册、
定稿述标、写实现代码）一律拒绝。拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止，告诉用户"本仓库未接入开发流程，先运行 /setup-workspace"。

## 1. 入口门禁（全部通过才继续）

1. **重入判定先行**：docs/designs/ 已有 slug 以 `-ui` 收尾、指向本任务的 ui 草稿
   且 `status: draft` → 续接不是重做（见 §5）；已 approved 的 ui 草稿即定稿终态，
   不重开（要改设计另立新稿）。
2. **校验约束输入（本技能的入口判据）**：design-brief 产物（docs/designs/ 内
   slug 以 `-brief` 收尾的约束清单）或用户等价说明（逐角色约束、明确设计要求的
   原话）→ 有其一即过。两者皆无 → 停止并指路 /design-brief，**禁止裸设计**。
3. **适用性亮牌（可拒绝）**：任务没有界面交付（用户故事/FR 不涉及界面、页面、
   原型、排版呈现）→ 亮牌"这没有界面交付，不需要界面设计"；要建或改基线分册 →
   指路 /design-baseline；要定稿述标、把原型落进仓库 → 指路 /design-deliver。
   亮牌后用户坚持才做。

## 2. 装载上下文

按顺序读：约束输入全文（brief 产物重点逐角色三要素；对话原话逐字留作决策溯源）→
GLOSSARY.md 项目术语（述标 / 设计基线）→ 基线分册
`docs/standards/design-<对象平台>.md`（有 → 读入并执行跟随纪律；无 → 记"无基线"，
用套件默认阶梯出设计，出口建议 /design-baseline，不代跑）→ 代码现状与既有界面
（风格延续与组件复用的素材）。然后用三五句话向用户复述：约束是什么、打算给什么
布局方向。有偏差，用户此刻纠正的成本最低。

## 3. 设计纪律

- **对象路由（按需装载，一次只载一个）**：界面对象属于哪类，就先装载哪本分册，
  再开设计——分册给该对象的布局模式与视觉决策要点，决策照它的口径落。

  | 对象 | 信号 | 分册 |
  |---|---|---|
  | Web | 浏览器访问：后台、控制台、官网 | references/web.md |
  | 移动端 | 手机/平板触屏 App | references/mobile.md |
  | 桌面端 | 桌面应用：窗口、菜单、文件系统 | references/desktop.md |
  | CLI | 命令行工具、终端交互 | references/cli.md |
  | 文档视觉 | 文档/报告/看板的排版呈现 | references/docs.md |

  跨对象任务各载各的，逐对象出方案。分册与任务信号对不上时问用户，不硬套。
- **布局决策先于视觉、逐条指得回约束**：从约束三要素（信息优先级/密度要求/
  关键操作路径）推布局——每条布局决策注明它满足哪条约束；指不回去的决策是
  装饰，删掉。**Web 方案必须明示移动端适配决策**：断点或独立布局，二选一写明；
  选断点给断点值与分栏变化，选独立布局给触发条件与导航差异。约束里没提移动
  访问却要做适配的，先回问用户，不替用户加需求。
- **视觉决策跟随基线**：有基线 → 配色/字体/密度/阶梯/组件观感逐项对齐，任何
  偏离逐条声明并附理由（写进草稿「偏离与豁免」节）；无基线 → 用套件默认阶梯
  并在草稿声明"无基线，用套件默认阶梯"。
- **视觉章法装载 ref-refactoring-ui**：出布局与视觉决策时用 Skill 工具装载
  ref-refactoring-ui（一次只载一个），按其任务路由表读对应分册——层级营造、
  间距阶梯、色阶、文字排版等决策照其章法口径落；章法与基线冲突时基线优先。
- **原型四态纪律（沿 dev-clarify 原型规格）**：单文件 HTML、CSS/JS 全内联、
  **零外部依赖**（不引 CDN/外链/框架）、≤200 行；正常/空/加载/错误四态各一个
  切换钮，缺任一态不许出口；主流程可点通；样式花在状态可见性上，不花装饰上。
  原型草稿落系统临时目录，不进仓库——定稿落 docs/designs/assets/ 是
  design-deliver 的事。
- **自查逐项留痕**：硬指标清单每项写"通过/不通过 + 证据（数值或出处）"，
  禁止留空，禁止只写"已检查"。

## 4. 出口门禁（全部通过才算完）

1. **落盘前用 Skill 工具装载 ref-writing**（一次只载一个），草稿写法以它为准。
2. **布局自查**：每对象布局决策指得回约束；Web 方案含移动端适配决策（二选一
   明示）。缺任一不出口。
3. **四态自查**：原型正常/空/加载/错误齐备、切换可看、主流程可点通。
4. **硬指标清单逐项自查并记录结果**（默认阈值如下；基线另有更严值从基线）：
   - 正文对比度 ≥4.5:1（WCAG AA）；
   - 正文字号 Web ≥14px；
   - 触控目标 ≥44px（仅移动端触屏；桌面指针设备豁免）；
   - 间距与字号阶梯符合基线（无基线用套件默认阶梯：间距 4/8/12/16/24/32/48px，
     字号 12/14/16/20/24/32px）。

   不通过项 → 修复后复核；不能修复 → 附豁免理由留痕（随自查结果进述标素材）。
5. **草稿落盘**：按模板落 `docs/designs/NNNN-<slug>-ui.md`（id 与 brief/design
   同一计数空间，slug 以 `-ui` 收尾，`status: draft`），跑
   `.sdlc/check.sh validate docs/designs/NNNN-<slug>-ui.md` 必须通过。草稿含
   **风格跟随声明**（跟随基线/偏离逐条/无基线声明）与硬指标自查结果——它们是
   述标说明「风格跟随声明」「硬指标自查结果」小节的素材。
6. **出口（指路，不自动串联）**：报草稿与原型路径，说明其去向——交
   /design-deliver 定稿述标（「界面设计」节四小节 + 原型落 assets）。只指路，
   不代跑。

## 5. 中断与交接

会话可能在任何时刻结束。停下前先把 ui 草稿以 `status: draft` 落盘——已定的布局
与视觉决策逐节写入，未定的标"待确认"，原型的当前临时路径记入草稿。重入从 §1.1
续接：盘上的 draft 就是进度，已 approved 的 ui 草稿不重开。状态在盘上，不在
对话里。

## ui 设计草稿模板（固定）

```markdown
---
id: 0002
spec: 0001
status: draft
created: <date>
---
# <标题：XX 界面设计方案>
## 对象与输入   ← 界面对象（路由到的分册）、约束输入（brief 产物路径 / 对话描述）
## 布局方案     ← 逐对象小节；Web 小节必含「移动端适配决策：断点/独立布局」二选一
## 视觉决策与基线跟随 ← 配色/字体/密度/阶梯对齐情况；无基线则声明用套件默认阶梯
## 原型（四态） ← 单文件零依赖；临时路径 + 四态切换说明
## 硬指标自查   ← 逐项：通过/不通过 + 证据；不通过项修复或附豁免理由
## 偏离与豁免   ← 偏离逐条附理由；无则写"全程跟随基线，无偏离"
## 述标素材     ← 风格跟随声明 + 交 design-deliver 定稿的清单
```

## 禁止事项（任何时候）

- 无约束输入开工——没有 brief 产物且没有用户等价说明就出设计（先指路
  /design-brief）。
- Web 方案缺移动端适配决策，或断点/独立布局二选一不写明。
- 原型四态缺项；原型引外部依赖（CDN、外链、框架）；原型超 200 行。
- 跳过硬指标自查、清单结果留空，或无豁免理由就放行不通过项。
- 建或改基线分册（design-baseline 的事）；定稿述标、把原型落进仓库
  （design-deliver 的事）；写实现代码。
- 跳过 validate 或在 validate 未过时落盘定稿。
