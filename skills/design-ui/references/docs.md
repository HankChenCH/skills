# 文档视觉对象：布局模式与视觉决策要点

design-ui 对象路由选中本分册后加载。适用：文档/报告/看板的排版呈现——
README、验收报告、述标说明、数据看板页。核心动作：读法（精读/速查/核销）
翻成文档结构与排版决策。

## 布局模式（按约束三要素选型，决策注明满足哪条约束）

- **线性精读布局**：结论/目标先行、步骤编号线性、每步可验证、
  术语首现即解释——对齐"首次上手"约束；前置条件在开头显式化。
- **速查检索布局**：目录与锚点可达、条目自足（单条看完即用）、
  同构条目三件套（签名/示例/注意）——对齐"跳读速查"约束。
- **对照核销布局**：要求→结果映射表、证据链显式（路径/编号/输出引用）、
  结论汇总在首屏——对齐"评审验收"约束；述标说明即此模式的套件实例
  （「界面设计」节四小节）。
- **看板总览布局**：先结论后论据、异常指标优先呈现、数字可溯源——
  对齐"管理者总览"约束。

## 视觉决策落法（文档口径）

- 标题阶梯：层级用字号阶梯表达（基线分册；无基线用套件默认阶梯），同级同款，
  不靠加粗混色冒充层级。
- 强调：全文一种手段为主（粗体或高亮二选一），不混用；颜色不作唯一区分
  （色弱可辨）。
- 对比度：正文与表头对背景 ≥4.5:1；引用/代码块与正文有可辨的底色差。
- 行长与段长：正文行长适中、段落 3–5 句——密度约束落在可读口径，
  不落在固定字数。

## 好 / 坏对照

- 好："验收报告首屏核销汇总表：每行要求原文链接→结果→证据引用；
  异常项置顶。"
- 坏："大标题加蓝色高亮突出重点。"——强调手段无规则混用，删掉重定。

## 自查口令

三类读法对应的结构都落了吗？证据链显式可点吗？
强调手段全文一致吗、对比度过线吗？
