# Web 对象：布局模式与视觉决策要点

design-ui 对象路由选中本分册后加载。适用：浏览器访问的界面——后台、控制台、
官网、SaaS 工作台。核心动作：把约束三要素翻成屏内布局，并明示移动端适配决策。

## 布局模式（按约束三要素选型，决策注明满足哪条约束）

- **列表 + 详情（主从布局）**：数据角色的高频主场——列表承载"一屏多看数据"，
  详情承载"单条看全"；主从比例、唤起方式（侧滑/新页）随密度约束定。
- **总览 + 下钻（仪表盘布局）**：管理者"先全局后明细"——首屏聚合健康度/趋势，
  图表可点进入明细；异常态视觉权重高于正常态。
- **分步表单 / 向导布局**：录入与审批流——步数对齐关键操作路径约束，
  每步必填项可视化，进度可见可回退。
- **多标签工作台布局**：操作员并行单据——状态外层可见（标签角标），
  常用动作常驻不随标签切换。

## 移动端适配决策（Web 方案必含，二选一明示）

- **选断点**：给断点值与分栏变化——如"≤768px：侧栏收为抽屉、多列表格转
  单列卡片、操作按钮并入详情页"；约束里"谁在手机上访问"决定收窄的取舍。
- **选独立布局**：给触发条件与导航差异——如"移动访问仅查状态一种场景，
  独立只读视图：底部 Tab 三项，不给批量操作"。
- 两方案都不写"以后再说"；约束未提移动访问的，回问用户，不替用户加需求。

## 视觉决策落法（Web 口径）

- 对比度：正文对背景 ≥4.5:1（WCAG AA）；异常/警示色同时靠图标与文字区分，
  不只靠色相。
- 字号：正文 ≥14px；12px 仅限标签、时间戳等非正文辅助信息。
- 密度：高密度表用行分隔与斑马纹，留白跟随间距阶梯；不靠缩小字号堆密度。
- 阶梯：间距与字号对齐基线分册；无基线用套件默认阶梯（SKILL.md §4.4）。

## 好 / 坏对照

- 好："≤768px 断点：筛选器收为顶部抽屉、列表转卡片流——满足'操作员手机查
  设备状态'约束。"
- 坏："页面主色用蓝色，看起来专业。"——无约束指向的色彩偏好，删掉。
