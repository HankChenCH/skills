# 移动端对象：布局模式与视觉决策要点

design-ui 对象路由选中本分册后加载。适用：手机/平板触屏 App（原生或 H5）。
核心动作：一屏一个主任务，布局围着拇指与使用环境（手/时间/网络）转。

## 布局模式（按约束三要素选型，决策注明满足哪条约束）

- **单列纵览布局**：信息块纵向单列排布，首屏只放主任务与必须即时可见的信息
  （价格/状态）；其余收次级页——对齐"一屏一个主任务"约束。
- **底部导航布局**：3–5 个高频入口固定底部，当前态明确；深层路径用推入页，
  不用层层抽屉套抽屉。
- **拇指热区布局**：高频动作放下半屏易达区；破坏性动作放远处或加确认——
  对齐"单手可完成高频操作"约束。
- **全屏承接布局**：拍照、扫码、填报等任务页全屏承接，完成后返回原位，
  中断恢复不丢上下文——对齐"碎片时间、回来不丢"约束。

## 视觉决策落法（移动端口径）

- 触控目标：按钮、行、热区 ≥44px（含间距）；主操作钮加大且唯一——
  满足触控硬指标的方式写进布局（放哪、多大），不只在自查里报数。
- 弱网四态：加载态给骨架屏或进度、错误态给重试入口、空态给引导——
  四态在移动端是使用环境的一部分，不是装饰。
- 字号与对比度：正文 ≥14px、对比度 ≥4.5:1 同样适用；支持系统字号缩放，
  布局不因放大而破版。
- 平板分化：横竖屏与分屏姿态按约束处理；约束没提就不为平板特化。

## 好 / 坏对照

- 好："上报按钮固定右下、56px 圆钮——'扫码→拍照→上报'每步单手可达；
  弱网上报转后台队列并给状态提示。"
- 坏："用毛玻璃卡片流显得高级。"——装饰决策无约束指向，删掉。

## 自查口令

高频操作落在拇指易达区了吗？触控目标 ≥44px 写进布局而不只是自查表了吗？
四态在弱网/断网场景都成立吗？
