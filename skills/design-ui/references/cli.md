# CLI 对象：布局模式与视觉决策要点

design-ui 对象路由选中本分册后加载。适用：命令行工具、终端交互。
核心动作：CLI 的"界面"是命令面与输出面——布局落在输出分层与命令面结构上，
两类使用者（人类/脚本）不许互相绑架。

## 布局模式（按约束三要素选型，决策注明满足哪条约束）

- **输出分层布局**：stdout 只放数据与结论、诊断与进度走 stderr——对齐
  "管道可组合"约束；分层的默认档位（静默/摘要/verbose）写明。
- **结论先行布局**：首行一行状态结论，详情按需展开（`--verbose`）——对齐
  "诊断排障"约束；结论行格式固定可 grep。
- **进度输出布局**：批处理给单行刷新进度或分段日志，二选一写明——对齐
  "进度可见、可中止"约束；中断后能判断已完成部分。
- **命令面布局**：高频任务参数顺序与默认值、危险操作显式 flag、
  `--help`/`--dry-run` 可发现——对齐"试错成本低"约束。

## 视觉决策落法（CLI 口径）

- 颜色：仅作强调、不作唯一信息载体——无色终端与色弱用户不丢信息；
  前景对终端深浅背景对比度按 ≥4.5:1 口径选色，不依赖固定背景。
- 退出码：语义表进设计（0 成功/非 0 分类失败），与输出分层同源——
  脚本使用者靠它分支。
- 机器可读模式：`--json` 输出与人类输出信息对等、结构稳定，
  不因版本变更破坏字段。
- 阶梯：日志等级与详略档位对齐基线分册约定；无基线用套件默认
  （quiet / 默认 / verbose 三档）。

## 好 / 坏对照

- 好："失败时 stderr 首行'哪个环节/什么原因/怎么修'，`--json` 下同字段
  结构化；颜色仅标记严重级，摘掉颜色信息不减。"
- 坏："报错画红色 ASCII 横幅。"——装饰且无色终端丢失信息，删掉。
