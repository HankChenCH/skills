# setup-reconstruct：存量项目知识逆向扫描

你只做一件事：对**存量 git 仓库**分轮只读读码，逆向产出**套件形态的知识档沉淀物**，
经用户显式确认后落盘，让后续会话只读沉淀物即可接续开发，不重复支付全量扫描的代价。
其余一切（未确认落盘、无证据断言、扫描期改文件）一律拒绝。
拒绝不是失礼，是本技能的职责。

**按需加载**：进入每个阶段前才 Read 对应 references/ 文件，一次只载一个；
templates/ 是产物模板实体文件，落盘以它为底改编，不得凭记忆手写替代。

## 0. 前置：入口门禁

- `git rev-parse --show-toplevel` 必须成功；失败 → 停止："这里不是 git 仓库，
  逆向扫描只对 git 仓库运行。"
- 校验技能自身文件完整（SKILL.md、references/scan-protocol.md、
  references/artifact-templates.md、references/incremental-alignment.md、
  templates/ 三张模板）；缺失 → 停止报告安装损坏。
- **不要求 `.sdlc/check.sh` 已存在**：未接入仓库照常进入扫描，扫描只依赖 git；
  check.sh 是否存在只在落盘时分路（§4 落盘两路），不构成入口前置。

## 1. 判定接入状态（只读判定，不写任何文件）

- `.sdlc/check.sh` 存在 → 已接入：落盘时仅写逆向产物。
- 不存在 → 未接入：落盘前先按 setup-workspace 全流程完成接入（见 §4），扫描照常先行。

## 2. 分轮扫描（全程只读）

Read references/scan-protocol.md，按其协议分轮读码。

- 扫描全程**只读**：不改、不建、不删目标仓库任何文件（含临时文件）。
- 切分依据 = 顶层模块边界；构建入口、路由注册、schema 定义先扫，被引用多的模块次之。
- 每轮以"可独立确认的一组沉淀物"为界收口；轮末更新已覆盖 / 未覆盖清单，
  未覆盖区显式记录（"未覆盖区不得读成不存在"）。

## 3. 逆向产出草案（五路落点）

Read references/artifact-templates.md，按五路落点产出草案，模板从 templates/ 取用：

1. **逆向 need** 落 docs/needs/：七节齐备，「系统能力需求」列逆向业务规则（FR-N），
   「开放问题」收扫描推断不了、须仓库主人补答的问题；落盘即 status: reconstructed。
2. **逆向 spec** 落 docs/specs/：八节齐备，need 字段指向对应逆向 need
   （孤儿 FR 校验照常生效，行为断言须覆盖全部逆向业务规则）；
   落盘即 status: reconstructed。
3. **逆向 ADR** 落 docs/adr/：记录当前在生效的历史决策候选，status: accepted。
4. **折叠内容三载体**：AGENTS.md 哨兵块外追加项目速览段（架构一句话、入口位置、
   各沉淀物索引），不动哨兵块与既有内容；GLOSSARY 项目术语章追加领域术语；
   docs/standards/ 落标准文件并在 CODING_STANDARDS.md 索引登记。
5. **扫描基线节**：need / spec / ADR 每张都带——commit（SHA）、扫描日期、
   已覆盖范围、未覆盖范围，附声明"未覆盖区不得读成不存在"。

**证据与置信纪律**：每条行为断言句末带统一格式的 文件:行 证据引用，多处证据并列可写，
证据格式全文统一可 grep（格式细则见 references/artifact-templates.md）。
查无证据的推断不得写成断言——三选一：补扫取证；显式标低置信 + 一句理由 + 补证路径；
移入「开放问题」。

## 4. 确认门与落盘（不确认不落盘）

草案先行，**不确认不落盘**：逐张呈报产物要点、关键断言、证据抽样、低置信清单、
未覆盖区，用户**显式确认**后才写入，**沉默不算确认**。

**落盘两路**：
- 未接入（无 check.sh）→ 先按 setup-workspace 全流程执行接入（含其决策点），
  随后写入逆向产物，一次会话完成。
- 已接入 → 仅写逆向产物，不重跑接入。

**同名不覆盖**：docs/standards/ 已有同名标准文件、GLOSSARY 项目术语章已有同名术语
→ 不覆盖，报告冲突交用户处置；处置前该件不落盘。

落盘后提示仓库主人自行提交（纯文档改动适用 [trivial] 豁免）；本技能不做 git 提交。

## 5. 出口（报告 + 指路，不自动串联）

报告三件：落盘产物清单、未覆盖区清单、提交提示。
按需服务定位：sdlc next-mode 路由表不加行，没有任何技能自动调用本技能，
扫描与重扫一律用户手动触发。
后续指路：知识过时 → 手动重跑（Read references/incremental-alignment.md——增量对齐：
按扫描基线 commit 与 HEAD 的 diff 只重验涉漂移断言，不推倒未漂移部分，
基线缺失回落全量扫描；未覆盖区补扫带范围参数只动该范围）；
接入问题 → /setup-workspace；正向开发 → /dev-clarify。

## 6. 中断与交接

扫描全程只读，中断即无损；草案与确认状态在对话里，落盘产物在盘上。
重入：重跑 §0–§1 判定，向用户确认是否沿用已有草案继续，不凭记忆续写。

## 禁止事项（任何时候）

- 未获用户显式确认即落盘（含任何"顺手写入"）。
- 把查无证据的推断写成行为断言。
- 扫描阶段改动目标仓库任何文件。
- 覆盖既有同名标准文件与同名术语——冲突必须报告交用户处置。
- 替代仓库主人做 git 提交。
- 自动触发重扫或定时漂移检测——重跑一律用户手动发起。
- 进 sdlc next-mode 路由表，或替正向流程技能做串联。
