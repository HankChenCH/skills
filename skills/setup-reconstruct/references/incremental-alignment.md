# 增量对齐协议（重跑语义：增量对齐与补扫）

主文档 §5 重跑语义的本细则。重跑与补扫沿用首扫同一确认门：确认门前全程只读、
草案先行，不确认不落盘；落盘后提示仓库主人自行提交，本技能不做 git 提交。

## 重跑入口（先判基线，再选路）

- 重跑一律用户手动发起；入口先读存量产物的扫描基线节，取基线 commit。
- 基线在 → 走下方增量对齐，只动漂移部分，不推倒未漂移的已确认内容。
- 基线缺失（手写产物、基线节残缺、commit 已不可达）→ 回落全量扫描
  （按 scan-protocol.md 首扫协议重来），不得凭记忆增量。

## 增量对齐（按漂移分组，只重验涉漂移断言）

1. **取变更文件集**：`git diff --name-status <基线commit>..HEAD`，
   得基线到 HEAD 的新增 / 修改 / 删除文件集。
2. **按证据引用分组**：grep 存量产物全部断言的证据引用，与变更文件集求交——
   证据指向漂移文件的断言入涉漂移组，其余入未涉漂移组；删除文件波及的断言视同涉漂移。
3. **只重验涉漂移断言**，逐条三选一：
   - 重验后行为未变、仅行号移动 → 更新证据行号，断言语句不变；
   - 行为已变 → 重取证改写断言（首扫证据与置信纪律照常）；
   - 无法确认 → 与用户确认后标过时（低置信格式注明"基线后漂移、待复核"），或移入「开放问题」。
4. **新增文件产出增量断言草案**：对变更文件集中的新增文件按首扫协议出增量断言，
   归入对应产物；不新开产物张数，除非确无对应产物可归。
5. **同一确认门合并写入**：增量草案逐张呈报（涉漂移断言更新前后对照、增量断言、
   过时标注清单），用户显式确认后合并写入——只动涉漂移与增量部分，
   未涉漂移的断言与正文逐字不变，不推倒未漂移部分。
6. **逐张更新扫描基线**：确认落盘后，每张逆向产物的扫描基线更新为本次重跑时点的
   新 commit，扫描日期与已覆盖 / 未覆盖范围随之刷新。

## 补扫（带范围参数的重跑）

用户对基线标注的未覆盖区发起补扫，规则四条：

- **范围参数必填**：补扫必须显式带范围（目录子树 / 模块 / 文件清单）；
  未带范围的补扫请求按全量重跑处置，走上方增量对齐协议。
- **只产出该范围增量产物**：只读该范围，按首扫证据与置信纪律产出该范围的
  增量断言草案，经确认门后并入对应产物。
- **更新基线覆盖清单**：确认落盘后，已覆盖范围并入补扫范围，未覆盖范围相应缩减，
  commit 更新为补扫时点。
- **已确认存量产物不被重写**：补扫不触碰范围外任何已确认内容；
  与存量断言冲突时报告交用户处置，不静默覆盖。
