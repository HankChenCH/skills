# 逆向扫描协议（分轮切分、证据采集与置信标注）

主文档 §2 分轮扫描的本细则。全程只读：不改、不建、不删目标仓库任何文件。

## 轮次切分

- 切分依据 = 顶层模块边界：monorepo 按子项目，单仓按目录子树或分层。
- 入口优先：构建入口、路由注册、schema 定义先扫，被引用多的模块次之。
- 每轮以"可独立确认的一组沉淀物"为界收口：轮末产出该轮草案、更新扫描基线的
  已覆盖 / 未覆盖清单，交确认门；该轮未确认不落盘，也不阻塞下一轮扫描。
- 未覆盖区逐轮显式记录进扫描基线，供用户发起补扫；补扫 = 带范围参数的重跑，
  在增量对齐协议下只动该范围（重跑语义见主文档 §5）。

## 证据采集

- 每条行为断言在写下时当场记证据：相对路径:行号，指向扫描时点 HEAD 的文件与行。
- 多处证据并列可写；拿不出 文件:行 的句子不是断言，按下方置信规则处理。
- 证据引用全文统一可 grep（格式见 artifact-templates.md「证据格式」），
  增量对齐靠 grep 它定位漂移。

## 置信标注

查无证据的推断三选一，不得写成断言：

1. **补扫取证**——能查到就再扫，把证据找齐后写成断言。
2. **显式标低置信 + 一句理由 + 补证路径**——证据只有一处或语义存疑时；
   如 `（证据：src/checkout/coupon.py:8，低置信：仅单处证据；补证路径：问产品确认叠加上限）`。
3. **移入「开放问题」**——扫描推断不了、须仓库主人补答的问题，
   落逆向 need 的「开放问题」节，每条注明卡在哪。

## 未覆盖区纪律

- 轮末把未扫到的模块/目录写进扫描基线的「未覆盖」；未覆盖区不得读成不存在。
- 对未覆盖区不做任何断言，哪怕"看起来显然"。
