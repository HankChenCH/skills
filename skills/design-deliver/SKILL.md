# design-deliver：把界面设计定稿为述标

你只做一件事：把**设计决策与四态原型**定稿为**述标**——design 产物「界面设计」
节四小节 + 原型落 `docs/designs/assets/<design-id>/`，出口走 design 既有的
approved 门（即述标评审门）。其余一切（采集约束、建基线、出布局草稿、写技术
方案节、写实现代码）一律拒绝。拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止，告诉用户"本仓库未接入开发流程，先运行 /setup-workspace"。

## 1. 入口门禁（全部通过才继续）

1. **重入判定先行**：docs/designs/ 已有 `spec: NNNN` 指向本 spec 的 design——
   `status: draft` 且已有「界面设计」节 → 续接不是重做（见 §5）；`status: draft`
   但无「界面设计」节（dev-design 起草的共存稿）→ 走并存分支补节，不动技术节
   （见 §3.1）；`status: approved` 且「界面设计」节齐 → 定稿终态，不重开（要改
   设计另立新稿）；`status: approved` 但缺「界面设计」节 → 亮牌"给已批准的
   技术方案补述标属修订"，用户显式确认才补（只加节不改技术节，状态保持
   approved）。
2. **确定输入（本技能的入口判据）**：二者取其一——
   - design-ui 的 ui 草稿（docs/designs/ 内 slug 以 `-ui` 收尾，「述标素材」节
     齐）及其引用的四态原型；
   - 或简单 spec（dev-design 入口判据不命中：无难逆转、无上下文困惑、无真实
     权衡，模块划分与数据流显而易见）及其设计约束（brief 产物或用户等价说明）。

   两者皆无 → 停止转述："先跑 /design-ui 出草稿，或给我简单 spec 编号与设计
   约束"，禁止凭空起稿。
3. **适用性亮牌（可拒绝）**：任务没有界面交付（用户故事/FR 不涉及界面、页面、
   原型、排版呈现）→ 亮牌"这没有界面交付，无需述标"；要出布局与原型草稿 →
   指路 /design-ui；要建或改基线分册 → 指路 /design-baseline；spec 命中
   dev-design 判据且要写技术方案节 → 指路 /dev-design（它起草后本技能并存
   补节）。亮牌后用户坚持才做。

## 2. 装载上下文

按顺序读：输入全文（ui 草稿重点「述标素材」「硬指标自查」两节；简单 spec 重点
`## 用户故事`、`## 验收场景` 的使用者信号）→ GLOSSARY.md 项目术语（述标）→
基线分册 `docs/standards/design-<对象平台>.md`（有 → 读入，风格跟随声明以它
为据；无 → 出口声明"无基线，用套件默认阶梯"）→ docs/designs/ 与
docs/designs/assets/ 现状（id 计数空间与既有述标形态）。然后用三五句话向用户
复述：述标要呈现什么界面、四小节各打算写什么。有偏差，用户此刻纠正的成本最低。

## 3. 述标纪律

### 3.1 共产接口（与 dev-design 的节权属，§6.5）

- **一个 design 产物、两类生产者、节权属固定**：技术节（模块划分/数据流/
  seam 清单/ADR 索引）归 dev-design，「界面设计」节与原型落库归本技能。并存时
  各写各的节互不覆盖——本技能禁止改写技术节，dev-design 禁止改写「界面设计」节。
- **简单 spec 直接建**：dev-design 判据不命中 → 本技能直接建立含「界面设计」节
  的 design 产物，不必经 dev-design；日后该 spec 暴露设计级问题 → dev-design
  回到同一产物补技术节，本技能的节保持原样。
- **frontmatter 沿 design 现契约**：`id` 按 docs/designs/ 目录内最大号 +1（与
  brief/ui/design 同一计数空间，互不重号）、`spec`、`status`、`created`；
  approved 时追加 `approved: <今日>`。两类生产者共用同一扇 approved 门，推进
  规则见 §4.5。

### 3.2 「界面设计」节四小节（固定，缺一不出口）

1. **设计意图**：这套界面为什么这么设计——取舍与理由，验收方读完能复述
   "为什么是这样"。
2. **角色约束**：逐角色约束如何被满足——brief 产物（或用户等价说明）的逐角色
   三要素到布局决策的映射；无 brief 产物时引用户原话并标注来源。
3. **风格跟随声明**：跟随基线 / 偏离逐条附理由 / 无基线声明"用套件默认阶梯"
   （ui 草稿「偏离与豁免」节是素材）。
4. **硬指标自查结果**：逐项"通过/不通过 + 证据"，不通过项写修复结果或豁免
   理由（ui 草稿「硬指标自查」节是素材；简单 spec 由本技能现场自查）。

### 3.3 原型定稿纪律（沿 dev-clarify 原型规格）

- 单文件 HTML、CSS/JS 全内联、**零外部依赖**（不引 CDN/外链/框架）、≤200 行；
  正常/空/加载/错误四态切换钮常驻、当前态高亮；主流程可点通。
- 原型由 design-ui 起草（临时目录）、本技能定稿落
  `docs/designs/assets/<design-id>/`；简单 spec 由本技能现场整理定稿。
- **知识档进仓库，区别于样张的系统临时目录**；assets 约定位置以外不落原型。

## 4. 出口门禁（全部通过才算完）

1. **落盘前用 Skill 工具装载 ref-writing**（一次只载一个），述标写法以它为准。
2. **四小节自查**：「界面设计」节四小节齐且各节有实内容——意图能复述、约束有
   映射、跟随有声明、自查有证据。缺任一不出口。
3. **原型自查**：四态可切换、主流程可点通、零外部依赖、≤200 行、已落
   `docs/designs/assets/<design-id>/` 且 git 可见。
4. **落盘与校验**：按模板落 `docs/designs/NNNN-<slug>.md`，跑
   `.sdlc/check.sh validate` 必须通过，再跑 `.sdlc/check.sh publish`。流程产物
   落盘的提交留痕用 `[trivial]`。
5. **述标评审门（决策点，必须问）**：完整念一遍四小节，给用户原型路径与打开
   命令（open / xdg-open），抛决策问题："述标批准吗？"——**用户显式批准，
   沉默不算批准**。批准 → design `status: approved`、追加 `approved: <今日>`，
   重跑 validate 与 publish；沉默或要改 → 保持 `status: draft`，意见写回续改，
   改完重念。
6. **出口（指路，不自动串联）**：design approved → 指路 /dev-plan（"先述标再
   拆票"）；仍 draft → 说明待办（等用户确认，或等 dev-design 并存补技术节）。
   只指路，不代跑。

## 5. 中断与交接

会话可能在任何时刻结束。停下前先把 design 产物以 `status: draft` 落盘——已定的
小节逐节写入，未定的标"待确认"，原型当前态落 assets（或在产物中记临时路径）。
重入从 §1.1 续接：盘上的 draft 就是进度，已 approved 且节齐的产物不重开。
状态在盘上，不在对话里。

## design 产物模板（述标形态，固定）

```markdown
---
id: 0002
spec: 0001
status: draft
created: <date>
---
# <标题：一句话述标>
## 界面设计
### 设计意图       ← 为什么这么设计：取舍与理由
### 角色约束       ← 逐角色约束 → 布局决策映射；无 brief 引用户原话并标注来源
### 风格跟随声明   ← 跟随基线 / 偏离逐条附理由 / 无基线声明用套件默认阶梯
### 硬指标自查结果 ← 逐项：通过/不通过 + 证据；不通过项写修复结果或豁免理由
## 原型           ← docs/designs/assets/<design-id>/ 路径 + 四态切换说明
```

技术节（模块划分/数据流/seam 清单/ADR 索引）归 dev-design：并存时由它补写，
本技能不代写；两族节互不覆盖，章节先后反映交付顺序即可。

## 禁止事项（任何时候）

- 沉默推进 approved——未经用户显式批准把 design 置 approved；沉默或"都行"
  不算批准。
- 原型落 assets 约定位置以外（`docs/designs/assets/<design-id>/` 之外不落）；
  原型引外部依赖（CDN、外链、框架）或超 200 行；四态缺项。
- 改写 dev-design 的技术节（模块划分/数据流/seam 清单/ADR 索引归它写）。
- 采集角色约束（design-brief 的事）、建基线分册（design-baseline 的事）、出
  布局草稿与临时原型（design-ui 的事）、写实现代码。
- 跳过 validate 或在 validate 未过时落盘定稿。
