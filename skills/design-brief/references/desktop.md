# 桌面端对象：角色画像与场景要点

design-brief 对象路由选中本分册后加载。适用：桌面应用（原生或跨平台）——
窗口、菜单、文件系统交互。核心动作：大屏、长会话、精确指针这三个条件
决定三要素口径。

## 角色画像（约束以角色为单位逐个落）

- **专业操作员**：IDE、设计工具、终端型用户——多面板长驻、键盘为主。
  约束重心：大屏高密度多面板、面板可自定义、快捷键覆盖高频动作。
- **数据录入员**：长会话批量处理——录入、核对、修正。约束重心：
  录入节奏不被打断、校验即时、批量操作有进度与可回退。
- **审阅者 / 决策者**：读得多、批得少——大文档、多版本对照。
  约束重心：对照视图、批注一步可达、导航记忆（回来还在原处）。

## 场景要点

- 多窗口 / 多任务并行：约束写"跨单据信息可并排可见"，不写窗口排布。
- 键盘流：高频动作有快捷键要求，快捷键可在约束里点名（Ctrl+S 类约定俗成的）。
- 长会话：状态持久、可中断恢复、撤销重做安全网——写进关键操作路径。
- 批量操作：选中海量对象执行——约束写进度可见、可中止、可回退。

## 三要素落法（桌面口径）

- 信息优先级：落成面板主次要求——主工作区放什么、辅助面板放什么、
  什么可停靠/隐藏；不写具体面板布局。
- 密度要求：落成大屏口径——单屏并排面板数、数据行数量级、
  信息分区意图；桌面允许比 Web 更密，约束要写明这个倾向。
- 关键操作路径：落成动作序列要求——高频任务键盘几步内完成、
  危险动作有确认或可撤销、中断后从原状态续作。

## 好 / 坏对照

- 好："录入员批量导入 1000 行时进度可中止，中断后从已导入部分续传。"
- 坏："左侧放导航树，右侧放编辑器。"——面板布局，归 design-ui。

## 自查口令

危险动作的回退要求落在路径里了吗？
