# 文档视觉对象：角色画像与场景要点

design-brief 对象路由选中本分册后加载。适用：文档 / 报告 / 看板的排版呈现
——README、验收报告、述标说明、数据看板页。核心动作：文档也有使用者，
读法（线性精读 / 跳读速查 / 对照核销）决定三要素口径。

## 角色画像（约束以角色为单位逐个落）

- **首次上手者**：线性精读——教程、README、上手指南。约束重心：
  结论/目标先行、步骤编号线性、每步可验证、术语首现即解释。
- **速查者**：跳读检索——API 参考、参数表、FAQ。约束重心：
  目录与锚点可达、条目自足（单条看完即用）、表格化高密度。
- **评审 / 验收方**：对照核销——验收报告、述标说明。约束重心：
  逐条可对照（要求→结果映射）、证据链显式（路径/编号/输出引用）、
  结论汇总在首屏。

## 场景要点

- 上手文档：约束写"读完能跑通的最短路径"与前置条件显式化。
- API / 参数速查：约束写每条目结构一致（签名/示例/注意三件套同构）。
- 报告 / 看板页：约束写先结论后论据、异常指标优先呈现、
  数字可溯源（带出处引用）。
- 述标说明（design-* 链）：约束写四小节齐、角色约束可对照原型核销——
  口径沿 GLOSSARY「述标」。

## 三要素落法（文档口径）

- 信息优先级：落成阅读顺序要求——首屏给什么（结论/目录/汇总）、
  正文主次结构、附录收什么；不写版式模板。
- 密度要求：落成可读性口径——段落长度倾向、列表 vs 表格的选择意图、
  图表优先于长文的比例要求。
- 关键操作路径：落成检索路径要求——目录层级几层内可达目标、
  锚点/交叉引用覆盖高频跳转、示例可复制即用。

## 好 / 坏对照

- 好："验收报告首屏是核销汇总表，每行含要求原文链接与验证证据引用。"
- 坏："用大标题加蓝色高亮突出重点。"——视觉决策，归 design-ui。

## 自查口令

三类读法（精读/速查/核销）对应的使用者都约束了吗？证据链要求写了吗？
密度写的是可读性口径还是版式稿？
