# CLI 对象：角色画像与场景要点

design-brief 对象路由选中本分册后加载。适用：命令行工具、终端交互。
核心动作：CLI 的"界面"是命令面与输出面——约束写清两类使用者
（人类与脚本）各自要什么，两种模式不许互相绑架。

## 角色画像（约束以角色为单位逐个落）

- **交互式人类**：运维、开发者——诊断、试错、探索。约束重心：
  人可读输出、错误信息指出修哪、`--help` 能自学、试错成本低（dry-run）。
- **脚本 / 自动化**：CI、定时任务、管道调用者。约束重心：
  机器可读模式（`--json` 类）、稳定退出码、输出可管道组合、无交互阻塞。

## 场景要点

- 诊断排障：约束写"结论先行——一行状态结论 + 详情按需展开（--verbose）"。
- 批处理：约束写进度输出约定与中断恢复语义。
- 管道组合：约束写"过滤后输出可作下一个命令的输入"——数据在 stdout、
  人类提示在 stderr 的要求。
- 配置变更：约束写变更前后差异可见、误操作可回退。

## 三要素落法（CLI 口径）

- 信息优先级：落成输出分层要求——stdout 只放数据/结论、诊断放 stderr、
  默认输出量与详细模式的信息差写清楚。
- 密度要求：落成默认输出的信息量口径——无消息即成功的静默约定、
  或一行摘要 + `--verbose` 展开的分档；不规定具体文案版式。
- 关键操作路径：落成命令面要求——高频任务的参数顺序与默认值、
  危险操作需显式 flag 或确认、`--help`/`--dry-run` 可发现。

## 好 / 坏对照

- 好："失败时 stderr 首行给出'哪个环节、什么原因、怎么修'，`--json` 下同样可解析。"
- 坏："报错用红色输出，带 ASCII 横幅。"——视觉决策，CLI 里也归 design-ui。
