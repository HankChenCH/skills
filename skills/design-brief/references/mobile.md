# 移动端对象：角色画像与场景要点

design-brief 对象路由选中本分册后加载。适用：手机/平板触屏 App（原生或 H5）。
核心动作：把使用环境（手、时间、网络）写进约束——移动端的约束一半来自场景
条件，一半来自角色任务。

## 角色画像（约束以角色为单位逐个落）

- **一线作业者**：现场人员——扫码、拍照、上报、巡检。约束重心：
  一屏一个主任务、大触控目标、弱网可续、单手可完成高频操作。
- **消费者用户**：浏览、挑选、下单、求助。约束重心：引导线性、
  关键信息（价格/状态）即时可见、中断后可回来。
- **移动管理者**：碎片时间审批与查看。约束重心：待办聚合一屏、
  批准/驳回一步可达、明细按需展开。

## 场景要点

- 碎片时间：会话随时被打断——约束写"状态可恢复、回来不丢上下文"。
- 单手 / 行走中使用：高频操作落在拇指易达区的要求；避免双指精细操作成为必经路径。
- 弱网 / 断网：写清哪些信息必须离线可见、哪些操作允许排队。
- 推送唤醒：从通知到完成任务的最短路径要求。

## 三要素落法（移动端口径）

- 信息优先级：落成"一屏一个主任务"——主任务是什么、什么信息必须首屏、
  什么收进次级页。
- 密度要求：落成单列纵览口径——每屏信息块数量级、行高与触控目标的宽松度；
  不写具体像素值（触控目标硬指标归 design-ui 自查）。
- 关键操作路径：落成步数上限——高频任务 2–3 步内完成、路径单手可达、
  完成后有明确反馈。
- 平板分化：iPad/平板横竖屏若在范围内，把使用姿态写成约束，不写布局。

## 好 / 坏对照

- 好："巡检员单手 3 步内完成'扫码→拍照→上报'，弱网时上报排队、照片不丢。"
- 坏："底部放 Tab 栏，首页用卡片流。"——布局决策，归 design-ui。

## 自查口令

每个角色的使用环境（手/时间/网络）进约束了吗？高频路径有步数上限吗？
密度写的是单屏信息量还是布局稿？
