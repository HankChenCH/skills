# dev-plan：把 spec 拆成工单

你只做一件事：把**一张 approved 的 spec**变成**一组过校验、可独立开工的垂直切片工单**。
其余一切（写 spec、写代码、评审实现）一律拒绝。
拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止，告诉用户"本仓库未接入开发流程，先运行 /setup-workspace"。

## 1. 入口门禁（全部通过才继续）

1. **确定 spec**。用户给了编号或路径 → 用它；没给 → 运行 `.sdlc/check.sh phase`
   找 `approved` 的 spec：恰有一张名下无工单（输出中没有 ticket 行带 `spec=NNNN` 指向它）
   → 直接用它；其余情况列出候选（编号、标题、名下已有几张票）请用户点名，
   默认建议：名下无工单里编号最小的一张；都已拆过 → 说明情形请用户裁决。
   禁止自行挑一张没被点名的 spec。
2. 读该 spec 的 frontmatter：`status` 不是 `approved` → **停止**：
   "spec NNNN 还是 draft，先 /dev-spec 完成批准。"不拆任何工单。
3. **重入**：docs/tickets/ 已有 `spec: NNNN` 指向本 spec 的工单 → 这是续拆不是重拆：
   向用户展示已有票与场景覆盖的缺口，从缺口继续（见 §3）；已拆完整 → 直接走 §4。

## 2. 装载上下文

按顺序读：spec 全文（重点 `## 实现决策`、`## 测试决策`、`## 验收场景`）→
docs/adr/ 中相关 ADR → GLOSSARY.md → 粗读改动将落到的代码区域（目录结构、
既有同类实现），为切片大小与先后提供依据。不装载参考技能，不写任何代码。

然后用三五句话向用户复述：spec 覆盖什么、打算切几片、集成级场景有几条。
有偏差，用户此刻纠正的成本最低。

## 3. 拆分纪律

- **垂直切片**：每片切穿全部层（数据、接口、UI、测试同步动），单独可演示，
  大小适配单个新会话的上下文——装不下就再切。禁止按层横切，
  "先把模型全写完"的票不是切片，是分层事故。
- **场景映射**：`[FR-N | 工单级]` 场景逐条落进**恰好一张**工单的验收标准（条目注明
  FR-N）；要两张票才能交付的场景先并票或重切，确实装不进 → 建议回 /dev-spec 把它
  改标集成级（回路，不是失败），本轮停下等待。`[FR-N | 集成级]` 场景不进票——
  它们是 dev-accept 的运行清单，规划时单列并向用户点明集成风险。
- **阻塞边**：只标真实依赖（后一片在前一片的端到端行为上叠加），写进 `blocked-by`；
  能并行就并行，禁止为"看起来有序"加边，禁止成环（validate 会拦）。
- **机械重构**：重命名、改共享符号类型这类宽泛机械改动不硬塞切片，
  按 expand–contract 拆：先并存、分批迁移、最后收缩，每批单独保 CI 绿。
- **固定模板**：确认后用下面的模板落盘 `docs/tickets/NNNN-slug.md`
  （id = 目录内最大号 +1，type 一律 feature——fix 票出自 dev-fix，slug 用 ASCII 小写短横线）：

```markdown
---
id: 0007
type: feature
spec: 0001
status: ready
blocked-by: []
created: <date>
---
# 0007: <标题>

**做什么：** 端到端行为（用户视角），非分层实现清单

**验收标准：**
- [ ] <可验证的条目，勾选时须有证据（哪个测试/什么输出）>

**Blocked by：** 无 | 编号列表

## Progress
（实现过程中追加：做到哪步 / 下一个动作 / 卡在哪，三行以内）
```

## 4. 决策点与出口门禁

1. **拆分粒度 + 阻塞边必须问人**：先不动盘，向用户展示编号清单——每票一行（编号、
   标题、覆盖哪些 FR、blocked-by 谁），末尾单列集成级场景清单与默认建议，请求确认。
   要改 → 回 §3 改完重展；确认前一张票都不落盘。
2. 确认后逐张落盘并运行 `.sdlc/check.sh validate docs/tickets/NNNN-slug.md`，
   每张都必须通过；不过 → 修复后重跑。
3. 逐张运行 `.sdlc/check.sh publish docs/tickets/NNNN-slug.md`。
4. 运行 `.sdlc/check.sh frontier` 并展示，抛出决策问题："从哪张开工？默认建议
   <最小编号>。"工单由用户点名，本技能不代挑、不自动开工。

## 5. 中断与交接

会话可能在任何时刻结束。凡是停下（等用户决策、上下文将尽、被卡住）：
已确认的票逐张落盘（status: ready），未确认的切片方案附进 spec `## 备注`，再停。
重入从 §1 重入分支续接——盘上的票就是进度。状态在盘上，不在对话里。

## 禁止事项（任何时候）

- 拆未 approved 的 spec，或顺手改 spec 正文。
- 按层横切；把集成级场景塞进单票；让 `blocked-by` 成环。
- 跳过 validate，或为让它通过而删减验收标准。
- 替用户挑下一张开工的票。
