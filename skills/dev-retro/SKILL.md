# dev-retro：复盘与豁免审计

你只做一件事：把**一段交付周期的经验**变成**经用户采纳并落实的改动清单，加一份复盘报告**。
其余一切（顺手改代码、修缺陷、改工单状态、未经采纳直接改标准）一律拒绝。
拒绝不是失礼，是本技能的职责。

## 0. 前置：工作区校验

- 仓库根目录必须存在 `.sdlc/check.sh`（由 /setup-workspace 生成）。
- 不存在 → 停止，告诉用户"本仓库未接入开发流程，先运行 /setup-workspace"。

## 1. 入口门禁（全部通过才继续）

1. **重入判定先行**：docs/retros/ 已有 `status: draft` 的报告 → 续接不是重开，
   从报告里标"未执行"的步骤继续（见 §5）；`status: done` 即终态，不重开报告。
2. **确定复盘范围**（决策点，带默认建议）：默认 = 自上一份 `done` 报告的
   `created`（无历史报告则自仓库首次提交）以来至 HEAD 的 git 区间，外加全部
   未核销的评审遗留与验收残余风险。向用户复述区间与素材清单，确认后继续；
   用户点名别的范围（某几次迭代、某张 spec）→ 用它的。
3. **素材存在性**：范围内无任何提交、无评审/验收遗留、用户也没有口述主题 →
   停止："无可复盘素材"。不硬凑发现。

## 2. 装载上下文

按顺序收集：config.sh（BASE_REF，确定区间边界）→ 范围内 `git log --oneline` →
docs/reviews/ 中"留档供 retro 参考"的 findings → docs/acceptance/ 报告的
残余风险与下一轮建议。然后用三五句话向用户复述：复盘哪个区间、手上有哪几类
素材。有偏差，用户此刻纠正的成本最低。

## 3. 复盘纪律

- **豁免审计是机械步骤**：`git log --grep='\[trivial\]'` 圈出范围内豁免提交，
  逐条 `git show --stat --name-only` 看证据。判定基准 = GLOSSARY 的 [trivial]
  定义（限 typo 与纯文档改动）。滥用信号：正文没有豁免理由、涉及非文档文件、
  规模明显超出小修。结论只有三态：合规 / 滥用 / 存疑；存疑只列证据，不下结论。
- **绕过信号**：范围内 subject 既无 `[#NNNN]` 又无 `[trivial]` 的提交 =
  `--no-verify` 嫌疑，逐条列出。这是蓝图 §3"诚实边界"承诺的兜底审计。
- **证据原则**：审计结论必须引用 diff 证据（文件清单、行数、路径），
  只凭 commit message 定罪是禁止事项。
- **遗留项收集**：评审报告"留档供 retro 参考"的条目、验收报告残余风险与
  下一轮建议、用户口述主题，逐条登记，注明来源。
- **改动清单三分类**，每条带目标文件、建议改动、理由、默认建议：
  标准修订 → CODING_STANDARDS.md / docs/standards/ 增量条目；检查增补 →
  蓝图与 assets/check.sh 双写（治理规则：先文档后技能）；技能修订 →
  先蓝图规格节后技能文件。

## 4. 出口门禁（全部通过才算完）

1. **抛决策问题："采纳哪些？"** 逐条给默认建议；沉默不算确认；不采纳的
   逐条把理由写进报告。
2. **落实采纳项**：按三分类的治理通道执行，增量不覆盖既有内容。
3. 落盘前用 Skill 工具装载 ref-writing，报告写法以它为准。
4. 用下面的固定模板落盘 `docs/retros/NNNN-slug.md`（id = 目录内最大号 +1，
   slug 用 ASCII 小写短横线），`status: done`。
5. 报告与落实的改动分别提交：流程产物与纯文档走 `[trivial]` 并写明豁免理由，
   其他改动带对应 `[#NNNN]`。不使用 --no-verify。
6. **无下游自动串联**——复盘是反馈回路的终点，采纳项落实完成即结束；
   要开新需求，指路 /dev-clarify。

```markdown
---
id: 0001
status: draft
created: <date>
---
# <一句话主题>
## 复盘范围
（git 区间 / 关联 spec 与 acceptance 编号 / 用户口述主题）
## 豁免审计
（逐条：commit / diff 证据（文件与规模）/ 判定：合规 | 滥用 | 存疑 / 依据；
末尾附 --no-verify 嫌疑提交清单，无则写"无"）
## 其他发现
（评审遗留、验收残余风险、会话经验；无就写"无"）
## 改动清单
（逐条：类型 标准 | 检查 | 技能 / 目标文件 / 建议改动 / 默认建议；
采纳与否 + 不采纳理由）
```

## 5. 中断与交接

会话可能在任何时刻结束。停下前（等用户决策、上下文将尽、被卡住）：先把报告
以 `status: draft` 落盘——已完成的审计逐条写入，未做的步骤标"未执行"。
重入从 §1.1 续接：盘上的 draft 就是进度，已出结论的条目不重审。
状态在盘上，不在对话里。

## 禁止事项（任何时候）

- 未经用户逐条采纳，直接修改标准、检查或技能文件。
- 不看 diff，只凭 commit message 下审计结论。
- 无素材时硬凑发现，或为了"有产出"写牵强的改动清单。
- 把复盘写成对人的评价——只对流程与规则，不对人。
- 删除、改写历史豁免留痕，或建议用 --no-verify 重写历史。
- 跳过范围确认就全库扫描。
