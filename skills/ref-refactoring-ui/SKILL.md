# ref-refactoring-ui：什么是好的界面视觉设计

总标准只有一条：**界面靠层级与体系成立，不靠装饰——重要的东西一眼可见，每个视觉决定来自提前定好的受限集合，而不是临场硬挑。**
以下通则是九册的公共标准，章法细则按路由表加载，不整载。

## 通则

1. **从功能开始，不从外壳开始**：先设计一个真实功能的简单版本，导航与外壳留到最后；低保真起稿、灰度先行、细节后置。
2. **一切决定出自体系**：字号、间距、颜色、圆角、阴影都从提前定好的受限阶梯里选——选项越少，决定越快、越一致。
3. **层级优先于语义**：信息与操作按重要性分层设计——主要的一眼可见，次要的清晰不抢眼，第三级的可发现不打扰。
4. **弱化与强调成对使用**：突出不了一个元素时，去弱化跟它抢注意力的元素。
5. **少即是多**：边框、颜色、阴影都是最后手段——先用留白、背景色差与字重对比做区隔。

## 适用边界

仅图形界面（Web / 移动端 / 桌面端），CLI 与文档视觉不适用（二者在 design-ui
有专属分册）。本技能是内部参考，不响应独立的界面设计请求：用户直接要求设计
界面时，转 design-brief → design-ui 链。
