# 从零起界面：先功能，后外壳

> ← 原书 01「从零开始」

从零开始设计时最大的风险不是做不好，而是被外壳、细节和想象中的范围拖垮。
本章给出一套起稿顺序与范围纪律：从哪下手、何时才碰细节、一次做多大。

## 规则

1. **从一个真实功能开始设计，不要从应用外壳开始**。先挑一个具体功能，只画它需要的元素；导航、侧边栏、logo 等外壳等两三个功能成形后再定。
   - 正例：机票预订服务先画「搜索航班」——出发/到达/日期输入框加一个搜索按钮。
   - 反例：开局先纠结导航栏放顶部还是侧边、内容通栏还是进容器——此时你还没有判断导航所需的信息。（原书 01「从一个功能开始，而不是从布局开始」）
2. **细节留到后面，灰度先行**。早期不抠字体、阴影、图标；开始细化时也先不上色，只靠间距、对比度和大小撑起画面。
   - 正例：纸上粗笔画草图、或纯灰度画完布局再加色。
   - 反例：第一稿就在高保真工具里逐像素调阴影和字号，方案没探几个、时间已烧完。（原书 01「细节留到后面」「先别上色」）
3. **一次只设计一个功能的简单版本，小步循环**。基本版满意就去做出来，在实际可用的界面上迭代，而不是在脑内想象全部边界情况。
   - 正例：先做最简日历视图，跑起来后再处理两个会议同时间的显示问题。
   - 反例：试图在设计阶段穷举 2000 个联系人、每种错误提示的形态——纯靠想象硬扛意外复杂性。（原书 01「别设计太多」「小步循环」）
4. **默认功能很难做，只设计能交付的最小版本**。锦上添花的部分晚点再设计，别在设计里暗示你还没准备好实现的东西。
   - 正例：评论系统第一版不含附件区，上线后再迭代。
   - 反例：第一天就画上附件区，实现时发现工作量远超预期，整个评论系统一起搁置。（原书 01「当个悲观派」）
5. **先想清楚个性，再让各因素服务它**。字体（衬线优雅/圆润活泼/中性朴素）、颜色、圆角大小、界面措辞共同决定观感；圆角尤其要一致——同一界面混用直角与圆角几乎总是更难看。（原书 01「选择一种个性」）
6. **提前定好体系，用排除法挑值**。色阶、字号等各备一组受限选项；挑值时先猜一个，把两侧相邻值摆在一起对比，大概率两个一眼出局。
   - 正例：图标尺寸只在 12/16/24/32px 里选，摆出三个候选一次定案。
   - 反例：每次都开取色器现调一个新蓝、逐像素试字号——选项无限多，决定永远下不了。（原书 01「限制你的选项」「提前定好体系」「用排除法做设计」）
