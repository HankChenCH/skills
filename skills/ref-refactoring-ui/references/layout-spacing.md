# 布局与间距：留白给足，尺寸进阶

> ← 原书 03「布局与间距」

布局最常见的病是拥挤、间距随手编、宽屏硬填满。本章给三样东西：留白的加减
顺序、一套间距与尺寸阶梯、以及何时该（不该）跟随栅格。

## 规则

1. **留白是减出来的，不是加出来的**。先给每个元素多得多的空间，再一点点减到满意——单独看「略多」的留白放进完整界面往往刚好。
   - 正例：卡片先取双倍内边距，逐步收。
   - 反例：挤了才加几像素边距，元素只得到「不明显难看」的最低呼吸空间。（原书 03「一开始就把留白给足」）
2. **建立间距与尺寸阶梯，任何相邻取值差距不低于约 25%**。以 16px 为基准（浏览器默认字号、整除干净），小端挨得近、大端隔得远；从此只从阶梯取值。
   - 正例：需要空间就先取阶梯一档，不够再取下一档。
   - 反例：在 120px 与 125px 之间纠结——线性阶梯（如「全是 4px 倍数」）帮不了任何决定。（原书 03「建立间距与尺寸体系」「定义这套体系」）
3. **不必填满屏幕**。只需要 600px 就用 600px；元素只占它刚好需要的宽度，别因为导航通栏就把所有东西通栏。
   - 正例：窄表单保持最佳宽度，说明文字拆到旁边一栏。
   - 反例：为对齐把窄内容硬拉宽，或把画布上所有东西塞满。（原书 03「你不需要把整个屏幕填满」及小节）
4. **别把栅格当宗教**。侧边栏等内容型元素用针对内容优化的固定宽度，主内容区弹性伸缩；只有确实要跟着缩放的元素才用百分比，最佳尺寸固定的元素给 max-width。
   - 正例：登录卡片定 max-width，大屏不放大、小屏才缩。
   - 反例：侧边栏按 25% 弹性伸缩——屏变宽占地方、屏变窄文字断行。（原书 03「栅格被高估了」）
5. **各元素独立缩放，别用 em 固化比例关系**。大屏上很大的元素到小屏要缩得更快；小元素与大元素的差距在小屏上应没那么夸张。
   - 正例：正文缩到 14px 时标题从 45px 降到 20–24px，而非按 2.5em 落到 35px。
   - 反例：按钮内边距绑定字号等比缩放，大小按钮只像整体缩放的同一张图。（原书 03「相对尺寸无法通用」）
6. **避免含糊的间距**：靠间距分组时，组与组之间的空间必须明显大于组内空间，让归属一目了然。
   - 正例：表单每组（标签+输入框）间距大于组内标签与输入框的间距。
   - 反例：标签下外边距与输入框下外边距相等，用户分不清哪个标签配哪个框。（原书 03「避免含糊的间距」）
