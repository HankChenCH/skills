# 两态接入与出口（接入分流、清单收口核验、指路串联）

主文档 §3 接入步与清单收口步、§4 出口的本细则。
接入状态判定沿主文档 §1（`.sdlc/check.sh` 存在与否，只读判定）。

## 两态接入

- **未接入**：先按 **setup-workspace 全流程**执行接入——**含其全部决策点**，
  不跳过、不代答（tracker 选型、多仓入册等由仓库主人拍板）；**接入完成才落
  迁移产物**（时序硬约束：识别 / 翻译成果先行备好，落盘排在接入之后），
  **一次会话**完成接入与迁移。
- **已接入**：仅补迁移产物与对账清单，接入资产（.sdlc/、AGENTS.md、
  check.sh 等 setup-workspace 生成物）**逐字不变**——迁移落盘后接入资产
  diff 必须为空，出现差异即回查（接入资产被误改）。
- 两态共用后续步骤：翻译产物、处置、对账清单在接入态核验后照常落盘。

## 对账清单收口

- 完整迁移收口前逐行核验对账清单：识别报告覆盖的**每件**外来痕迹都有
  一行，每行**来源 → 归宿 → 处置结果**三段**齐备**；**缺行**的痕迹回
  翻译 / 处置步补齐，**不带缺行收口**。
- 清单是轻产物，不进 check.sh 门禁；落盘后提示仓库主人自行提交
  （同 references/ledger-template.md 填写规则），本技能不做 git 提交。

## 出口（报告 + 对账清单 + 指路，不自动串联）

- 出口三件：**迁移报告**（识别 → 翻译 → 处置 → 接入的过程与结果摘要，
  会话内陈述）、**对账清单**（落盘路径 + 逐件核销口径）、**指路
  setup-reconstruct**。
- **可选串联**：迁移只保证外来产物归宿，存量代码的知识逆向是另一件事——
  setup-reconstruct 由用户**自选触发，不自动运行**；用户不选择时
  **不产生逆向产物**，迁移出口即终点。
- 按需服务定位不变：sdlc next-mode 路由表不加行，迁移一律用户手动触发。
