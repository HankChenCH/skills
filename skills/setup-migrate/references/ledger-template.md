# 对账清单模板与落点

对账清单实体落目标仓库 `docs/migrations/NNNN-slug.md`：编号接目录内最大号 +1
（空目录从 0001 起），slug 用小写短横线。下方「模板」是落盘底稿——改编只动
编号与日期、尖括号占位、表格行内容；frontmatter 字段集合与表结构不动。

## 模板

```markdown
---
id: <NNNN>
created: <YYYY-MM-DD>
---
# <NNNN>-<slug>：迁移对账清单

逐件一行：来源 → 归宿 → 处置结果。处置结果只取四个值：
已翻译 / 已关闭 / 失败待补 / 未处理。

| 来源 | 归宿 | 处置结果 |
|---|---|---|
| <本地路径，或 issue 编号 + 平台> | <新产物路径 / 归档位置 / 显式弃置及理由> | <已翻译 / 已关闭 / 失败待补 / 未处理> |

## 备注

<调研不可考决策、E1 未处理明细提示、用户拍板记录记在这里>
```

## 填写规则

- **frontmatter 仅 `id` / `created`**——对账清单是快照语义：一次迁移一张，
  落盘即终态；重跑迁移生成新编号清单，不改旧清单。
- 「来源」写本地路径，或 issue 编号 + 平台（如 `#42 github`）；「归宿」写
  新产物路径、归档位置，或显式弃置及理由；「处置结果」只取四值之一。
- 失败项（issue 关闭失败等）记「失败待补」，人工补办后在原行补记，不另开清单。
- 非点名套件痕迹记「未处理」，并在备注节提示用户（E1）。
- 对账清单是轻产物：不进 check.sh 门禁（validate 拒识，phase / frontier
  不受影响），留痕靠版本库；落盘后提示仓库主人自行提交，本技能不做 git 提交。
