# 处置协议（tracker issue 处置 + 生命周期技能处置）

主文档 §3 处置步的本细则。前置：翻译步（references/translation-mapping.md）
已把全部翻译产物落盘并逐件记行；处置只处理"翻译完了"的痕迹，
顺序先 tracker issue 后生命周期技能（技能移除前产物归宿已定）。

## tracker issue 处置

- **范围**：仅识别报告中**开着的**-issue 外来 issue（非 wontfix，且翻译步已全部翻译）。
  **已闭环 issue 无 tracker 操作**——不删历史 issue、不动 label 定义（spec 非目标）。
- **平台 issue**（tracker 上）：全部翻译后经平台 CLI 逐件关闭
  （gh issue close / glab issue close 等，与 publish 适配器同款调用面，只调平台既有
  命令，**不扩 trackers 适配器**——其只发布语义保持不变）；关闭评论注明
  **"已迁移"** 并指向对账清单路径（docs/migrations/NNNN-slug.md）；
  对账清单记 issue 编号（或平台 + 编号）与新产物路径，处置结果记「已关闭」。
- **本地 tracker**（.scratch/）文件：无外部副作用——**标记关闭并归位**：
  文件内状态行注「已迁移 <日期>」，移入关闭子目录或按原布局标注，
  对账清单记本地文件路径。
- **E3 关闭失败**（凭据 / 权限 / CLI 缺失）：对账清单记失败明细
  （issue 编号、平台、失败原因），处置结果记「失败待补」；**不阻断**——
  本地翻译产物与门禁接入照常继续完成，事后人工补办后在原清单对应行补记。

## 生命周期技能处置

- **判据沿蓝图 §10.3**：生命周期类 → 处置；**写作类保留**
  （writing-\* 等内容创作技能不处置、不迁移）。superpower 生命周期清单以
  调研报告 docs/research/0002-superpower-skills-suite.md 为准——其
  writing-plans / writing-skills 名带 writing- 前缀但属框架元类，
  **不可用 writing- 前缀作写作类判据**，按调研报告分类处置。
- **处置动作 = 移出技能发现路径**：仓库专属位置安装的 → 移除，或移入
  不在技能发现路径上的归档目录；改 description 之类的**软禁用不采用**
  （不满足"不再被自动触发"的验收语义）。
- **作用域**：装在仓库专属位置 → 直接处置；装在用户全局技能目录
  （其他项目可能仍用）→ **默认归档而非删除**，且**处置前必须经用户确认作用域**，
  不擅动全局安装；用户确认与否的拍板记录进对账清单备注。
- 每件处置在对账清单记行：来源路径 → 归宿（已移除 / 归档位置）→「已关闭」；
  写作类保留项也逐件记行（归宿写"保留，写作类"），逐件可核销。
