# 上下文 token 水位线

进入 next 模式才加载本文件，在**每次调用目标技能之前**执行评估
（含同一会话内的再次 next）。

next 模式是全链路里最容易连续吃上下文的环节：被调技能、它的 references、
产物全文、命令输出全部进窗口，而上下文越满模型表现越差。水位线的职责是在
跌出聪明区之前早早收口，把续接交给盘上状态（状态在盘上不在对话里），
而不是赌压缩后的记忆。

## 测量（先精确后估算，宁高勿低）

1. **首选**：读智能体环境的上下文指示（状态栏或系统提示给出的已用 token 数
   或剩余百分比）。有精确值 → 直接按档位表定档。
2. **兜底估算**：环境无指示时按字符折算——中文 ≈1.5 字/token、英文
   ≈4 字符/token；估算对象 = 系统提示 + 全部对话消息 + 全部工具调用的输入
   输出累计值，除以窗口总量。只允许向上取整；算不准按更高档执行。

## 档位表（占窗口百分比；2026-10-27 用户定档）

| 档位 | 区间 | 动作 |
|---|---|---|
| 绿 | <30% | 正常推进：调用路由表目标技能，允许其自动串联，直走到下一个决策点 |
| 黄 | 30%–50% | 收窄推进：只调用目标技能完成**单阶段**，向它声明"完成本阶段即在出口收口，不自动串联下一技能"；决策点照常问人；推进前告知用户当前用量与本轮边界 |
| 红 | ≥50% | 停止推进：不调用任何技能；报告用量与档位，建议新开会话重跑 /sdlc（盘点）或 /sdlc next（从盘上状态续接） |

50% 红线远在常见自动压缩阈值（80–90%）之前，为收口与决策对话留足余量；
若环境的压缩阈值更低，以更低者为准。

## 话术规范

黄/红档的输出必须包含三件事：当前用量（精确值或"估算 ≥N%"）、命中档位、
本轮边界（黄："本轮只到 X，出口不串联"；红："建议新会话续接"）。
默认建议放第一项。禁止"感觉还够""应该行"式表述。

## 禁止

- 红档以"就差一步"为由继续调用新技能。
- 环境无指示时跳过评估（必须走兜底估算）。
- 因水位收窄而跳过决策点——收窄的是推进距离，不是决策纪律。
- 估算向下取整。
